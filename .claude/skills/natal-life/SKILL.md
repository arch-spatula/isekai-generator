# 네이탈 일생 해석

계약: `docs/spec/life-narrative-interpretation.md`. 해석은 에이전트가 하고, 형식·근거 인용은 검증기가 확인한다.
네이탈은 시기 계산(트랜짓·프로그레션)이 없으므로 생애 연표를 쓰지 않고 인물 사전과 재능, 상처와 회복만 맡는다.

## 1. 대상 디렉터리와 선행 산출물

- 사용자가 준 차트 디렉터리, 또는 같은 대화에서 chart-report가 저장한 `chartDir`를 쓴다. 둘 다 없으면 묻는다.
  `artifacts/`를 탐색하거나 최신 버전을 추측하지 않는다.
- `test -e <디렉터리>/natal-life.md`가 성공하면 덮어쓰지 않고 멈춘 뒤 알린다.
- `natal-judgment.md`를 `test -e`로 확인한다. 없으면 만드는 방법(`/natal-judgment <디렉터리>`)을 알리고 멈춘다.
  대신 실행하지 않는다. 네이탈은 판단 파생 사실이 없으므로 `derive-judgment-facts`는 필요 없다.
- `grep -q '^하우스별 룰러와 행성' <디렉터리>/natal-facts.md`가 실패하면 이 사실 층이 생기기 전에 만든 폴더다.
  차트를 새로 뽑아야 한다고 알리고 멈춘다.

## 2. 읽기

같은 디렉터리의 `natal-chart.md`, `natal-facts.md`, `natal-judgment.md`만 읽는다.
사주·자미두수 파일, 다른 버전의 문서, 기존 GDD는 읽지 않는다.

## 3. 해석과 작성

`<디렉터리>/natal-life.md`에 아래 형식 그대로 쓴다. 항목 안에는 `키: 값` 필드 줄만 쓰고 필드마다 한 줄이다.

```markdown
# Natal 일생 해석

차트: ASC <사인> · Sun <사인> · Moon <사인> · <하우스 시스템>

## 인물 사전
### 부모
성향: …
주인공과의 관계: …
관계의 변화: <어떤 조건·사건에서 어떻게 바뀌는가>
근거: <인용 1개 이상>
### 형제·또래
### 연인·배우자
### 자녀·제자
### 벗·동료
### 스승·후원자
### 경쟁자·적대자

## 재능과 생업
### 주 재능
내용: …
꽃피는 시기: <어떤 조건·환경에서 드러나는가>
막히는 조건: …
근거: …
### 보조 재능
…
(필요하면 이름을 정해 항목을 더한다)

## 상처와 회복
### 반복되는 실패
내용: …
발현 조건: …
근거: …
### 상실
### 회복
```

### 무엇을 쓰는가

- **사건의 형태로 쓴다.** "거리를 둘 수 있다" 같은 경향에서 멈추지 않고, 어떤 일이 생기면 무엇을 하고 그 결과
  무엇이 남는지까지 쓴다.
- **시기 대신 조건으로 쓴다.** 나이·생애 단계(유년·청년 등)를 정하지 않는다. `관계의 변화`와 `꽃피는 시기`는
  "먼 길을 떠나 본 뒤", "많은 사람 앞에서 책임을 맡았을 때"처럼 계기가 되는 조건과 사건으로 쓴다.
- **보편적 생애 사건 언어로 쓴다.** 집을 떠남, 스승을 만남, 첫 상실, 동료와의 결별, 책임을 떠안음처럼 이세계에서도
  그대로 성립하는 말을 쓴다. 회사·대학·회계·계약·심사 같은 현대 제도 명사와 무기·스킬·던전·직업 클래스 같은 게임
  용어는 쓰지 않는다. 행성·사인 이름을 사람이나 사물 이름으로 옮기지도 않는다(예: Mars를 "전쟁의 신"으로 직역하지 않는다).
- **1차 판단을 따른다.** `natal-judgment.md`의 결론을 뒤집지 않는다. 1차의 `대안`은 서사의 갈림길(다른 선택을 했다면
  어떻게 되었을지)로 쓸 수 있다.
- **인물 사전은 하우스에서 읽는다.** `하우스별 룰러와 행성`의 커스프 사인, 룰러와 그 위치, 하우스 안 행성을 중심으로
  쓴다. 부모는 4H·10H, 형제·또래는 3H, 연인·배우자는 7H(연애는 5H도), 자녀·제자는 5H, 벗·동료는 11H,
  스승·후원자는 9H에서 읽는다. 경쟁자·적대자는 7H·12H나 1차 판단의 핵심 긴장에서 근거를 골라 밝힌다.
  하우스에 행성이 없어도 항목을 쓰고, 룰러의 위치로 읽거나 비어 있음을 서사 정보로 다룬다.
- **재능은 1차 판단의 주요 행성·우세 원소와 2H·6H·10H에서 읽는다.** 차트 룰러 상태와 핵심 긴장은 상처와 회복에 반영한다.
- **사실은 세 파일에 있는 것만 근거로 쓴다.** 파일에 없는 품위·애스펙트·하우스 배치를 직접 계산해 넣지 않는다.
- 해석을 미리 약화하는 면책·책임 회피 문장은 쓰지 않는다. 불확실성은 1차 판단의 `대안`과 갈림길로 다룬다.

### 형식 규칙

- `차트`는 `natal-judgment.md`의 `차트` 줄과 같은 규칙으로 `natal-chart.md`에서 옮긴다
  (예: `ASC Scorpio · Sun Virgo · Moon Sagittarius · Placidus`).
- `## 생애 연표` 섹션을 쓰지 않는다. 인물 7명과 상처와 회복 3항목은 위 순서와 이름 그대로 모두 쓴다. 재능과 생업은
  주 재능·보조 재능으로 시작한다.
- 인용은 `[facts:<항목>]`(괄호 안 정의는 빼고, 예: `[facts:하우스별 룰러와 행성]`),
  `[chart:<절 제목, 10행성 이름, ASC 또는 MC>]`(예: `[chart:Major Aspects]`, `[chart:Venus]`),
  `[judgment:<1차 판단 섹션>]`만 쓴다. `[derived:]`는 쓰지 않는다. 파일에 없는 이름을 만들지 않는다.
- 1차 판단의 네 섹션(차트 룰러 상태·주요 행성·우세 원소·핵심 긴장)을 문서 어딘가에서 모두 한 번 이상 인용한다.

## 4. 검증

```bash
bun scripts/check-life-document.ts natal <디렉터리>
```

- 출력이 없고 exit 0이면 끝이다.
- 위반 줄이 나오면 그 줄만 고쳐 다시 실행한다. 3번 고쳐도 통과하지 못하면 멈추고 남은 위반을 그대로 알린다.
- 검증을 통과시키려고 해석 내용을 바꾸지 않는다. 인용 이름·형식을 고친다.

## 5. 보고

파일 경로와 주 재능·보조 재능의 `내용`을 한 줄씩 알린다. 문서 본문을 다시 옮겨 쓰지 않는다.
