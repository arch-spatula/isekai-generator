# ADR: 다섯 단계 게임 설계를 지우고 life.md만 읽는 최소 지시 GDD 에이전트 하나로 쓴다

* **Status:** Accepted
* **Date:** 2026-11-28
* **Decision Owners:** Project Owner
* **관련:** [차트부터 GDD까지 하나의 Claude 흐름](2026-11-23-claude-gdd-flow.md), [세 체계 일생 통합](../spec/life-integration.md), #128(이 결정), #124, #125, #126, #127

## 배경

`life.md` 다음에는 다섯 단계가 있었다. 번역 브리프, 이세계 정체성, 세계, 전투, GDD 순서다.
단계마다 정해진 필드와 검증기가 있었고, 정체성·세계·전투에는 검토 에이전트가 붙었다. 모든 필드에 재료나 지어냄 표시를 요구하는 재료 지도도 있었다.
이상한 결과가 나올 때마다 이슈 하나에 필드·금지 규칙·검증기를 하나씩 더했고, 스킬마다 굵은 규칙이 15~24개로 늘었다. 결과에는 다음 문제가 나타났다.

- 과한 구체성: "상업도시"면 될 곳이 "여러 길이 모이는 장터 도시"가 되고, "산적"이면 될 적이 사연을 가진 "통행세 무리"가 됐다(#126, #127).
- 서로 반대 방향을 요구하는 규칙: 검토 기준이 일반성을 감점하면서 동시에 흔한 말을 허용했다(#125).
- 어긋난 맞물림: 대표 장면 하나에 세 장의 지역·세력·동료가 섞였다(#124).
- 앞선 수정이 만든 문제: 위 네 이슈 중 셋이 앞선 이슈에서 더한 규칙에서 생겼다.

## 실험 (로컬 run, 원본은 저장소에 없음)

같은 `life.md`로 GDD를 두 조건에서 만들었다.

- A: 다섯 단계와 검토
- B: 새 에이전트에게 `life.md`와 기운 사실(`scripts/attribute-facts.ts` 출력)만 주고 짧은 지시

사용자는 B가 "확실히 좋아졌다"고 판정했다. 서로 다른 명식 세 개에서 같은 지시로 B를 더 만들었고, 모두 이전보다 낫다고 판정했다. 표본은 명식 네 개이고 판정자는 한 명이다.

| 관찰 | 내용 |
| --- | --- |
| B에서 나아진 점 | 장르 기본값의 이름(상업도시·산적), 교역·흥정 활동, 동료가 빠지는 장의 이유, 장 대응이 맞는 대표 장면 |
| 명식마다 달라진 것 | 클래스, 속성, 핵심 전투 동작, 동료 구성, 선택 |
| B의 남은 약점 | 넷 중 하나에서 대표 장면이 아직 합류하지 않은 동료를 씀. 넷 모두 "게이지가 차면 터지고 대가를 치른다"는 규칙이 있음. 0인 기운은 동료만 채움. 지시문 예시(상업도시·산적·호위)가 넷 모두에 나옴 |

넷 중 한 명식의 `life.md`는 출생자가 누구인지 아는 세션이 썼다. 그래서 그 결과는 GDD 단계가 `life.md`를 옮기는 충실도의 사례로만 본다.

## 결정

1. **GDD는 `gdd-writer` 에이전트 하나가 쓴다.**
   - `.claude/agents/gdd-writer.md`의 본문은 실험 B의 지시문 원문(영어)이다. 파일 경로 자리만 `<dir>`로 바꿨다.
   - 도구는 Read·Write뿐이고, `<dir>/life.md`와 `<dir>/attribute-facts.txt`만 읽는다.
   - 깨끗한 맥락이 실험 조건이었다. 스킬 규칙을 읽은 세션이 직접 쓰면 그 규칙이 섞인다.
2. **`/write-gdd` 스킬은 입력 준비와 호출만 맡는다.**
   - 기운 사실을 파일로 만들고 에이전트에 디렉터리 경로만 넘긴다.
   - 스킬에 설계 규칙을 쓰지 않는다. 부른 세션은 `gdd.md`를 대신 쓰거나 고치지 않는다.
3. **검증은 차트 명칭 금지 하나다.** `scripts/check-gdd.ts`는 `scripts/chart-names.ts`의 목록으로 차트 명칭만 거부한다. 절 구성·인용·장 대응은 검사하지 않는다.
4. **지시문을 바꾸거나 규칙을 더하려면 비교를 거친다.**
   - 같은 명식에서 바꾸기 전과 바꾼 뒤의 지시문으로 GDD를 새로 만든다.
   - 사용자가 두 결과를 보고 판정해야 바꾼다.
   - 위의 남은 약점도 이 절차 없이 규칙으로 메우지 않는다.
5. **다섯 단계를 지운다.**
   - 지운 것: 스킬 translate-life·design-identity·design-world·design-combat, 검토 에이전트 game-step-reviewer, 그 검증기·테스트·fixture, 번역 명세와 게임 설계 흐름 명세, 재료 지도와 그 명세, CLAUDE.md의 재료 지도 절
   - 기록은 git에만 남긴다. 스킬이나 에이전트 호출로 옛 단계에 닿는 경로를 두지 않는다.
   - 게임 단계의 지난 ADR은 Status를 이 결정으로 대체됐다고 바꾸고, 실패한 시도의 기록으로 둔다.

차트 계산부터 일생 통합까지는 바꾸지 않는다.

## 검토한 대안

| 결정 | 대안 | 고르지 않은 이유 |
| --- | --- | --- |
| 다섯 단계를 지운다 | 규칙을 하나씩 솎아 낸다 | 규칙끼리 맞물려 있어 하나를 빼면 다른 곳이 어긋난다. 실험에서 규칙이 거의 없는 쪽이 나았다 |
| 전용 에이전트 | 스킬 본문에 지시문을 둔다 | 스킬은 부른 세션의 맥락에서 돈다. 그 세션이 읽은 다른 규칙이 섞이는 것을 막을 수 없다 |
| 지시문 원문(영어) | 한국어로 옮기거나 예시를 뺀다 | 비교하지 않은 변경이다. 바꾸려면 결정 4를 거친다 |
| 차트 명칭 검사만 | 절 구성이나 장 대응도 검사 | 절 구성을 고정하면 다시 필드가 생긴다. 장 대응 오류는 넷 중 하나였고, 막으려면 결정 4로 지시를 바꾼 뒤 비교한다 |
| git에만 기록 | `docs/legacy/`로 옮긴다 | 옮긴 문서가 다시 참고 자료로 쓰일 수 있다. 사용자가 git 기록으로 충분하다고 했다 |

## 결과

- `/write-gdd`의 입력은 `life.md`다. 번역 브리프·정체성·세계·전투 문서는 더 만들지 않는다.
- GDD의 형식은 고정하지 않는다. GDD를 읽는 다음 단계가 생기면 그때 형식을 정하고, 정하기 전에 결정 4로 비교한다.
- 이슈 #124~#127은 대상 단계가 없어져 닫는다.
- 판정은 다시 생성한 결과에서 사용자가 본다. 실험 명식 하나로 새 `/write-gdd`를 돌렸을 때 B와 같은 수준이어야 한다.
