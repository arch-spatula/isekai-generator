# ADR: 비식별 설계 사례 카드의 대안 중심 검색 도입

* **Status:** Accepted — 구현 미반영
* **Date:** 2026-11-11
* **Decision Owners:** Project Owner
* **Scope:** 개인화 전투·세계 콘셉트 후보 생성과 독립 의미 검토의 검색 보조 하네스

---

# 1. Context

온톨로지는 가능한 개념 관계를 제공하지만 그 관계를 실제 조작, 자원, 실패와 성장 구조로
결합한 사례까지 설명하지 않는다. 과거 GDD 전문을 검색 입력으로 사용하면 풍부한 사례를
얻을 수 있지만 이전 인물·문체·설정이 새 생성에 유입되고, 설명이 긴 사례가 정답처럼
과대 대표될 수 있다. 가장 유사한 성공작 하나만 검색하는 방식도 새로운 후보를 만드는
대신 과거 결과를 복제할 가능성이 크다.

검색의 목적은 답안을 제공하는 것이 아니라 생성기가 처음 선택한 은유와 다른 설계 경로,
반례와 알려진 실패를 제때 검토하게 하는 것이다.

# 2. Decision

개인정보와 고유 설정을 제거한 **설계 사례 카드**를 저장소에 버전 관리하고, 후보 생성과
독립 의미 검토에서 대안 중심으로 검색한다. 초기 구현은 로컬 정적 카드와 결정적 메타데이터
필터로 시작한다. 벡터 데이터베이스, 외부 검색 서비스와 임베딩 모델 도입은 이번 결정에
포함하지 않는다.

카드는 최소한 다음 정보를 가진다.

```yaml
schemaVersion: 1
id: absorb-release-interceptor
interpretationConcepts:
  - rapid-intervention
  - protection
  - shared-burden
mechanics:
  approach: high-speed-intercept
  interaction: absorb-collision
  resource: stored-impact
  payoff: directional-release
  failure: overload
strengths:
  - pressure-and-cost-share-one-loop
risks:
  - intentional-damage-may-become-optimal
reuseBoundary:
  - do-not-copy-names
  - do-not-copy-world-lore
  - do-not-copy-visual-identity
```

카드는 완성된 GDD, 문장 템플릿이나 캐릭터 외형을 저장하지 않는다. 하나의 카드가 하나의
정답을 의미하지 않으며 온톨로지 개념과 실제 게임 인과를 연결한 짧은 사례다.

검색은 유사도 상위 결과만 반환하지 않고 다음 역할을 각각 충족한다.

- **유사 번역:** 같은 해석 긴장을 다른 메커니즘으로 표현한 카드
- **반례:** 현재 후보와 다른 힘의 매개체·상호작용·숙련 방식을 사용한 카드
- **실패 경고:** 현재 후보와 유사한 수렴·직역·위험 구조 실패를 설명하는 카드

후보 생성기에는 필요한 최소 필드만 전달한다. 검색 결과는 후보의 근거가 아니라 탐색
자극이며, 최종 후보는 현재 통합 해석 ID와 자체 인과를 별도로 제시해야 한다. 검색된 카드의
표현이나 설정을 복사해 근거처럼 사용할 수 없다.

# 3. Retrieval Contract

초기 검색 계약은 다음과 같다.

1. 현재 해석 긴장을 온톨로지 개념 ID로 정규화한다.
2. 현재 초안의 메커니즘 지문을 만든다.
3. 유사 번역, 반례, 실패 경고를 역할별로 제한된 수만 조회한다.
4. 같은 메커니즘 계열만 반환되면 거리 조건을 넓혀 한 번 재조회한다.
5. 카드 ID와 사용 목적만 진행 기록에 남기고 카드 내용을 산출물 근거로 인용하지 않는다.
6. 검색 결과가 없거나 품질이 낮아도 생성이 중단되지 않으며 온톨로지와 현재 해석만으로
   후보를 만들 수 있어야 한다.

초기에는 태그·개념 교집합과 메커니즘 거리로 결정적 검색을 구현한다. 카드 수와 검색 실패
양상이 실제로 증가하기 전에는 임베딩 검색을 도입하지 않는다. 향후 의미 검색을 도입하더라도
같은 역할별 다양성, 출처 경계와 결과 개수 제한을 유지한다.

# 4. Validation

결정적 검증은 다음을 확인한다.

- 카드 스키마, 온톨로지 참조와 ID가 유효하다.
- 금지된 개인 식별 정보, 실제 출생 입력과 로컬 아티팩트 링크가 없다.
- 카드에 메커니즘의 접근·상호작용·자원·결과·실패 중 필요한 필드가 있다.
- 검색 결과가 요청한 유사 번역·반례·실패 경고 역할을 구분한다.
- 동일 카드 또는 동일 메커니즘 계열이 모든 검색 슬롯을 점유하지 않는다.
- 검색 없이도 후보 생성 계약을 수행할 수 있다.

검색 카드가 실제로 창작 폭을 넓혔는지, 표면 복제가 발생했는지와 최종 후보의 재미는 독립
의미 검토 및 합성 fixture 기반 모델 평가로 확인한다.

# 5. Rejected Alternatives

## 5.1 과거 GDD 전문을 벡터 검색

개인별 설정과 문체가 재유입되고 로컬 아티팩트가 영구 지식의 전제가 될 수 있으므로
채택하지 않는다.

## 5.2 가장 유사한 성공 사례 하나만 검색

탐색보다 복제를 강화하고 이미 선택한 은유를 확인하는 자료만 반환할 수 있으므로 채택하지
않는다.

## 5.3 검색 결과를 최종 선택 점수에 직접 가산

카드가 많은 메커니즘이 과대 평가되고 새로운 창작이 불리해진다. 검색은 후보 확장과 검토에
사용하되 현재 해석 적합성 점수를 대신하지 않는다.

## 5.4 처음부터 외부 RAG 인프라 도입

현재 카드 규모와 개인정보 경계에는 정적 파일과 결정적 검색으로 충분하다. 운영 복잡성과
모델 의존성이 실제 필요보다 크므로 보류한다.

# 6. Consequences

## Positive

- 과거 학습을 설정 복제 없이 재사용할 수 있다.
- 현재 초안과 다른 상호작용을 의도적으로 검색해 후보 고착을 줄인다.
- 실패 사례도 생성 하네스의 능동적인 검토 자료가 된다.
- 정적 카드와 결정적 검색으로 시작해 테스트와 변경 검토가 쉽다.

## Negative

- 카드 추출과 비식별화에 사람의 판단이 필요하다.
- 카드가 많아지면 태그 품질과 중복 관리가 필요하다.
- 검색된 사례가 프롬프트에서 여전히 권위 있는 답안처럼 작동할 수 있다.
- 정적 태그 검색은 표현이 다른 유사 개념을 놓칠 수 있다.

# 7. Follow-up

1. 카드 스키마와 비식별화 검사를 상세 spec으로 정의한다.
2. 서로 다른 상호작용 계열의 합성 카드와 실패 경고 카드를 소수 작성한다.
3. 온톨로지 ID 교집합과 메커니즘 거리 기반의 결정적 검색기를 구현한다.
4. 역할별 검색 결과와 검색 없는 fallback을 합성 테스트로 검증한다.
5. 후보 생성·독립 평가 입력에서 카드 원문과 현재 해석 근거가 혼동되지 않게 구분한다.
6. 카드 규모와 검색 누락을 측정한 뒤에만 임베딩 또는 외부 인덱스 도입 ADR을 검토한다.
