# ADR: 개인화 전투 원형을 후보 비교로 선택

* **Status:** Accepted
* **Date:** 2026-11-03
* **Decision Owners:** Project Owner
* **Scope:** 통합 차트 해석에서 개인화 Action RPG GDD를 생성하는 설계 단계

---

# 1. Context

이 결정은
[v0.1.24와 v0.1.25의 전투 원형 수렴 이슈](../incidents/2026-11-03-combat-archetype-convergence.md)를
조사한 결과로 제안되었다.

서로 다른 출생정보로 생성한 v0.1.24와 v0.1.25는 세계, 인물, 관계와 세부 전투 규칙이
달랐지만 모두 사슬검을 사용하는 근접 사냥꾼으로 수렴했다. 이전 산출물을 참조하거나
계산 결과를 재사용한 정황은 없었다. 두 통합 해석에 공통으로 나타난 안정과 변화,
연결과 독립, 압력의 축적과 해소 같은 긴장을 동일한 모델과 디자인 프롬프트가
`붙들기 → 축적 → 파열`로 번역하면서 같은 전투 원형을 다시 선택한 것으로 판단한다.

현재 파이프라인은 통합 해석에서 곧바로 하나의 GDD를 만든다. 해석의 차이를 전투 거리,
힘의 매개체, 공간 활용이나 숙련 방식으로 분기하는 기준이 없고, 서로 다른 전투 후보를
비교하지도 않는다. 따라서 개인화는 세계와 관계의 세부 묘사에는 반영되지만 주인공의
직업과 플레이어 판타지를 충분히 구별하지 못할 수 있다.

출생연도, 별자리나 오행을 특정 직업에 고정하면 외형적 다양성은 쉽게 얻을 수 있다.
그러나 이는 해석의 전체 맥락을 단순한 클래스 표로 축소하며, 해당 인물에게 그 플레이
방식이 적합한 이유를 설명하지 못한다.

# 2. Decision

통합 해석과 최종 GDD 사이에 **개인화 전투 원형 선택 단계**를 둔다. 이 단계는 하나의
아이디어를 바로 확장하지 않고 구조적으로 다른 여러 후보를 만든 뒤 해석 적합성,
플레이 가능성과 고유성을 비교하여 하나를 선택한다.

이 결정은 특정 차트 요소를 전사, 마법사, 소환사 같은 직업과 일대일 대응하지 않는다.
먼저 해석에서 게임플레이 성향을 추출하고, 각 후보가 그 성향과 긴장을 서로 다른 Action
RPG 문법으로 표현하도록 한다.

## 2.1 게임플레이 성향 축

선택 단계는 최소한 다음 축을 구조화한다.

- 전투 거리: 밀착, 중거리, 원거리
- 힘의 매개체: 신체, 무기, 주문, 소환체, 설치물, 환경
- 주도 방식: 직접 타격, 반응·반격, 지휘, 준비·함정, 변신
- 공간 활용: 추격, 진지 구축, 위치 교환, 영역 확장, 공중 이동
- 전투 리듬: 지속 압박, 축적 후 폭발, 순환, 준비 후 실행, 즉흥 변주
- 숙련의 핵심: 타이밍, 조준, 자원 조합, 배치, 명령, 형태 전환
- 위험 구조: 체력, 과열, 집중 붕괴, 소환체 손실, 지형 붕괴

각 판단에는 통합 해석 ID, 반대 근거 또는 한계와 확신도를 함께 기록한다. 해석에 등장한
직업·문서·계약 같은 표면 명사를 전투 요소로 직접 치환하지 않는다.

## 2.2 후보 생성과 차이 기준

최소 네 개의 후보를 만들며, 후보 쌍은 전투 거리, 힘의 매개체, 주된 공격 동사, 공간
활용, 위험 자원과 숙련 방식 중 최소 세 축에서 달라야 한다. 검을 사슬낫으로 바꾸는 것처럼
명칭과 외형만 달라지고 플레이 루프가 같은 경우는 별도 후보로 인정하지 않는다.

후보군은 필요에 따라 다음처럼 서로 다른 플레이어 판타지를 포함할 수 있다.

- 밀착형 부위 파괴 전사
- 원거리 궤도·탄도 마법사
- 소환체 역할 분담 지휘자
- 설치물과 지형을 사용하는 영역 설계자
- 신체 변형과 자세 전환을 사용하는 변신가

이 목록은 고정 클래스 표가 아니라 후보의 구조적 거리를 설명하는 예시다.

## 2.3 선택 기준

후보는 다음 기준으로 비교한다.

- 해석 적합성: 핵심 긴장과 성장 경로를 플레이로 표현하는가
- 변별력: 해당 해석의 드문 조합과 고유 항목을 사용하는가
- 액션성: 조작, 적의 대응과 전투 장면으로 설명 가능한가
- 성장성: 초기 한계와 후반 확장을 같은 힘의 계통으로 설명 가능한가
- 비독점성: 하나의 심리 은유가 모든 주요 시스템을 점령하지 않는가
- 장르 독립성: 차트 용어를 제거해도 매력적인 Action RPG인가
- 후보 간 거리: 다른 후보와 실제 플레이 방식이 충분히 다른가

선택 결과에는 채택 이유뿐 아니라 주요 탈락 후보와 탈락 이유를 남긴다. 첫 번째로 떠오른
응집력 높은 아이디어가 자동으로 최종안이 되지 않게 하기 위함이다.

## 2.4 산출물과 중복 감지

선택 결과는 GDD와 분리된 Markdown 문서 `gameplay-concept-brief.md`로 저장한다. 이
문서에는 게임플레이 성향 축, 후보 비교, 선택 결과, 인용한 통합 해석 ID와 최종 콘셉트
지문이 포함되어야 한다. 기계 검증이 필요한 값은 고정된 제목과 `key: value` 형식을
사용하되, 후보의 판타지·근거·약점은 사람이 읽을 수 있는 문장으로 기록한다.

과거 GDD 전문을 생성 에이전트에 제공하지 않는다. 대신 다음과 같은 작은 구조화 지문만
별도 레지스트리에 저장하여 반복 수렴을 감지한다.

```json
{
  "combat_range": "melee",
  "power_medium": "transforming_chain_weapon",
  "primary_loop": "read-bind-build-release",
  "mobility": "grapple",
  "resource": "heat_pressure",
  "enemy_scale": "giant_body_part"
}
```

새 후보가 기존 지문과 지나치게 유사하면 다른 후보를 한 번 더 비교한다. 중복을 무조건
금지하지는 않는다. 현재 해석에 가장 적합한 선택이라면 허용하되, 기존 원형과 플레이상
무엇이 다른지 기록한다. 이름만 다르고 핵심 루프가 같으면 중복으로 본다.

# 3. Validation

LLM이 후보의 다양성을 선언하는 문장을 검사하지 않는다. 다음 구조 조건은 CLI가
결정적으로 검증한다.

- 후보가 최소 네 개인가
- 모든 후보에 필수 게임플레이 축이 있는가
- 각 후보가 하나 이상의 유효한 통합 해석 ID를 인용하는가
- 후보 쌍마다 최소 세 축이 다른가
- 선택 후보에 반대 근거 또는 약점과 탈락 후보 비교가 있는가
- 기존 콘셉트 지문과의 유사도가 임계치를 넘는가
- 최종 GDD의 전투 거리, 매개체와 핵심 루프가 선택된 지문과 일치하는가

해석 적합성, 전투의 매력과 성장 인과 같은 의미 판단은 모델이 담당한다. 후보 개수,
필드 존재, 축 차이, ID 유효성 및 지문 유사도처럼 고정 가능한 조건만 스크립트가
검증한다.

# 4. Rejected Alternatives

## 4.1 차트 요소와 클래스를 고정 대응

출생연도, 별자리나 오행마다 무기와 직업을 고정하면 다양성은 생기지만 전체 해석의
상호작용과 발현 조건을 잃는다. 개인화 근거도 얕아지므로 채택하지 않는다.

## 4.2 프롬프트에 매번 다르게 만들라고 지시

구조적 차이의 정의와 검증 없이 다양성만 요구하면 명칭과 설정만 달라지고 플레이 루프는
반복될 수 있다. 재현 가능한 품질 기준이 아니므로 채택하지 않는다.

## 4.3 과거 GDD 전체를 다음 생성에 제공

중복 회피에는 도움이 되지만 이전 표현과 설정이 새 결과에 유입되어 격리를 깨고, 버전이
쌓일수록 입력이 커진다. 콘텐츠 대신 최소 지문만 비교한다.

## 4.4 이전 무기를 무조건 금지

현재 인물에게 가장 적합한 원형까지 배제하여 개인화보다 순번 다양성을 우선할 수 있다.
중복은 재검토 조건으로 사용하고 자동 금지하지 않는다.

# 5. Consequences

## Positive

- 서로 다른 해석이 세계관 문구뿐 아니라 직업과 조작 경험에서도 구별될 가능성이 커진다.
- 왜 근접 전사, 원거리 마법사 또는 소환 지휘자를 선택했는지 근거를 추적할 수 있다.
- 동일 모델이 익숙한 무기와 전투 루프로 반복 수렴하는 현상을 조기에 발견할 수 있다.
- 후보 다양성과 파일 형식 같은 기계 조건을 LLM 문장 검증에서 분리할 수 있다.

## Negative

- 후보 생성과 비교 단계가 추가되어 비용과 생성 시간이 늘어난다.
- 지문 축과 유사도 임계치가 부정확하면 의미 있는 변형을 중복으로 판정할 수 있다.
- 해석의 고유성이 약한 경우 후보 비교가 임의적인 장르 선택처럼 보일 수 있다.
- 과거 지문과 다르다는 이유만으로 적합도가 낮은 후보를 선택하지 않도록 균형이 필요하다.

# 6. Follow-up

이 결정은 `select-gameplay-concept` 스킬, Markdown brief validator, 전투 지문 레지스트리와
GDD 지문 검증으로 파이프라인에 적용되었다. 구현 순서는 다음과 같다.

1. `gameplay-concept-brief.md` 문서 계약과 출력 위치를 정의한다.
2. 게임플레이 성향 추출과 최소 네 후보 비교 프롬프트를 작성한다.
3. 후보 축 차이와 해석 ID를 검사하는 결정적 validator를 구현한다.
4. GDD 생성 단계가 선택된 콘셉트 지문만 입력받도록 계약을 변경한다.
5. 과거 콘텐츠 없이 지문만 저장·조회하는 레지스트리를 추가한다.
6. 같은 출생정보의 반복 생성과 서로 다른 출생정보 생성을 함께 회귀 테스트한다.
7. 기존 v0.1.24와 v0.1.25는 소급 수정하지 않는다.
