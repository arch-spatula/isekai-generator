# ADR: 클래스를 정하기 전에 영역을 이세계의 힘으로 옮긴 후보를 견준다

* **Status:** Accepted
* **Date:** 2026-11-25
* **Decision Owners:** Project Owner
* **관련:** [Claude 게임 설계 흐름](../spec/claude-game-design-flow.md) 4.7·5.5절, [이세계 정체성 설계](2026-11-24-isekai-identity-design.md), #106

## 배경

정체성 단계가 현실 직업에 이세계 이름만 붙인 클래스를 만들었다. 한 run에서는 브리프 능력의 `다루는 것`이 "물건과 값, 거래, 말과 글"이었고,
클래스가 "재료와 사람을 짜맞추고 값과 말을 셈하는" 직업이 됐으며, 전투는 "값을 외쳐 구조의 무게를 바꾸는" 조작이 됐다. 출신 도시·지역·세력도
장부와 셈으로 채워졌다("이세계 회계사").

원인은 단계 사이의 압력 차이다.

- 번역 단계는 `다루는 것`을 출처 재능 그대로 옮기도록 정해져 있다(충실성). 그래서 정체성 단계의 입력은 현실 명사다.
- 정체성 단계에는 "이세계를 지어낸다"는 목표만 있고, 현실 명사를 이세계의 힘으로 바꾸는 절차가 없었다. 전투 단계는 후보 비교가 있지만,
  그 입력인 클래스가 이미 현실 직업이었다.
- 같은 재료로 다른 방향(무리의 지휘, 기록의 주문화, 가치 교환의 변성, 물자의 소모품화 등)이 가능했으나 어느 단계도 그 후보를 펼치지 않았다.

## 결정

1. **정체성 문서의 첫 절은 `클래스 후보`다.** 후보 세 개마다 `재료`(주인공 능력), `영역`(다루는 것을 현실 명사가 아니라 기능으로 올린 말),
   `이세계의 힘`(그 기능이 이세계에서 무엇이 되어 싸우는가), `판단`(`채택` 또는 `제외 — 이유`)을 쓴다.
2. **클래스는 채택한 후보다.** 클래스의 항목 이름은 채택한 후보의 이름이고, `하는 일`은 그 후보의 `이세계의 힘`을 구체화한다.
3. **검증기는 형식만 본다.** 후보 수, 재료의 능력 인용, 판단 형식, 채택 하나, 클래스와 채택 후보의 일치를 `check-identity`가 확인한다.
   현실 동작이 남았는지는 의미 판단이라 검토자의 `비교` 기준이 본다(정체성에도 적용).
4. **부직업은 현실 직업이 남아도 된다.** 생업에서 오는 자리이기 때문이다. 이세계의 힘은 클래스와 전투의 요구다.
5. **(2026-11-26 추가, #110) 후보는 이 사람만의 조합인지로 고른다.** 재능의 갈래를 한 동작에 함께 담는지, 다른 주인공에게도 붙일 수 있는지를 견준다.
   처음에는 "전장에서 얼마나 드러내는가"로 골랐는데, 로컬 run v0.5.16(원본은 저장소에 없음)에서 재료를 즉석 무기로 바꾸는 후보가 "직접적·선제적"이라는 이유로 이기고
   사람·조직 갈래가 "새로 만들어내지 않는다"는 이유로 빠져, 클래스가 이름만 다른 대장장이가 됐다. "직접적·선제적이지 않다"는 제외 이유로 쓰지 않는다.
   (2026-11-26, #120) 이 결정의 "재능의 갈래를 한 동작에 함께 담는가"는 [장르 이름과 부직업 ADR](2026-11-26-genre-names-and-sub-jobs.md) 결정 3으로 대체됐다.
   로컬 run v0.5.17(원본은 저장소에 없음)에서 이 기준이 재능을 억지로 합친 클래스를 이기게 해, 클래스가 다시 이름만 다른 대장장이가 됐다.
6. **(2026-11-26 추가, #110) 제외한 후보에는 `남는 곳`을 쓴다.** 그 갈래가 클래스·부직업·동료·퀘스트 중 어디에 남는지 적는다. 검증기는 형식을, 검토는 그 자리에서
   실제로 쓰였는지를 본다. 지침의 구체 예시(무기로 싸우는 클래스와 그 무기를 고치는 부직업)는 흐름 명세 4.5에 따라 기능 설명으로 바꿨다.

## 검토한 대안

| 대안 | 고르지 않은 이유 |
| --- | --- |
| 번역 브리프에 `영역` 필드를 더한다 | 번역은 충실성 단계라 지어내는 일이 섞인다. 영역을 무엇으로 올릴지는 클래스 설계의 판단이다 |
| 현실 명사 금지어 목록으로 검사한다 | 단어 일치는 의미의 간접지표다. 다른 말로 같은 동작을 쓰면 통과하고, 정당한 쓰임은 막는다 |
| 지침에 이세계 직업 예시 목록을 둔다 | 지침의 구체 이미지가 결과로 새어 run 사이 수렴을 만든다(흐름 명세 4.5) |
| 판타지 메커니즘 목표 어휘(외부 데이터)를 둔다 | 라이선스·명칭 기준 확인이 먼저다(#106 후속). 후보 비교로 부족한지 관찰한 뒤 정한다 |

## 결과

- 바뀐 계약: 흐름 명세 4.7·5.5·6절, 정체성 스킬과 검증기, 검토 에이전트의 비교 기준, 재료 지도의 정체성 필드.
- 이 변경 전에 만든 `identity.md`는 `클래스 후보` 절이 없어 새 검증기를 통과하지 못한다. 뒤 단계(세계·전투·GDD)는 `## 클래스`를 그대로 읽으므로 형식이 바뀌지 않는다.
- 출신 도시가 `생활 기반`의 현실 명사를 그대로 산업으로 쓰는 문제와 통합 단계에서 재능이 줄어드는 문제는 이 결정 밖이다.
