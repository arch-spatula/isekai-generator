# ADR: Godot과 PixelFX를 이용한 게임 제작 경로 평가

* **Status:** Proposed — 격리된 프로토타입으로 평가 전
* **Date:** 2026-11-11
* **Decision Owners:** Project Owner
* **Scope:** 생성 게임의 2D 런타임과 픽셀 VFX 제작·재생 경로

## 배경

현재 생성 게임은 2D 탑다운 픽셀아트 Action RPG를 공통 제작 조건으로 사용하며,
LÖVE2D를 우선 런타임으로 정했다. 이 선택은 Lua 코드와 작은 실행 경계라는 장점이 있지만,
타일맵, 애니메이션, 파티클, UI, 내비게이션, 디버깅과 플랫폼별 내보내기를 프로젝트가
개별 라이브러리와 도구로 조합해야 한다.

Godot은 전용 2D 렌더러와 편집기, 씬·리소스 모델, TileMap, 애니메이션, 파티클, 물리,
UI, 프로파일링과 CLI 내보내기를 한 생태계에서 제공한다. 생성된 게임을 독립 저장소로
승격하여 사람이 계속 편집하고 배포하는 목표에는 이 통합 생태계가 유리할 가능성이 있다.
반면 생성 에이전트가 `project.godot`, 씬, 스크립트, 리소스 경로와 입력 설정의 관계를
일관되게 만들어야 하므로, 순수 Lua 파일을 생성하는 LÖVE2D보다 출력 계약이 복잡하다.

픽셀 VFX에는 Pixelbolt를 우선 검증 도구로 선택한 기존 결정이 있다. 이후 조사한
[PixelFX](https://github.com/patch-gg/pixelfx)는 21개 범주의 244개 효과와 공격 연기
데이터를 제공하고, 엔진 중립적인 PNG 스프라이트시트와 Aseprite 형식 JSON을 생성한다.
따라서 Godot을 사용하더라도 JavaScript 런타임을 게임에 포함하지 않고 결과를 가져올 수
있다.

이번 문서는 Godot이나 PixelFX의 최종 도입을 확정하지 않는다. 실제 생성·실행·수정·배포
비용을 작은 프로토타입으로 비교하기 위한 평가 경로를 정한다.

## 결정

LÖVE2D 기준 구현과 기존 결정을 유지한 상태에서, **Godot 4.7.x Standard와 GDScript를
사용하는 격리된 게임 프로토타입**을 만든다. 같은 프로토타입에 **PixelFX를 기본 VFX
카탈로그 후보**로 연결하여 다음 두 가설을 함께 검증한다.

1. Godot의 통합 2D 제작·디버깅·내보내기 생태계가 생성 프로젝트의 복잡성 증가보다 큰
   생산성 이점을 제공한다.
2. PixelFX의 결정적 스프라이트시트와 메타데이터가 Godot의 `SpriteFrames` 및
   `AnimatedSprite2D` 재생 경로와 안정적으로 연결되고, 탑다운 픽셀 전투의 품질 기준을
   만족한다.

프로토타입은 기존 생성 파이프라인이나 LÖVE 실험을 교체하지 않는다. 평가가 끝나기 전에
Orrery 계산 엔진을 GDScript 또는 C#으로 포팅하지 않는다. 차트 계산과 생성 오케스트레이션은
Bun/TypeScript 경계에 남기고, 게임에는 정규화된 입력과 Seed만 전달한다.

Godot 프로젝트 전체를 매번 자유 생성하지 않는다. 먼저 검증된 최소 템플릿을 만들고,
생성 단계는 명시된 씬 슬롯, 스크립트, 데이터와 에셋만 채우도록 제한할 수 있는지 평가한다.
이 방식으로 에이전트 생성 결과의 구조적 오류와 Godot 텍스트 리소스 충돌을 줄일 수 있는지도
측정한다.

## PixelFX 통합 경계

PixelFX의 JavaScript 코드는 제작 도구로만 실행한다. Godot 배포물에는 다음 결과와 필요한
라이선스 고지만 포함한다.

```text
PixelFX 소스와 고정 버전
    → 결정적 렌더 명령
    → 투명 PNG 스프라이트시트 + Aseprite JSON
    → Godot import
    → SpriteFrames + 공통 EffectPlayer
```

- 효과 ID, 도구 버전 또는 커밋, 팔레트, 시드와 렌더 옵션을 재생성 정보로 기록한다.
- JSON의 프레임 길이, 피벗, 반복 여부와 `act`의 `windup`, `recovery`, `hits`, `freeze`
  정보를 보존한다.
- 공통 `EffectPlayer`는 효과 생성, 반복 재생, 완료 후 해제와 타격 시점 알림만 담당한다.
  개별 효과마다 별도 재생 코드를 만들지 않는다.
- 화면 흔들림, 히트스톱, 캐릭터 피격 반응과 후처리는 Godot의 게임 연출 계층에서
  처리한다. PixelFX 메타데이터는 그 시점을 제공하지만 게임 상태를 직접 제어하지 않는다.
- PixelFX는 MIT 라이선스의 코드와 효과를 제공한다. 실제 고정 버전의 `LICENSE`와
  `NOTICE.md`를 확인하고 배포물의 제3자 고지에 보존한다.

## 비교 프로토타입

평가는 한 개의 작은 전투 방으로 제한한다.

- 정수 픽셀 이동이 가능한 플레이어 한 명
- 일반 적 세 개체와 피격·사망 상태
- 기본 근접 공격, 원거리 투사체, 지면 광역 공격 각 하나
- 타일 기반 충돌과 간단한 적 추적
- 체력 UI, 일시정지와 입력 재매핑의 최소 경로
- PixelFX의 검격·투사체·폭발 또는 지면 효과와 타격 시점 연결
- 데스크톱 개발 빌드와 headless CLI 내보내기

LÖVE2D와 Godot에서 화면 내용과 기능 범위를 동일하게 맞추되, 엔진별 내부 구조까지 같게
만들지는 않는다. 비교를 위해 새 범용 프레임워크, ECS나 플러그인 묶음을 먼저 도입하지
않는다.

## 성공 기준

Godot 채택 후보는 다음 조건을 모두 만족해야 한다.

1. 깨끗한 환경에서 고정된 Godot 버전으로 프로젝트를 열고 CLI로 실행·내보낼 수 있다.
2. 템플릿과 생성 데이터만으로 프로토타입을 재생성하고 자동 검증할 수 있다.
3. 생성된 씬·리소스의 누락 경로와 잘못된 연결을 headless 검사에서 탐지한다.
4. 키보드와 게임패드 입력, 충돌, 애니메이션과 UI를 외부 게임 프레임워크 없이 구현한다.
5. 같은 범위의 LÖVE2D 프로토타입보다 직접 유지할 기반 코드와 외부 라이브러리 선택이
   줄어든다.
6. 생성 결과를 사람이 Godot 편집기에서 열어 레벨, 애니메이션과 효과를 수정할 수 있다.

PixelFX 채택 후보는 다음 조건을 모두 만족해야 한다.

1. 고정 버전·시드·옵션으로 재생성한 PNG와 메타데이터가 동일하다.
2. 프레임 길이, 피벗, 반복, 앞·뒤 레이어와 타격 시점이 Godot에서 보존된다.
3. 대표 세 효과가 프로젝트 팔레트와 픽셀 크기에 맞고 전조·타격·피격을 가리지 않는다.
4. 다수의 적과 효과가 겹치는 장면에서 목표 프레임 시간과 메모리 기준을 만족한다.
5. 새 효과 추가가 공통 import와 재생 경로만으로 가능하며 수작업 리소스 수정에 의존하지
   않는다.

구체적인 프레임 시간과 메모리 한도는 대상 해상도와 최소 사양을 정할 때 기록한다. 수치가
정해지기 전에는 성능 검증을 완료로 판정하지 않는다.

## 중단 및 후속 결정

다음 중 하나가 확인되면 Godot 전환을 보류하고 LÖVE2D를 유지한다.

- 에이전트가 생성한 Godot 텍스트 리소스와 씬 연결을 결정적으로 검증할 수 없다.
- 템플릿 제약 때문에 개인화된 전투와 세계 구조를 표현하기 어렵다.
- 편집기와 내보내기의 이점보다 프로젝트 형식·버전 마이그레이션 비용이 크다.
- 목표 플랫폼에서 필요한 렌더러나 배포 경로를 재현할 수 없다.

PixelFX가 시각 품질, 탑다운 원근, 재생성 또는 성능 기준을 통과하지 못하면 Pixelbolt,
Godot 네이티브 파티클·셰이더 또는 제한된 수작업 효과를 비교한다. 여러 VFX 도구를 동시에
기본 의존성으로 채택하지 않는다.

평가가 끝나면 별도 ADR에서 다음 중 하나를 결정한다.

- Godot을 생성 게임의 우선 런타임으로 채택하고 기존 LÖVE·Lua 포팅 결정을 대체한다.
- LÖVE2D를 유지하되 PixelFX 출력만 사용한다.
- LÖVE2D와 기존 Pixelbolt 계획을 유지한다.
- 두 런타임을 서로 다른 배포 대상으로 유지할 명확한 필요가 있을 때만 이중 지원한다.

## 영향

### 기대 효과

- 탑다운 액션 RPG에 필요한 편집기와 2D 기능을 한 생태계에서 평가할 수 있다.
- PixelFX의 폭넓은 효과를 엔진 교체와 독립된 제작 아티팩트로 사용할 수 있다.
- 런타임을 정하기 전에 생성 가능성, 수동 편집성, 배포와 VFX 품질을 같은 프로토타입에서
  비교할 수 있다.
- 복잡한 차트 계산을 엔진 언어로 성급하게 다시 포팅하지 않는다.

### 비용과 위험

- 평가 기간에는 LÖVE와 Godot 두 프로토타입을 비교해야 한다.
- Godot 씬·리소스·import 결과의 버전 관리와 생성 계약을 새로 정의해야 한다.
- PixelFX 출력은 즉시 사용할 수 있어도 프로젝트 팔레트, 탑다운 원근과 캐릭터 동작에
  맞추는 미술·연출 작업이 남는다.
- Godot 버전 변경과 PixelFX 고정 버전 갱신을 각각 검증해야 한다.
