# ADR: 차트부터 GDD까지 하나의 Claude 흐름으로 만든다

* **Status:** Accepted — 문서 결정, 구현 전
* **Date:** 2026-11-23
* **Decision Owners:** Project Owner
* **관련:** [일생 해석의 게임 번역 규칙](../spec/life-to-game-translation.md), [Claude 게임 설계 흐름](../spec/claude-game-design-flow.md), [인물과 환경 해석 구분](2026-11-10-person-environment-world-story.md), #55

## 배경

지금까지 GDD는 Codex 흐름(차트 → 전문 해석 → 통합 해석 → 전투 선택 → 세계 선택 → GDD)이 만들었다. 이 흐름의 결과는 기대에
미치지 못했다.

- **기호를 세계의 명사로 직역했다.** 예를 들어 자미두수 명궁에 武曲이 있다는 이유로 주인공의 출신지를 장부 도시처럼 만들었다.
  세계 선택과 GDD가 별·궁 이름이 남은 통합 해석을 읽었고, 기호의 뜻을 가장 짧은 명사로 바꿨다.
- **주인공의 배경을 해석하지 않았다.** 통합 해석은 "어떤 사람인가"를 영역별로 정리했을 뿐, 어디서 태어나 어떻게 자랐고 무엇 때문에
  떠났는지 같은 일생의 사건을 담지 않았다. 배경을 해석할 재료가 충분히 있었는데도 그것을 해석하는 단계가 없었다.

이전 [직역 개선 계획](../GDD/personalized-gdd-remediation-plan.md)은 현실 직무 명사를 능력으로 직역하는 문제(심사 → 심사관)만 다뤘다.
기호 직역과 배경 부재는 다루지 않았다.

한편 Claude 스킬 흐름은 차트에서 일생 통합 해석 `life.md`까지 만든다. `life.md`는 기호를 생애 사건으로 옮긴 문서이며(별·궁·행성 이름을
서술에 쓰지 않는다), 유년·소년의 무대, 부모와 형제, 떠남의 계기, 상처, 관계의 무게를 담는다.

## 결정

GDD까지 Claude가 쓴다. 차트부터 GDD까지 하나의 흐름으로 만든다.

```text
chart-report → saju·ziwei·natal judgment → derived facts → saju·ziwei·natal life → life material → life.md
  → translation brief → combat selection → world selection → GDD
```

1. **입력 격리:** 번역 브리프부터 GDD까지는 `life.md`, 번역 브리프, 앞 게임 단계의 산출물만 읽는다. 차트·사실 파일·1차 판단·체계별 일생 해석은
   읽지 않는다. 기호를 볼 수 없으면 기호를 직역할 수 없다.
2. **기호 명칭 금지:** 게임 단계의 산출물에 별·궁·십신·천간·지지·행성·사인·하우스 같은 차트 명칭이 나오면 검증기가 거부한다. 명칭 목록은 계산기 상수에서 만든다.
3. **배경 해석:** 번역 브리프가 출신지·성장 환경·가족 구조·떠남의 계기를 `life.md`에서 해석한다. 배경과 세계의 요소마다
   "삶의 사실 → 반복되는 행동·감정 → 장소·세계의 성격" 해석 경로와 출처를 남긴다.
4. **세계와 배경은 환경에 관한 사실에서, 서사 갈등은 인물과 환경이 만나는 곳에서 세운다.** [인물과 환경 해석 구분 ADR](2026-11-10-person-environment-world-story.md)을
   따른다. 출신지·공동체·세력·지역의 성격은 `life.md`의 환경에 관한 사실(가족과 공동체가 준 지원·기대·제약, 생활 기반, 떠남의 조건, 그 시기의
   사건)에서 만든다. 주인공의 `축`·`반복되는 실패`·재능은 주인공의 작동 방식으로 쓰고, 그것이 환경의 지원·요구·저항과 만나는 지점에서 사건과
   선택의 대가를 만든다. 세계의 모든 문제를 주인공 내면의 비유로 환원하지 않는다. 장은 생애 단계에서 나온다.
5. **게임 형식:** 고정된 화면·아트 계약은 두지 않는다. 장르 성격만 유지한다.
   - 유지: 픽셀 그래픽, 빠른 실시간 액션, 로그라이트(런을 반복하고, 런 안에서 보상을 고르며, 런 밖에서 성장이 쌓인다).
   - 제외: 칸에 아이템을 배치하는 인벤토리, 인접 칸 시너지, 장비 슬롯 연결, 슬롯 퍼즐.
6. **전투:** 번역 브리프가 능력의 재료(재능 항목)를 정하고, 전투 선택 단계가 그 재료 안에서 후보 네 개를 비교해 구체적인 전투 방식을 고른다.
   다른 run과의 중복은 기존 지문 비교로 막는다. 세계도 지문 비교를 유지한다.
7. **진행 상태:** 파일 기반 단계표(`pipeline-status`)를 이 흐름의 단계로 바꾼다. 상태 DB는 두지 않는다.
8. **Codex 경로:** 전문 해석 → 통합 해석 경로와 `.agents/skills/`의 생성 스킬은 GDD 입력에서 뺀다. 새 흐름이 완성되어 쓰는 곳이 없어지면 제거한다.

## 결과

- [게임 번역 명세](../spec/life-to-game-translation.md)의 열린 질문 "두 생성 흐름을 잇는 방법"은 이 결정으로 정리된다. 흐름은 하나다.
- 기존 GDD 템플릿(`docs/prompts/personalized-action-rpg-concept.md`)은 통합 해석 ID와 공통 화면 계약을 전제하므로 새 흐름에서는 쓰지 않는다.
  절 구성은 이어받되 배경 절을 더한 새 템플릿을 쓴다([Claude 게임 설계 흐름](../spec/claude-game-design-flow.md)).
- 이전 직역 개선 계획의 원칙(표면 명사 제거 → 행동 패턴 변환)은 세계관과 배경까지 넓혀 적용한다.
