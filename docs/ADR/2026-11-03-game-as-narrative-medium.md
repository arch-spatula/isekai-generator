# ADR: 게임을 개인화된 서사 전달 매체로 정의

* **Status:** Accepted
* **Date:** 2026-11-03
* **Decision Owners:** Project Owner
* **Scope:** 개인화 이세계 Action RPG의 작품 방향과 게임플레이 설계 우선순위

---

# 1. Context

게임은 고유한 규칙을 통해서만 이야기를 체험하게 할 수 있지만, 모든 게임이 하나의
새롭고 특수한 메커니즘을 중심으로 작품성을 증명해야 하는 것은 아니다. 예를 들어
《Baba Is You》는 규칙 조작 자체가 작품의 핵심이지만, 이 프로젝트가 생성하려는 게임의
주된 차별점은 메커니즘 발명보다 개인화된 주인공과 삶, 모험 및 변화에 있다.

이 구분이 없으면 각 게임이 새 기믹을 제안하는 데 집중하여 서사와 시스템의 연결이
약해지거나, 반대로 서사를 강조한다는 이유로 플레이의 재미와 상호작용을 부차적으로
취급할 수 있다.

# 2. Decision

이 프로젝트의 게임을 **개인화된 서사를 플레이 가능한 경험으로 전달하는 매체**로
정의한다.

전투, 탐험, 성장, 관계와 선택 같은 Action RPG 시스템은 이야기와 분리된 기능 목록이
아니라 주인공의 욕구, 갈등, 대가와 변화를 플레이어가 직접 경험하게 하는 수단이어야
한다. 각 게임이 독창적인 단일 핵심 메커니즘을 새로 발명할 필요는 없다. 검증된 장르
문법과 재사용 가능한 Gameplay Primitive를 사용하되, 그것들이 해당 인물과 이야기를
어떻게 표현하는지가 게임별 차별점이 된다.

이 결정은 메커니즘, 재미 또는 조작감이 중요하지 않다는 뜻이 아니다. 이야기를 읽는
것과 게임을 플레이하는 것의 차이를 만들 만큼 의미 있는 상호작용과 숙련, 선택 및
피드백은 반드시 제공한다. 다만 이야기와 무관한 기믹 경쟁, 시스템 수의 증가와 복잡도
자체는 우선순위로 삼지 않는다.

# 3. Design Boundaries

- 게임플레이는 서사를 장식하거나 중단하는 별도 층이 아니라 서사의 행동과 결과를
  표현해야 한다.
- 주요 전투, 탐험, 성장과 관계 시스템에는 주인공의 욕구 또는 변화와 연결되는 이유가
  있어야 한다.
- 익숙한 Action RPG 문법을 사용하는 것은 허용한다. 새로움은 반드시 새로운 규칙에서만
  나오지 않으며, 인물·상황·시스템의 결합에서도 나올 수 있다.
- 특수 메커니즘이 서사를 더 잘 체험하게 한다면 채택할 수 있지만, 모든 생성 결과에
  이를 의무화하지 않는다.
- 컷신과 설명문만으로 서사를 전달하지 않는다. 핵심 갈등과 대가는 가능한 범위에서
  플레이어의 행동, 선택, 실패 가능성과 게임 상태 변화로 표현한다.
- 서사를 이유로 전투 감각, 조작 명료성, 피드백과 반복 플레이의 재미를 면제하지 않는다.

# 4. Consequences

## Positive

- 생성 시스템의 차별점을 특수 기믹의 수가 아니라 개인화된 플레이 경험에 집중할 수 있다.
- 익숙하고 구현 가능한 시스템을 재사용하면서도 각 이야기와 인물에 맞게 조합할 수 있다.
- 내러티브와 게임플레이를 별도로 생성한 뒤 억지로 결합하는 문제를 줄일 수 있다.
- 게임의 범위와 복잡도를 통제하면서 스토리의 행동, 대가와 변화를 플레이로 표현할 수 있다.

## Negative

- 시스템만 보았을 때 혁신성이 약하다는 인상을 줄 수 있다.
- 서사 연결을 지나치게 강조하면 순수한 전투·탐험의 리듬과 반복 재미가 약해질 수 있다.
- 익숙한 장르 문법에 의존하면서 결과가 서로 비슷해지지 않도록 조합과 표현을 검토해야 한다.
- 서사적 의도와 실제 플레이 경험의 일치 여부를 문서만으로 검증하기 어렵다.

# 5. Follow-up Application

이 결정은 다음 순서로 후속 반영한다. 이 ADR의 작성만으로 기존 문서나 생성 결과가
자동으로 변경된 것으로 보지 않는다.

## 5.1 생성 프롬프트

[`docs/prompts/personalized-action-rpg-concept.md`](../prompts/personalized-action-rpg-concept.md)에
다음을 생성 원칙과 자체 점검 기준으로 반영한다.

- 각 핵심 시스템이 주인공의 욕구, 갈등 또는 변화와 어떻게 연결되는지 설명할 것
- 독창적인 단일 메커니즘의 발명을 모든 게임에 요구하지 않을 것
- 설정과 컷신뿐 아니라 플레이어 행동과 게임 상태 변화로 주요 서사를 표현할 것
- 서사적 의미와 별개로 기본적인 조작감, 피드백과 반복 재미를 검토할 것

## 5.2 생성 모드 계약

Light와 Deep 모드의 문서 분량 차이 때문에 위 원칙이 누락되지 않도록
[`light-mode.md`](../../.agents/skills/generate-personalized-gdd/references/light-mode.md)와
[`deep-mode.md`](../../.agents/skills/generate-personalized-gdd/references/deep-mode.md)의 필수
산출 범위에 반영한다. Light 모드는 핵심 연결만 간결하게 요구하고, Deep 모드는 주요
서사 비트와 시스템·콘텐츠 루프의 대응까지 요구한다.

## 5.3 개별 GDD

향후 생성되는 각 GDD에는 최소한 다음 대응 관계가 식별되어야 한다.

```text
주인공의 욕구·갈등·변화
    → 플레이어가 하는 행동과 선택
    → 전투·탐험·성장·관계 시스템의 반응
    → 서사 및 게임 상태의 결과
```

기존 버전의 GDD는 소급하여 덮어쓰지 않는다. 이 결정이 프롬프트와 모드 계약에 반영된
뒤 새 버전으로 생성하거나, 명시적인 개정 작업에서만 적용한다.

## 5.4 검증과 플레이테스트

GDD 검증에는 핵심 시스템과 서사의 연결이 문서에 존재하는지 확인하는 기준을 추가한다.
구현 이후에는 플레이테스트에서 다음을 확인한다.

- 플레이어가 주요 행동의 서사적 이유와 결과를 이해할 수 있는가
- 핵심 변화가 설명문뿐 아니라 플레이와 게임 상태에 나타나는가
- 서사적 의미가 없어도 기본 전투와 탐험이 충분히 명료하고 재미있는가
- 서사와 무관한 시스템 복잡도가 경험을 방해하지 않는가

세부 기능의 동작과 데이터 구조는 이 ADR이 아니라 해당 기능의 `docs/spec/` 문서에
기록한다.
