# ADR: 게임 효과음 제작 도구 후보 정리

* **Status:** Proposed — 후보와 판단 기준 정리, 도구 선택 보류
* **Date:** 2026-11-17
* **Decision Owners:** Project Owner
* **Scope:** 생성 게임의 전투·이동 효과음 제작. 배경 음악과 음성은 범위 밖이다.

## 배경

[공통 게임 화면·아트 계약](../spec/game-presentation-contract.md)은 공격 준비, 유효 범위와
명중 결과를 동작·형태·색 대비와 함께 **소리**로 구별하도록 요구한다. 생성된 개인화 기획서도
명중의 짧은 금속음, 회피 성공의 발소리처럼 전투 피드백을 소리로 정의한다.

이미지와 이펙트에는 결정이 있다. [LibreSprite](2026-11-09-libresprite-image-generation.md),
[Pixelbolt](2026-11-09-pixelbolt-vfx-plan.md), [PixelFX](2026-11-11-godot-pixelfx-evaluation.md)는
모두 제작 원본을 코드나 데이터로 관리하고, 고정 버전 도구로 재생성하는 방향을 택했다.
반면 효과음에는 제작 도구도 결정도 없고, 개발 셸에는 오디오 생성·변환 도구가 하나도 없다.
[Godot 에이전트 도구 도입](2026-11-17-godot-agent-tooling-ecosystem.md)의 `audio-design` 스킬은
버스 구성과 믹싱 기법을 다루며 소리를 만드는 도구를 제공하지 않는다.

이 문서는 도구를 고르지 않는다. 나중에 고를 수 있도록 후보와 판단 기준, 비교 실험의 범위를
기록한다.

## 판단 기준

1. **재생성 가능성** — 제작 원본(파라미터, 스크립트, 출처 기록)을 Git으로 관리하고 같은 출력을
   다시 만들 수 있는가. 이미지·이펙트 결정과의 일관성이다.
2. **에이전트 조작성** — CLI나 스크립트로 실행할 수 있어 에이전트가 만들고 고칠 수 있는가.
3. **표현 적합성** — 픽셀아트 화면과 어울리는가. 짧은 금속음처럼 재질감이 필요한 소리를
   표현할 수 있는가.
4. **라이선스와 비용** — 출력물을 상용 게임에 쓸 수 있는가. 유료 서비스나 귀속 표기가
   필요한가.
5. **개발 셸 재현성** — Nix 개발 셸에 고정 버전으로 넣을 수 있는가.
6. **엔진 중립 출력** — WAV·OGG처럼 Godot과 LÖVE2D가 모두 재생하는 파일을 만드는가.
   게임 실행에 생성 도구가 필요하지 않아야 한다.

## 후보

라이선스, 저장소 활동과 nixpkgs 제공 여부는 2026-11-17에 GitHub API와 프로젝트 `flake.lock`
기준 `nix eval`로 확인했다. 표현 품질은 실제로 들어 보지 않았으므로 판단하지 않는다.

### A. 파라미터 기반 생성기 (코드가 원본)

| 후보 | 라이선스 | 실행 방식 | nixpkgs | 특징 |
|---|---|---|---|---|
| [jsfxr](https://github.com/chr15m/jsfxr) | Unlicense | npm 패키지, Node | 없음 (npm으로 고정) | sfxr 계열. 파라미터 JSON이 원본이 되고 WAV로 렌더한다. |
| [ZzFX](https://github.com/KilledByAPixel/ZzFX) | MIT | npm 패키지, JS | 없음 (npm으로 고정) | 파라미터 배열 하나로 소리를 정의한다. 브라우저 재생이 주 용도라 파일 출력 경로는 확인이 필요하다. |
| [rfxgen](https://github.com/raysan5/rfxgen) | Zlib | 네이티브 CLI·GUI | 없음 (직접 빌드 필요) | sfxr 계열. 파라미터 파일과 CLI 내보내기를 제공한다. |

* 장점: 이미지·이펙트와 같은 "코드가 원본" 흐름이고, 출력물 라이선스 부담이 거의 없다.
  개발 셸에 이미 있는 Node로 jsfxr·ZzFX를 실행할 수 있다.
* 한계: 결과가 칩튠 계열 합성음이다. 픽셀아트에는 어울릴 수 있지만 재질감 있는 금속음은
  표현이 제한될 수 있다.

### B. 녹음·라이선스 소재 사용

| 후보 | 라이선스 | 특징 |
|---|---|---|
| CC0 효과음 묶음 (예: Kenney 오디오 팩) | CC0 | 귀속 표기 없이 쓸 수 있는 녹음 소재 |
| Freesound, OpenGameArt | 소재별 상이 (CC0, CC-BY 등) | 선택 폭이 넓지만 소재마다 라이선스를 기록해야 한다 |

* 장점: 금속음, 발소리 같은 재질감을 바로 얻는다.
* 한계: 재생성 대상이 아니라 출처 기록 대상이다. 원본 파일, 출처 URL, 라이선스를 함께
  관리해야 한다. 개인화된 변형은 아래 C의 가공으로만 가능하다.

### C. 가공·변환 도구 (A나 B와 함께 사용)

| 후보 | 라이선스 | nixpkgs | 역할 |
|---|---|---|---|
| [SoX](https://sourceforge.net/projects/sox/) | GPL·LGPL | `sox` 14.4.2 | 자르기, 정규화, 피치·이펙트, 간단한 합성 |
| [FFmpeg](https://ffmpeg.org/) | LGPL·GPL | `ffmpeg-headless` 9.0.2 | 형식 변환(OGG 등), 라우드니스 정규화 |
| [Audacity](https://www.audacityteam.org/) | GPL | `audacity` 4.0.0 | 사람이 직접 편집할 때 쓰는 GUI 편집기 |

* 이 범주만으로는 소리를 설계하기 어렵다. 어떤 생성·소재 방식을 고르든 출력 형식과 음량을
  맞추는 후처리 단계로 필요할 가능성이 높다.
* SoX의 nixpkgs 버전은 2021년 이후 개발이 멈춘 상류 저장소의 스냅샷이다.

### D. AI 효과음 생성 서비스

* 텍스트 설명으로 재질감 있는 효과음을 만들 수 있다.
* 유료 API 비용이 들고, 같은 입력으로 같은 출력을 보장하지 않으며, 서비스마다 출력물의 상업적
  이용 조건이 다르다. 이번 조사에서는 특정 서비스의 약관과 가격을 확인하지 않았다.

### E. 엔진 내 절차적 합성

* Godot `AudioStreamGenerator` 등으로 실행 중에 소리를 합성한다.
* 제작 도구가 필요 없지만 게임 코드가 늘고, LÖVE2D와 출력을 공유할 수 없어 엔진 중립 기준에
  맞지 않는다. 다른 후보가 모두 실패할 때만 검토한다.

## 비교 실험 (선택 전)

도구를 고르기 전에, 기획서가 요구하는 대표 효과음 세 개로 후보를 비교한다.

1. 명중 시 짧은 금속음
2. 회피 성공 소리
3. 이동 발소리 (반복 재생 시 단조롭지 않은 변주 포함)

* 비교 조합: A의 jsfxr 단독, B의 CC0 소재와 C의 후처리, A와 C의 후처리.
* 각 조합에서 원본(파라미터 또는 출처 기록), 생성·가공 명령, 도구 버전을 기록하고 재생성
  결과가 같은지 확인한다. 녹음 소재는 가공 결과의 재생성만 확인한다.
* 전투 화면에서 들어 보고, 명중·회피·발소리가 서로 구별되는지와 반복 시 피로도를 사람이
  판단한다. 자동 검사로는 재생 길이, 클리핑, 형식만 확인한다.

## 후속 결정

실험 결과에 따라 별도 ADR에서 다음 중 하나 또는 조합을 결정한다.

* 파라미터 생성기 하나를 기본 도구로 채택한다.
* 녹음 소재를 기본으로 하고, 출처 기록 형식과 후처리 도구를 정한다.
* 소리 유형별로 생성과 소재를 나누어 쓴다. 예를 들어 UI·회피는 생성, 금속음·발소리는 소재로 한다.

채택 시에는 개발 셸에 고정 버전으로 추가하고, 제작 원본과 출력물의 저장 위치를 정한다.
