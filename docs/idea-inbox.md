# 이세계 게임 생성기 아이디어 인박스

> 상태: 초안 / 미분류 아이디어 모음
> 목적: 아직 ADR, GDD, 기술 명세로 확정하기 어려운 아이디어와 고민을 보존한다.

최근 검토: 2026-09-23

이 문서의 내용은 확정된 요구사항이 아니다. 구현 결정을 내릴 때 각 항목을 ADR, GDD,
제품 명세, 운영 문서 등으로 옮기고 이 문서에는 원래 아이디어와 결정 결과의 링크를 남긴다.

## 핵심 컨셉

사용자의 생년월일, 태어난 시간, 태어난 도시를 입력받아 사주팔자, 자미두수,
네이탈 차트를 산출하고, 이를 생성 시드로 삼아 그 사용자만 경험할 수 있는 2D 이세계
게임을 AI가 제작한다.

목표 이미지는 **No Man's Sky의 절차적 생성 경험을 개인화된 2D 이세계 인디게임에
적용한 형태**다. 전생 자체를 다루기보다는 새 세계에서 한 인물의 삶과 모험을 경험하게
한다.

## 플레이어 경험

### 게임 생성과 출시

- AI 토큰을 사용해 게임을 점진적으로 개발한다.
- 개발 완료 시점이 곧 해당 사용자의 게임 출시일이다.
- 출시 예정일은 처음에는 모호하게 보여주고, 개발이 진행될수록 구체적으로 안내한다.
- 생성 작업이 대기열이나 토큰 충전 때문에 멈출 경우 티저 감상을 권장한다.
- 게임 완성 후에는 인터넷 연결 없이 플레이할 수 있어야 한다.

### 제작 대기 중 티저

제작 과정 자체를 기다림이 아닌 콘텐츠 경험으로 만든다. 티저는 비용과 생성 방식에 따라
사후 생성하거나 완전히 끌 수 있어야 한다.

티저 생성 정책은 다음 선택지를 제공하는 방향을 검토한다.

- 게임 제작을 기다리는 동안 티저를 먼저 생성한다. 대기 시간이 긴 실행 방식에서는 이를 권장한다.
- 게임 본편을 우선 완성하고 남은 예산이나 시간으로 티저를 사후 생성한다.
- 비용을 아끼기 위해 티저 생성을 끈다.

가능한 형식:

- 포스터
- 모션 코믹스 형식의 트레일러
- 컨셉 아트
- 클로즈 베타 빌드
- 그 밖의 제작 중간 산출물

가능한 소재:

- 주인공의 실루엣과 탄생
- 유년기
- 사역마와의 조우
- 친구 또는 연인과의 조우
- 일상
- 클라이맥스의 단서

### 참여 수준

두 가지 이용 방식을 고려한다.

1. **게임 플레이어 모드**: 휴먼 인 더 루프 참여를 클로즈 베타 테스트와 피드백에 한정한다.
2. **게임 디렉터 모드**: 제작 과정 전반에 사용자가 더 자주 개입하고 결정한다.

클로즈 베타에서는 특히 비정상적인 작업 사이클, 어색한 생성 결과, 세계관과 플레이의
불일치 등을 수집한다.

피드백은 단순한 만족도 조사에 그치지 않고, 어느 생성 단계와 노드에서 문제가 생겼는지
추적할 수 있어야 한다. 게임 플레이어 모드에서는 베타 피드백을 중심으로 받고, 게임
디렉터 모드에서는 중간 산출물의 승인, 수정 요청, 재생성 같은 개입도 허용하는 방향을
검토한다.

## 생성 시스템 구상

### 입력과 시드

- 입력: 생년월일, 출생 시간, 출생 도시
- 해석 체계: 사주팔자, 자미두수, 네이탈 차트
- 해석 결과는 캐릭터, 세계, 관계, 사건, 고유 메커니즘을 생성하는 시드로 사용한다.
- 점술 체계가 결과에 미치는 영향과 재현성, 개인정보 처리 방식은 별도로 정의해야 한다.

### AI 오케스트레이션

Houdini와 Blender가 노드 그래프로 프로시저럴 콘텐츠를 만드는 방식을 AI 게임 제작에
응용한다.

- 프롬프트와 AI 워크플로 각각을 노드로 표현한다.
- AI 오케스트레이터가 목표에 맞는 노드를 선택하고 연결한다.
- 생성한 결과를 다시 AI가 평가하고 수정하는 구조를 고려한다.
- 필요하면 전용 오케스트레이션 노드 도구를 개발한다.
- 게임별 GDD와 사용된 노드 및 프롬프트를 공개 가능한 내부 자료로 남긴다.
- 노드와 프롬프트 공개 방식은 엔딩 크레딧 형식도 고려한다.

핵심 기술 난제는 AI가 다른 AI의 결과를 신뢰성 있게 평가하고, 실패를 감지하며,
비용 안에서 반복을 종료하도록 만드는 것이다.

### 실행 및 과금 방식

검토 중인 실행 방식:

- 고정 요금제 또는 무제한 토큰 요금제
- 사용량 기반 API(Pay as you go)
- AWS 인스턴스에서 로컬 모델 실행
- 사용자의 로컬 컴퓨터에서 로컬 모델 실행

`무제한 토큰 요금제`와 `Pay as you go`는 일반적으로 서로 다른 과금 방식이므로 하나의
선택지로 확정하지 않는다. 실제 제공 방식과 공급자 제한을 확인한 뒤 용어와 정책을
구분한다.

운영 아이디어:

- API 또는 AWS 방식에는 예상 비용과 상한을 명확히 경고한다.
- 로컬 실행에는 예상 생성 시간과 하드웨어 요구사항을 경고한다.
- 로컬 실행에서는 기다리는 동안 볼 티저 기능을 권장한다.
- 대기 작업은 내부 크론 잡 또는 작업 큐로 이어서 처리한다.
- 비용 예측이 쉬운 고정 요금제도 우선 검토한다.

## 게임 디자인 방향

### 기반 기술과 고정 골격

- 빠른 프로토타이핑을 위해 LÖVE2D를 우선 고려한다.
- 전체 아트 스타일과 기본 화면 구조는 일정 범위로 고정한다.
- 방향키 중심의 기본 조작과 게임 화면 구성을 고정하고, 키 설정과 사운드 설정 등 공통
  기능은 템플릿화한다.
- 공통 골격 안에서도 캐릭터와 세계별 고유 메커니즘은 구현할 수 있어야 한다.
- 스킬과 사역마의 수는 게임마다 달라질 수 있다.
- 클라이맥스는 보스전, 정치적 대결, 전쟁, 유물 해제, 봉인 등으로 달라질 수 있다.
- 게임은 여러 챕터로 나눈다.

### 아직 결정하지 않은 게임 구조

- 오픈 월드와 메트로배니아 중 어느 구조가 생성형 게임에 더 적합한가?
- 액션은 도트 그래픽, 대화는 컨셉 아트로 표현하는 혼합 방식이 적합한가?
- 한 인생을 선형적으로 체험하게 할 것인가, 현재와 기억·추억·트라우마를 오가게 할 것인가?
- 선택에 따라 엔딩이 달라져야 하는가?
- 게임 길이를 어떤 기준으로 정하고 제한할 것인가?

`무직전생`처럼 한 인물의 삶을 깊게 경험하는 감각은 참고하되, 반드시 선형 구조를
따르지는 않는다. 캐릭터와 서사는 사용자마다 달라야 한다.

### 장기 확장 아이디어

완성된 개인 게임끼리 연결하는 DLC를 고려할 수 있다. Minecraft의 개인 서버처럼
사용자가 서버에 접속해 모험가 파티를 꾸리는 형태다. 현재 1인용 게임만으로도 범위가
크므로 초기 범위에서는 제외한다.

## 생성 다양성과 편향 방지

완성 후에도 저장소를 통해 피드백을 받고, 특정 시드나 프롬프트에서 반복되는 편향을
제거할 수 있어야 한다. 아래 항목은 알려진 실패 패턴 또는 반드시 검사할 가설이다.

- 환생 종족이 인간에 치우치지 않도록 한다.
- 신분이 몰락 귀족에 치우치지 않도록 하고, 빈민가 출신, 보부상 등 다양한 배경을 포함한다.
- 오크, 고블린, 오우거, 트롤, 노움, 드워프 등 비인간 종족도 성향에 맞춰 중립적으로 배정한다.
- 외모의 매력도와 종족, 신분, 도덕성은 서로 독립된 속성으로 다룬다.
- 캐릭터의 나이가 현실 사용자 나이 또는 특정 연령대에 몰리지 않도록 한다.
- 남성 캐릭터의 의상이 제복에 치우치지 않도록 한다.
- 피부색이 흰색에 치우치지 않도록 기후, 지역, 혈통과 세계 설정에 맞는 범위를 만든다.
- 갑옷 디자인이 상체 철갑옷에 치우치지 않도록 한다.
- 남성 캐릭터의 사역마가 까마귀에 치우치지 않도록 한다.
- 주인공이 항상 궁중의 독립 세력이나 특별 권력자가 되지 않도록 한다.
- 전투 수단이 검과 창에 치우치지 않도록 한다.

이를 단순한 프롬프트 지침에만 맡기지 않고, 생성 분포와 조합을 검사하는 평가 기준 및
회귀 테스트로 발전시키는 방안을 고려한다.

특정 시드에서 문제가 발견되면 해당 결과 하나만 수동 수정하는 데 그치지 않고, 원인이 된
시드 변환 규칙, 프롬프트, 노드 또는 평가 기준을 찾아 교정하거나 제거할 수 있어야 한다.
다만 교정이 기존에 완성된 게임의 재현성을 깨뜨릴 수 있으므로 생성기 버전과 게임별
생성 기록을 함께 보존하는 방안을 검토한다.

## 공개와 피드백

- 게임 완료 후 플레이어가 추가 피드백을 저장소에 제출할 수 있어야 한다.
- 게임 생성에 사용된 노드, 프롬프트, 주요 생성 판단은 공개 가능해야 한다.
- 게임별로 달라지는 GDD 또는 생성 기록을 제공한다.
- 공개 자료에는 개인정보나 원본 출생 정보가 포함되지 않도록 경계를 정해야 한다.

## 이름과 법적 검토

- 제품명과 저장소 이름은 미정이다.
- `나혼자 이세계 모험`은 `나 혼자만 레벨업`과의 명칭 유사성 때문에 권리자 또는
  법률 대리인과의 분쟁 가능성을 검토해야 한다.
- 소프트웨어를 MIT 라이선스로 공개하는 것과 제품명·상표·콘텐츠 권리는 별개의 문제이므로,
  이름을 확정하기 전에 별도의 법률 검토가 필요하다.

## 우선 확인할 질문

1. 점술 해석 결과를 게임 요소로 변환하는 규칙은 결정론적이어야 하는가?
