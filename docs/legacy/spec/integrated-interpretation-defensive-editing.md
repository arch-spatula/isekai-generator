# 통합 해석의 방어문구 편집 검토

> 상태: 구현 — 합성 회귀 통과, 실제 모델 생성의 의미 품질 평가는 미실행
> 작성일: 2026-11-13
> 범위: 통합 해석 생성 이후, 전투 선정 전에 독립 편집 검토 추가

## 1. 목적과 실행 순서

전문 해석의 편집 검토 이후에도 통합 에이전트가 새로운 방어문구를 작성할 수 있다.
통합 문서도 독립 편집 에이전트가 검토한 뒤 채택한다.

`통합 생성 → 구조·근거 검증 → 편집 검토 → 후보 검증·채택 → 전투 선정`

구조·근거 오류는 통합 생성의 기존 수정 경로로 처리한다. 방어문구 의심만 있거나
자동 진단이 없어도 편집 검토를 수행한다. 방어문구 진단 때문에 통합 생성부터 다시
호출하지 않는다. 전문 해석의 기존 검토 흐름은 유지한다.

## 2. 검토 기준과 입력 격리

편집자는 `fork_turns="none"`으로 실행한다. 같은 run의 미채택 통합 문서, 채택된
세 전문 해석, 진단, 편집 범위·모드와 해석 지침만 DB의 필터 입력으로 받는다.
원시 출생정보·차트 원문·대화 이력·이전 run은 전달하지 않는다.

- 불필요한 면책·책임 회피는 국소 편집한다. 금지 단어를 동의어로 바꾸는 처리는 금지한다.
- 계산 전제, 실제 자료의 부재·해상도와 조건부 발현을 설명하는 문장은 보존한다.
  ‘확정하지’ 같은 문자열은 의심 위치를 찾는 진단이며 의미상 부적합의 확정 판정이 아니다.
- 자동 진단마다 수정 또는 근거 있는 보존 결정을 기록한다. 오탐 보존은 해당 원문 해시와
  위치에 연결하고, 미해결·판단 보류와 구분한다. 최종 검증에서도 검토된 보존 결정을
  사용하며 같은 문자열만으로 다시 탈락시키지 않는다.
- 통합 항목 ID·순서·영역·관계·전문 근거와 전체 전문 항목의 연결, 체계별 고유 통찰과
  의미를 보존한다. 새 해석·능력·게임 설계를 추가하지 않는다.

## 3. 시도·제출·채택 계약

> 2026-11-23부터 [SQLite 제거 명세](remove-sqlite-state.md)의 파일 기반 명령으로 관리한다. 이전 SQLite 명령(`prepare/input/dispatch/bind-worker/submit/finish`)은 삭제되었다.

`integration`도 생성 시도와 편집 시도를 구분한다. 생성 후보가 구조·근거 검증을 통과해도 상태 명령은 `edit`를 안내하며,
편집이 통과하기 전에는 정식 통합 문서를 게시하거나 전투 선정을 시작하지 않는다.

편집자는 `artifact-input.ts`로 source·진단·허용 대상을 받고 `{sourceSha256, edits, review, reviewMarkdown}` 제안을 반환한다.
부모가 이를 `artifact-edit.ts` stdin으로 넘기면 도구가 원문 일치·변경 범위·구조·근거·의미 검토 결과를 확인해 후보를 조립한다.
무수정 결과도 검토 완료 기록이 필요하다.

`target`은 통합 항목의 실제 `I-NN` ID를 사용한다. 항목 밖 문단은 입력에 도구가 제공한 안정적인 대상 식별자를 사용하며 제목
문자열을 임의 식별자로 제출하지 않는다. 보존 사유만 보고할 때 가짜 수정 대상을 요구하지 않는다.

제안 원문은 보관하지 않는다. 편집 시도의 `result.md`에 상태, scope, 실패 종류와 진단별 처리(수정 또는 보존)·보존 사유를 남긴다.
상태 명령은 통과한 편집 후보와 정식 문서가 같을 때만 통합 단계를 완료로 보므로, 게시 후 본문이 바뀌면 `repair`가 되어 후속 단계가 막힌다.

## 4. 실패와 재개

편집 호출은 최대 3회다. 최초는 문장 범위이며 의미 보존에 더 넓은 문맥이 필요한
실패에만 항목·문단, 관련 문서 영역 순으로 확대한다. 형식 오류도 호출 예산을 소비하지만
범위는 유지한다. 무제한 재시도와 문서 전체 재작성은 허용하지 않는다.

형식 오류에는 필드·허용 대상·거부 이유를, 자동 진단에는 코드·위치를 제공한다.
재시도 입력에는 직전 후보·제안·검토·진단을 포함해 원문을 추측하여 다시 쓰지 않게 한다.
해시 불일치·게시 I/O 실패는 의미 편집 재시도로 처리하지 않는다. 실행 불명·중단·재개는
기존 SQLite worker 확인과 claim 갱신 계약을 따르며, 채택된 문서를 재생성하지 않는다.

## 5. 구현 범위와 검증

변경 대상은 상태 저장소의 통합 편집·채택·후속 차단·최종 검증, 통합 진단기,
편집 스킬의 통합 대상 지원, 통합·전체 생성 스킬의 호출 흐름과 관련 명세다.
통합 전용 검토가 전문 해석의 기존 계약을 깨뜨리지 않도록 한다.

[테스트 작성 가이드](test-writing-guide.md)에 따라 개인정보 없는 합성 입력으로 검증한다.

- 정상·무수정 통합도 검토 전에는 전투 선정 불가, 검토·채택 후에는 가능하다.
- 불필요한 방어문구의 국소 편집과 정당한 자료 한계 설명의 보존을 각각 검토할 수 있다.
  자동 테스트는 판정 전달·해시 연결을 검증하며 의미 판단 자체의 증거로 보고하지 않는다.
- 잘못된 target은 구체적으로 거부하고 같은 범위로 재시도한다. 의미상 실패만 범위를
  확대하며, 총 호출 한도·원문 보존·중단 재개·최종 검증을 확인한다.
- 자동 진단이 없는 추가 의미 대상, 근거·항목 훼손, 원문 변조와 오래된 검토 승인을 검사한다.

실제 모델의 전체 GDD 재생성은 구현 검증의 필수 조건으로 삼지 않는다.
관련 합성 테스트와 `bun run check:docs`를 실행하고 구조 검증과 의미 검토 결과를 구분한다.

구현 호출: `$implement-with-test-review docs/spec/integrated-interpretation-defensive-editing.md`

## 6. 구현 검증 기록

기존 CLI와 SQLite 시도·게시 경로에 통합 편집을 연결했다. 통합 자동 진단은 구조 검사와
분리하고, 편집 입력의 허용 대상·직전 후보·제안·진단, 채택 검토의 해시·위치 연결을 추가했다.
전문 해석의 기존 범위 확대·예산·오탐 거부 정책은 유지한다.

- [통합 편집 합성 회귀](../../scripts/artifacts/integration-edit.test.ts): 필수 검토 차단,
  국소 편집·정당한 보존, 대상·범위·예산, 후보·검토 변조, 중단 재개와 게시 I/O 복구.
- 테스트 작성과 읽기 전용 독립 리뷰를 분리했다. 재시도 입력 검증·비항목 편집 반례·
  게시 복구·보존 승인 귀속 및 CLI 인수 누락 지적을 반영한 테스트로 검증했다.
- `bun run test`: 30개 파일, 271개 통과·0개 실패, 문서 검사 오류 0개.

테스트는 합성 검토 결정을 제공해 상태·검증·채택 연결을 확인한다. 실제 편집 모델이
정당한 한계 설명과 불필요한 면책을 올바르게 구분한다는 의미 평가의 증거는 아니다.
실제 GDD 재생성이나 기존 로컬 생성 결과의 수정은 수행하지 않았다.
