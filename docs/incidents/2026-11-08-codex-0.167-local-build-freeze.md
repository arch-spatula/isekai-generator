# Codex 0.167 로컬 빌드로 인한 개발 셸 정지

## 상태

- 상태: 완화 — `flake.lock`을 Codex 0.166.0을 제공하는 이전 nixpkgs 리비전으로 롤백했다.
- 발견일: 2026-11-08.
- 재탐색 시점: 2026-11-15 이후.
- 범위: `just shell`로 진입하는 Nix 개발 셸과 그 셸이 제공하는 Codex CLI.

## 문제

Codex CLI를 0.167.0으로 갱신하기 위해 `nixos-unstable` 입력의 `flake.lock`을 갱신한 뒤
`just shell`을 실행했다. Nix 공식 바이너리 캐시에서 해당 Codex derivation을 받지 못해
Codex를 로컬 release 빌드하기 시작했고, 빌드 도중 컴퓨터가 응답하지 않는 상태가 됐다.

이 저장소는 최신 Codex의 모델 선택과 에이전트 기능을 사용하기 위해 CLI를 개발 셸에
포함한다. 따라서 Codex를 셸 밖으로 분리하는 것은 이번 완화책의 범위에 포함하지 않는다.

## 확인 결과

0.167.0으로 갱신된 잠금 상태에서 다음 dry-run을 실행했다.

```sh
nix build 'path:.#devShells.x86_64-linux.default' --dry-run
```

Nix는 캐시에서 Codex 결과를 가져오는 대신 다음 두 derivation을 빌드할 예정이라고 보고했다.

```text
codex-0.167.0.drv
nix-shell.drv
```

Codex derivation은 `codex-cli`, `codex-code-mode-host`, `codex-voice-host`를 Cargo release
모드로 빌드하도록 구성돼 있었다. 설정된 substituter는 `https://cache.nixos.org/` 하나였다.

## 영향

- 최초 `just shell` 진입이 긴 Codex 소스 빌드로 바뀌었다.
- 빌드 중 시스템 전체가 응답하지 않아 작업을 계속할 수 없었다.
- 같은 잠금 상태에서 무제한 로컬 빌드를 다시 실행하면 현상이 재발할 위험이 있다.

## 원인과 한계

직접 원인은 Codex 0.167.0 패키지가 nixpkgs에 존재하더라도 현재 환경에서 사용할 수 있는
바이너리 캐시 결과가 없어 로컬 컴파일로 전환된 것이다. OpenAI의 0.167.0 릴리스와
nixpkgs 패키징 여부는 Nix 공식 캐시에서 해당 derivation을 받을 수 있다는 보장이 아니다.

시스템 정지가 CPU, 메모리, swap 또는 디스크 I/O 중 어느 자원의 포화로 발생했는지는 당시
측정 자료가 없어 확정하지 않는다. 이 문서는 로컬 빌드가 시작된 사실과 사용자가 관찰한
정지만 기록하며, 특정 자원 부족을 검증된 근본 원인으로 단정하지 않는다.

## 즉시 완화

- `flake.lock`만 Git의 기존 상태로 복구했다.
- 복구된 잠금 상태에서 `pkgs.codex.version`이 `0.166.0`임을 빌드 없이 평가했다.
- 복구 후 dry-run에는 `nix-shell.drv`만 남고 Codex derivation은 빌드 대상으로 나타나지 않았다.
- 0.167.0 잠금 상태로 `just shell`을 다시 실행하지 않는다.
- 사용자의 기존 `docs/TODO.md` 변경 등 관련 없는 작업 트리 변경은 수정하지 않았다.

## 후속 탐색

2026-11-15 이후 다음 순서로 다시 판단한다.

1. 당시 선택한 nixpkgs 리비전의 Codex 버전과 `nix build ... --dry-run` 결과를 확인한다.
2. Codex derivation이 `cache.nixos.org`에서 다운로드되는지 확인한다.
3. 캐시가 계속 없다면 OpenAI 공식 Linux 배포 바이너리를 버전과 해시로 고정하는 Nix
   패키징을 검토한다.
4. 신뢰할 수 있는 사전 빌드 경로가 없을 때만 빌드 작업 수와 메모리 사용을 제한한 로컬
   빌드를 대안으로 검토한다. 제한값은 시스템 자원을 확인한 뒤 정한다.

## 재시도 조건

0.167.0 이상으로 다시 갱신하기 전에 dry-run에서 Codex가 로컬 빌드 대상으로 나타나지
않는 것을 우선 성공 조건으로 삼는다. 로컬 빌드가 불가피하다면 자원 제한과 관찰 방법을
먼저 정하고, 단순히 `just shell`을 재실행해 성공 여부를 시험하지 않는다.
