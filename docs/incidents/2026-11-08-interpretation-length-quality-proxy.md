# 통합 해석의 문장 길이를 품질로 대리한 검증 실패

## 상태와 영향

- 발견일: 2026-11-08.
- 상태: 해결 — 통합 검증기의 산문 길이 제한 제거 및 합성 회귀 검증 완료.
- 범위: 통합 해석 검증기의 산문 길이 조건과 관련 테스트.

로컬 생성에서 세 전문 해석은 통과했으나 통합 해석이 검증에 실패해 전투·세계 선정과
최종 GDD 작성으로 진행하지 못했다. 허용된 한 번의 수정 후에도 실패해 실행은 종료됐다.
이번 수정은 기대 동작을 복구하는 버그 수정이며 새 기능·확장에 따른 minor 승격은 아니다.

## 관찰과 재현

당시 최종 통합본은 두 항목의 `양면성` 중 강점 설명이 각각 14자와 13자여서 거부됐다.
다른 부분을 유지한 채 두 설명만 메모리에서 확장하면 같은 검증기가 통과했고, 하나만
확장하면 계속 실패했다. 이는 최종본의 거부 조건을 좁힌 로컬 관찰이며 내용의 의미적
충실도나 수정 전 첫 실패 전체를 독립적으로 재검증했다는 뜻은 아니다.

개인 자료와 무관하게 다음과 같은 합성 설명으로 같은 문제를 재현할 수 있다.

```text
양면성: 강점: 약속을 지킨다. | 취약점: 도움을 늦게 구한다.
```

나머지 필수 제목·필드·근거·영역을 갖춘 문서라도 기존 검증기의
`강점:\s*\S.{15,}\|\s*취약점:\s*\S.{15,}` 조건 때문에 이 문장을 거부한다.
반대로 문자를 늘렸다는 사실만으로 설명의 근거·구체성·완결성이 나아졌다고 볼 수 없다.

## 원인

검증기는 강점·취약점뿐 아니라 공통 핵심축, 체계별 고유 통찰, 영역 간 작동 구조,
시간 변화, 해석과 조건에도 최소 글자 수를 적용했다. 일부 수치는 작성 계약에 명시되지
않았다. 필수 구조 검사에 산문의 품질을 판정한다는 가정을 섞은 것이 문제다.

기존 테스트도 짧은 설명을 `shallow`로 분류해 실패를 기대했으며, 짧지만 완결된 문장을
허용하는 회귀가 부족했다. 이는 [개발 작업 명세](../spec/three-agent-implementation-workflow.md)의
길이만으로 깊이를 판단하지 않는 원칙과 어긋난다.

통합 검증기는 구체적인 항목·필드 대신 포괄적인 계약 오류만 반환한다. 통합 단계에는
전문 해석과 같은 시도별 출력·진단 보존 장치도 없어, 첫 수정에서 다른 문구 위반을
처리한 뒤 남은 조건을 찾기 어려웠다. 두 문제는 별도 개선 과제로 남긴다.

## 수정과 검증 기준

- 통합 검증기의 산문 최소 길이를 제거하고 필수 필드와 공백이 아닌 내용은 검사한다.
- 강점·취약점 쌍, 작동 사슬의 단계 구조, 영역·관계·ID·근거 계약은 유지한다.
- 빈 필드가 다음 줄을 내용으로 삼아 통과하지 않게 한다.
- 짧고 완결된 합성 설명의 허용과 누락·공백·형식 오류의 거부를 구분해 테스트한다.
- 구조 검증 성공을 의미 품질 승인으로 보고하지 않고 근거에 맞는 충실도는 의미 검토로 남긴다.

회귀는 커밋되는 합성 테스트로 재현하며 특정 로컬 실행·출생 입력의 보존을 요구하지 않는다.
종료된 실패 실행이나 과거 생성물을 소급 수정하지 않는다. 진단 상세화와 전 단계의
시도 로그 통일은 이번 수정의 완료 조건에 포함하지 않는다.

### 검증 결과

구현·테스트 작성·읽기 전용 테스트 리뷰를 분리했다. 독립 리뷰에서 추가 구분자를
허용하던 양면성 정규식 결함을 발견해 수정하고, 비어 있는 작동 단계와 실제 항목 근거
누락의 거부도 확인했다. 재검토 승인 후 고정한 통합본에서 다음 검증을 완료했다.

- 통합 검증기 테스트 120개 통과. 각 산문 필드의 짧은 설명을 독립적으로 허용하며,
  전체 축약 문서, CRLF, CLI 성공과 빈 필드 실패를 합성 입력으로 확인했다.
- 기준 구현에서는 짧은 설명과 빈 필드의 다음 줄 오인 회귀가 실패함을 확인했다.
- `bun run test`: 21개 파일, 260개 테스트 통과, 실패 0개.
- 문서 검사 오류 0개. 기존 수동 검토 후보는 버전 정책·예제·과거 문제 설명으로 유지했다.

이 해결 판정은 부당한 길이 거부와 해당 구조 검사에 한정한다. 생성 내용의 의미 품질,
상세 진단 및 시도별 로그 문제를 해결했다는 뜻은 아니다.

## 후속: 진단과 실행 로그 통일

별도 후속 변경으로 [실행별 이벤트 로그](../spec/artifact-event-log.md)를 추가한다.
통합 검증기는 항목·필드·행과 위반 조건을 반환하고, 검증 래퍼는 그 진단을 실행 루트의
`events.jsonl`에 append한다. 전문 해석의 실패·재시도·한도 소진도 같은 파일에 기록한다.
진행 체크포인트는 유지하되 실패 원인을 대신하지 않는다. 과거에 기록하지 않은 첫 시도의
진단을 복원했다고 주장하거나 종료된 실행을 소급 수정하지 않는다.
