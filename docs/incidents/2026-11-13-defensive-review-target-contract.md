# 방어문구 검토 대상 식별자 오류와 불필요한 범위 확대

> 상태: 미해결 — 생성은 재시도로 완료, 제출 계약 안내와 오류별 복구 정책 개선 필요
> 발견일: 2026-11-13
> 범위: 전문 해석 방어문구 편집의 secondary 대상 지정과 재시도 범위
> 추적 이슈: [#16](https://github.com/arch-spatula/isekai-generator/issues/16)

## 기대 동작

편집 에이전트는 문서 제목과 전문 해석 항목 ID를 구분해 검토 결과를 제출해야 한다.
`review.secondary[].target`은 실제 전문 항목 ID를 사용한다. 수정할 문장이 없으면
빈 편집 목록과 의미 검토 보고서를 제출할 수 있다.

제출 형식이 잘못된 경우와 문장 범위에서 의미를 보존하며 고칠 수 없는 경우를
구분해야 한다. 형식 오류만으로 더 넓은 본문 편집이 필요하다고 판단해서는 안 된다.

## 관측된 실패와 복구

로컬 생성의 사주 해석은 구조 검증을 통과했다. 첫 편집 에이전트도 수정할 방어문구가
없다고 판단해 `edits: []`를 반환했지만, 유지할 표현을 secondary 검토 대상으로 기록하면서
항목 ID와 제목을 섞어 사용했다. 아래는 개인정보를 제외한 관측 필드의 최소 발췌다.

```text
review.secondary[].target
S-01          → 실제 전문 항목 ID
계산 전제     → 문서 제목
오행의 배치   → 문서 제목
# 신살        → 문서 제목
```

검증기는 제목을 대상 식별자로 인정하지 않아 `editing-contract`와
`Error: Invalid secondary target`을 기록했다. 문서 제목을 바꾸거나 정해진 제목을
어긴 사건이 아니며, 해석 내용의 의미 오류를 발견했다는 결과도 아니다.

DB는 편집 실패를 집계해 다음 검토 범위를 `sentence`에서 `item`으로 확대했다.
두 번째 에이전트는 다시 검토한 뒤 수정할 내용이 없다고 판단해 `edits: []`,
`review.secondary: []`로 제출했고 통과했다. 사주 해석 본문은 변경되지 않았다.
이 실패 때문에 편집 모델 호출이 한 번 추가되고 편집 예산 한 회가 더 소비됐다.
토큰 사용량과 비용은 측정하지 않았다.

## 확인한 원인과 계약 공백

- [편집 검증 코드](../../scripts/artifacts/defensive-edit.ts)는 secondary 대상이 실제
  전문 항목 영역에 존재하는지 검사한다. 제목을 거부한 동작은 현재 계약에 따른 것이다.
- [편집 스킬](../../.agents/skills/edit-defensive-phrases/SKILL.md)은 secondary의
  `target` 필드를 나열하지만, 제목을 허용하지 않는 값의 제약과 제목 영역을 검토했을 때의
  보고 위치를 명시적으로 안내하지 않는다. 실행 입력과 안내의 보완 범위는 추가 검토가 필요하다.
- [상태 저장소](../../scripts/artifacts/artifact-state-store.ts)의 편집 재시도 범위는
  `editing-failed` 횟수로 결정된다. 이번 형식 오류에도 다음 범위가 확대됐으며,
  대상 식별자 수정에 의미 편집 범위 확대가 필요했다는 근거는 없다.
- 첫 제출의 `edits`는 비어 있었다. 빈 편집 목록도 검토 메타데이터의 유효성 검사를
  통과해야 하므로 잘못된 secondary가 전체 제출을 막았다.

## 후속 검토와 해결 기준

1. secondary 대상의 허용 값과 제목·서문처럼 항목 ID가 없는 영역의 검토 보고 방식을
   명시한다. 이 기록만으로 제목 영역을 편집 가능하게 넓히는 정책을 확정하지 않는다.
2. 제출 형식 오류와 의미 편집 실패를 구분하고, 각 오류의 범위·호출 예산·복구 정책을
   정한다. 형식 오류를 무제한 재시도하게 만들지는 않는다.
3. 합성 입력으로 실제 항목 ID, 잘못된 제목 대상, 빈 편집·빈 secondary의 동작을 검증한다.
   제목을 검토했다는 사실만으로 가짜 수정 대상을 만들도록 요구하지 않는다.
4. 잘못된 대상은 명확한 진단으로 거부하고, 복구 시 원문·근거·항목 ID를 보존하는지
   확인한다. 의미상 범위 확대가 필요한 사례도 별도로 검증한다.

이 문서는 당시 로컬 실행과 소스에서 확인한 관찰 기록이다. 최소 발췌는 실행 가능한
합성 fixture가 아니며, 이번 기록 작업에서 새로운 회귀 테스트나 모델 재실험은 수행하지
않았다. 로컬 원본은 커밋하지 않으므로 원본 전체의 독립 재검증에는 한계가 있다.
문서는 특정 실행이나 개인 출생 입력 없이 문제를 설명하며, 구현 수정은 후속 작업이다.
