# LÖVE2D 이펙트 라이브러리 조사

> 조사일: 2026-11-09
> 상태: 후보 조사 — 외부 라이브러리 설치·실행·도입 검증 전

## 목적과 범위

탑다운 픽셀 Action RPG의 이펙트를 최대한 코드로 관리하기 위해 LÖVE2D 관련 라이브러리와
제작 도구를 비교한다. 이미지 생성, 파티클 실행, 화면 후처리와 타격 연출의 시간 제어는
서로 다른 역할이다. 완성된 효과 소재와 이를 재생·가공하는 라이브러리를 구분한다.

아래 날짜는 공식 저장소의 생성일과 최근 푸시 시점에 대한 조사 당시 관찰이다.
프로젝트의 최초 개발일이나 안정성 보증을 뜻하지 않으며 이후 바뀔 수 있다.
공식 문서·소스·GitHub 메타데이터를 검토했지만 외부 후보를 실제 실행하지는 않았다.

## 후보 비교

| 후보 | 역할과 코드 관리 방식 | 조사 당시 연혁·상태 | 적용 판단 |
| --- | --- | --- | --- |
| [moonshine](https://github.com/vrld/moonshine) | Lua로 발광·색 보정·안개 등 후처리 셰이더를 조합 | 2015-01 생성, 최근 푸시 2023-12 | 다음 실험의 우선 후보. 검격·폭발 소재를 생성하는 도구는 아님 |
| [feel.lua](https://github.com/Kyonru/feel.lua) | Lua 레시피로 파티클 이벤트·흔들림·플래시·소리 등을 순차·병렬 실행 | 2026-05 생성, 최근 푸시 2026-10 | 코드 기반 연출 관리에 적합한 실험 후보. 조사 당시 작은 프로젝트이며 독립 출시 게임의 채택 근거는 확인하지 못함 |
| [STALKER-X](https://github.com/a327ex/STALKER-X) | 탑다운 카메라 추적·흔들림·플래시·페이드 | 2017-11 생성, 최근 푸시 2019-09, 보관 상태 | 기존 구현 참고 또는 제한적 도입 후보 |
| [Hot Particles](https://github.com/ReFreezed/HotParticles) | 파티클을 편집기에서 조절하고 Lua 코드로 출력 | 2020-05 생성, 최근 푸시 2022-03 | 입자 수치 튜닝용 보조 도구. 현재 환경의 호환성과 도구·출력물의 라이선스 확인 필요 |
| [light_world.lua](https://github.com/tanema/light_world.lua) | 동적 조명·그림자·노멀맵·발광맵 | 2014-10 생성, 최근 푸시 2025-11 | 조명이 미술의 핵심이 될 때 검토. 현재 작은 전투 효과 실험에는 범위가 큼 |
| [Effekseer](https://github.com/effekseer/Effekseer) | 전용 편집기와 런타임·플러그인으로 복잡한 파티클 제작·재생 | 별도의 편집기·런타임 통합이 필요한 도구 체계 | LÖVE 연결과 코드 중심 제작의 비용을 검토한 뒤 판단. 즉시 도입 대상으로 삼지 않음 |

moonshine은 LÖVE 공식 [Shader 문서](https://love2d.org/wiki/Shader)에서도 참고 대상으로
소개한다. STALKER-X는 실제 출시 게임
[BYTEPATH의 코드](https://github.com/a327ex/BYTEPATH/blob/master/main.lua)에서 사용하는 것을
확인했다. 이 사실이 각 후보의 현재 LÖVE 11.5 호환성이나 픽셀 화풍 적합성을 입증하지는 않는다.

## 비용과 라이선스 확인 범위

- moonshine 본체는 MIT이며 개별 효과는 MIT 또는 퍼블릭 도메인으로 구분된다.
  도입할 파일별 고지를 보존한다. [공식 라이선스 설명](https://github.com/vrld/moonshine#license)
- feel.lua는 MIT이며 flux를 포함한다. 자체 렌더러를 대신하기보다 게임이 소유한
  객체와 이벤트의 타이밍·값을 제어한다. [공식 설명](https://github.com/Kyonru/feel.lua#readme)
- light_world.lua는 MIT다. [라이선스](https://github.com/tanema/light_world.lua/blob/master/LICENSE)
- 나머지 후보는 이번 조사에서 배포 구성 전체의 라이선스 조건을 확정하지 않았다.
  실제 선택 버전의 코드·셰이더·소재·의존성 조건과 비용을 도입 전에 확인한다.

## 추천 방향과 다음 실험

현재 추천은 LÖVE 내장 파티클과 Lua로 직접 그리는 효과를 바탕으로 필요한 후처리만
추가하는 방식이다. 연출 순서가 복잡해지면
[flux](https://github.com/rxi/flux) 또는 [hump.timer](https://github.com/vrld/hump)의 시간 제어를
검토하고, 더 높은 수준의 레시피 관리가 필요할 때 feel.lua와 비교한다.
여러 시간 제어 라이브러리를 동시에 추가하는 것을 기본값으로 삼지 않는다.

다음 비교 대상으로는 moonshine의 약한 발광을 효과 전용 캔버스에 적용해 켜기·끄기를
비교하는 실험을 권한다. 배경·캐릭터의 픽셀 윤곽과 적의 공격 예고가 유지되는지,
효과 중첩 시 프레임 시간이 허용 범위인지 확인한다. 아직 구현하거나 성능을 측정하지 않았다.

이번 조사에서는 세피리아풍 검격·마법·폭발을 함께 제공하면서 장기 유지보수와 LÖVE 연결,
코드 중심 제작을 모두 충족한다고 확인할 수 있는 종합 라이브러리를 찾지 못했다.
이는 그런 프로젝트가 존재하지 않는다는 단정이 아니다.
