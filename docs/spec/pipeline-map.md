# 생성 흐름의 재료 지도

> 상태: 구현 — `scripts/pipeline-map.ts`, `bun run check:pipeline`
> 작성일: 2026-11-25

## 1. 목표

생성 흐름 자체가 적절한지 저장소를 유지보수하면서 확인한다. 생성 중에는 실행하지 않는다.

반복된 실패의 다수는 한 단계가 자기 입력에 없는 재료를 요구한 데서 나왔다. 배경이 없는 `life.md`에서 배경을 해석하라고 했고(#97),
기질을 담을 자리가 없어 기질이 재능이 됐으며(#99), 주인공 사건만 있는 장에서 시대의 모습을 쓰라고 했다(#100). 이것은 스킬·명세·검증기를 바꿀 때 생기므로
그때 확인한다.

## 2. 지도와 검사

`scripts/pipeline-map.ts`의 `STAGES`가 단계마다 읽는 파일, 쓰는 필드(`<섹션> > <필드>`), 그 필드의 재료(앞 단계 필드, 같은 단계 필드, 외부 표)를 선언한다.
인용 필드(`근거`·`재료`·`출처`)는 재료가 아니라 빼고, 체계별 일생 해석과 재료표는 섹션 단위(`<섹션> > *`)로 적는다.

| 검사 | 막는 실수 |
| --- | --- |
| 모든 필드에 재료가 있거나 `invented`(지어냄)와 이유가 있다 | 재료 없는 요구가 드러나지 않음 |
| 재료는 그 단계가 읽는 단계의 필드이고, 그 단계에 실제로 선언돼 있다 | 입력 격리 위반, 없는 필드를 재료로 가정 |
| 지도의 필드와 합성 fixture의 필드가 같다 | 형식이 바뀌었는데 지도가 낡음 |
| 스킬의 '읽기' 절이 선언한 입력 파일을 모두 말한다 | 스킬과 지도의 입력이 어긋남 |

`bun run check:pipeline`(또는 `bun scripts/pipeline-map.ts`)이 위반을 한 줄씩 출력하고, `bun run test`에도 들어 있다.
`--report`를 붙이면 지어내는 필드, 알려진 재료 부족(`gap`), 뒤 단계가 쓰지 않는 필드를 보고서로 출력한다. 보고서는 판정이 아니라 점검 목록이다.

## 3. 언제 쓰는가

- 스킬·명세·검증기의 필드나 입력을 바꾸면 지도를 함께 고치고 `bun run check:pipeline`을 통과시킨다.
- 새 요구를 넣을 때 그 필드의 재료를 지도에 먼저 적어 본다. 재료를 적을 수 없으면 앞 단계에 재료를 만들거나, 지어냄을 허용하는 자리로 표시한다.
- 생성 결과에서 같은 자리가 반복해서 걸리면 보고서의 `gap`과 `invented`를 먼저 본다.

## 4. 한계

- 재료가 선언돼 있는지만 본다. 재료가 의미상 충분한지(예: 동료의 삶의 사실이 전투 행동의 재료가 되는가)는 `gap`으로 사람이 적어 둔다.
- 지도는 사람이 쓴다. 필드 목록은 fixture와 대조해 낡지 않게 하지만, 재료 관계 자체가 맞는지는 검토로 본다.
