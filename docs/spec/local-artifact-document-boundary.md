# 로컬 아티팩트와 영구 문서의 근거 분리

> 상태: 구현 완료 — 참조 정비 및 아티팩트 없는 사본 검증 완료
> 작성일: 2026-11-05
> 해결 대상: [영구 문서의 로컬 아티팩트 의존 인시던트](../incidents/2026-11-05-local-artifact-document-dependency.md)

## 1. 목표와 성공 조건

커밋되는 문서가 로컬 생성 결과의 보존을 전제로 하지 않게 한다. 문제 발견 당시의
유용한 관찰은 남기되, 저장소가 제공하는 재현 자료와 구분한다.

- 로컬 `artifacts/`가 없어도 문제, 결정, 구현 계약과 검증 방법을 이해할 수 있다.
- 저장소 문서의 근거 링크가 특정 로컬 run이나 로컬 레지스트리를 가리키지 않는다.
- 필수 회귀 절차가 이전 GDD나 개인 출생 입력의 존재에 의존하지 않는다.
- 당시 관찰, 재현된 사실, 아직 재현되지 않은 가설을 구별한다.
- 개인정보를 제거한 최소 재현 자료만 커밋하고 기존 로컬 아티팩트는 변경하지 않는다.
- 재발 방지 검사는 경로 계약·버전 정책 설명까지 무차별적으로 금지하지 않는다.

## 2. 범위

포함 대상은 `docs/`의 운영 문서·ADR·인시던트·spec·프롬프트, 프로젝트 지침,
스킬 지침과 reference, 그리고 그 문서가 요구하는 회귀 테스트·fixture다.
저장소 최상위 문서 등 다른 추적 Markdown도 조사한다.

`docs/legacy/`는 탐색·검색·읽기·수정 대상에서 제외한다. 로컬 아티팩트의 이동·삭제·
재번호 부여, `.gitignore` 해제, 생성 결과 전체의 fixture 전환, 외부 자료 보관 서비스 도입,
미해결 해석 품질 문제 자체의 수정은 범위 밖이다. 활성 series도 이 작업만으로 바꾸지 않는다.

## 3. 참조 분류와 정비 규칙

| 분류 | 판별 기준 | 처리 |
| --- | --- | --- |
| 저장 계약 | 파일이 만들어질 위치·이름·스키마를 설명 | `<version>`, `<run-directory>` 등 일반 경로를 유지 |
| 형식 예제 | 버전·지문·manifest의 문법을 보여 줌 | 가상 예제임을 명시하고 실제 실행의 존재를 전제하지 않음 |
| 역사적 관찰 | 당시 조사자가 특정 결과에서 관찰한 사실 | 현상·판정 기준·관찰 결과를 문서 자체에 남기고 로컬 관찰임을 명시 |
| 영구 근거 링크 | 특정 로컬 파일이나 행을 열어야 함 | 필요한 최소 사례를 문서에 포함하고 로컬 링크·행 번호 의존 제거 |
| 필수 재현·회귀 | 특정 이전 결과·개인 입력으로 비교해야 함 | 합성 fixture와 명시적 평가 기준으로 교체 |
| 로컬 운영 | 동일 run의 재개·시도 관리·레지스트리 비교 | 실행 시 접근하는 로컬 계약으로 유지, 원본이 커밋됐다고 주장하지 않음 |
| 저장소 소스 참조 | `scripts/artifacts/` 등 추적 소스 코드 | 정상적인 소스 참조로 유지 |

버전 숫자가 있다는 이유만으로 위반으로 보지 않는다. 예를 들어 minor 채택 결정과
버전 문법 설명은 유지할 수 있다. 과거 실행 번호가 필요하면 당시의 로컬 식별자라고
명시하고 해당 파일에 접근해야 이해할 수 있는 구조를 없앤다. 불필요한 실행 번호는 제거한다.

## 4. 문서 종류별 수정 계획

### 인시던트

- 발견 시점, 기대·실제 동작, 최소 사례, 원인과 재현 상태를 문서만으로 이해할 수 있게 작성한다.
- 특정 파일 링크와 행 번호 대신 필요한 구절·입력 조건·검증 결과를 최소한으로 기록한다.
- 인용할 내용은 개인 식별·출생정보와 무관한 최소 조각으로 제한한다.
- 추출·변형한 사례를 원본 전체나 완전한 재현이라고 부르지 않는다.
- 집계 기록은 조사 범위·분류 기준·당시 결과를 보존하되 원본이 저장소에 없고
  독립적인 재검증이 제한됨을 밝힌다. 근거 없이 집계값을 재계산하거나 재현 완료로 바꾸지 않는다.

### ADR·spec·작업 계획

- 결정의 이유는 저장소 문서와 구현 계약을 통해 설명한다.
- 로컬 생성 성공은 당시의 관찰로 기록하고 커밋된 테스트 결과와 분리한다.
- 특정 이전 출력과의 비교 요구는 평가표와 합성 사례로 바꾼다.
- 실제 모델의 새 생성 실험은 별도 선택적 검증으로 분리한다. 그 결과와 상세 비교는
  로컬 run에 기록하며 저장소의 필수 재현 조건으로 만들지 않는다.
- 원래 입력이 보존되지 않았다면 같은 입력 재현이 가능하다고 주장하지 않는다.

### 스킬·프롬프트·프로젝트 지침

- 영구 문서 작성 시 로컬 아티팩트의 존재를 전제하지 않는 규칙을 추가한다.
- 현재 run의 출력 경로·시도 관리·인계 참조는 유지한다. 이는 실행 도중의 로컬 입력·출력 계약이다.
- 예제의 특정 실행 번호는 가상 값임을 표시하거나 일반화한다.
- 생성 결과를 확인할 권한과 그것을 영구 문서로 복제할 권한을 혼동하지 않게 한다.

## 5. 재현 자료 설계

합성 fixture는 원본을 보관하는 대체 저장소가 아니다. 확인할 문제를 일으키는 최소 구조를
직접 작성하고 기존 테스트의 위치·관례에 맞춘다. 공통 fixture 프레임워크를 새로 만들지 않는다.

예상 대상은 다음과 같으며 기존 fixture로 충분하면 재사용한다.

- 문서에 장식 구분선이 포함될 때 semantic evidence와 구별되는 최소 사례
- 방어적 의미를 가진 문장과 정당한 자료 부재·조건부 표현의 구분 사례
- 이름만 달라도 같은 전투·세계 구조로 비교되는 지문 사례
- 현실 직무 명사의 직접 치환과 행동 패턴의 창작적 변환을 비교하는 짧은 가상 사례

사례 작성과 회귀 판단 정책의 구현을 구분한다. 예를 들어 방어적 문장의 의미 검증이 아직
미구현이면 fixture가 존재한다는 이유로 해당 품질 인시던트를 해결 완료로 처리하지 않는다.

각 사례에는 무엇을 검증하는지, 실제 관찰에서 어떤 특성을 추출했는지, 합성한 범위와
검증의 한계를 설명한다. 원시 출생정보, 실제 개인 해석 전체, 특정 로컬 실행과의 매핑은
저장소 재현 자료에 넣지 않는다.

## 6. 재발 방지 검증 계획

문서 참조 검사는 저장소 소스만 대상으로 하고 로컬 `artifacts/`를 읽어 누락을 메우지 않는다.
기존 검사 도구가 있으면 확장하고, 없으면 최소한의 문서 검사 명령을 추가한다.

자동 실패 대상으로 구현한 것은 다음과 같다.

- Markdown 링크·이미지 링크·HTML 경로 등이 특정 로컬 run을 대상으로 하는 경우
- 사용자 홈 등 로컬 절대 경로의 아티팩트를 영구 문서에서 연결하는 경우
- fixture·재현 도구의 의존성은 소스 검토와 아티팩트 없는 사본에서의 전체 테스트로 확인한다.
  문서 링크 검사기만으로 임의의 코드가 읽는 파일을 판정한다고 주장하지 않는다.

반면 본문의 특정 실행 번호, 일반 경로 설명, 집계의 의미와 비교 절차의 의존성은
자동 검사만으로 확정하기 어렵다. 후보 위치를 보고하고 사람이 위 분류표로 판단한다.
이 과정을 단어 금지 정규식만으로 대체하지 않는다.

허용 예제와 위반 예제를 함께 검증해 일반 저장 계약, 가상 버전, `scripts/artifacts/`
소스 링크를 잘못 막지 않는지 확인한다. 검사 자체는 `docs/legacy/`를 읽지 않아야 한다.

## 7. 구현 순서와 검증

1. **참조 목록 작성·분류**
   - 로컬 아티팩트 내용이 아닌 추적 문서와 소스의 참조를 조사한다. 링크뿐 아니라
     “같은 출생 입력”, “기존 결과와 비교”, “과거 출력을 fixture로 보존” 같은 요구도 확인한다.
   - 검증: 각 후보에 분류·유지/수정 이유·완료 조건이 있다. legacy는 조사하지 않는다.
2. **최소 근거를 문서 안에 보존**
   - 기존 인시던트에서 현상·최소 사례·판정 기준을 확보한 뒤 로컬 링크 의존을 제거한다.
   - 검증: 원본 없이도 문제를 설명할 수 있고 개인정보나 전체 생성 문서를 복제하지 않는다.
3. **ADR·spec·회귀 계획 정비**
   - 특정 실행 의존을 제거하고 당시 관찰과 재현 가능한 검증을 구분한다.
   - 검증: 특정 이전 GDD나 개인 입력이 없어도 필수 작업 계획을 수행할 수 있다.
4. **필요한 합성 fixture와 재현 절차 정리**
   - 기존 사례를 재사용하고 부족한 최소 사례만 추가한다.
   - 검증: 임시 디렉터리에서 실행되며 원본 아티팩트나 실제 출생 입력을 요구하지 않는다.
5. **작성 지침과 참조 검사 추가**
   - 프로젝트·스킬의 문서 작성 규칙과 검사 명령을 연결한다.
   - 검증: 잘못된 로컬 링크를 탐지하고 정상적인 저장 경로·소스 참조는 허용한다.
6. **아티팩트 없는 작업 사본에서 확인**
   - 추적 파일과 변경 대상 파일만 복사한 임시 작업 사본을 사용한다. 실제 로컬
     아티팩트를 삭제·이동해 시험하지 않는다. 필요한 의존성은 별도 설치 절차를 따른다.
   - 검증: 문서 링크 검사, 필수 재현 절차와 관련 테스트를 실행하고 접근성·설명 완결성을 검토한다.
7. **문제 종료 여부 판정**
   - 문서별 수정 결과, 미재현 항목과 남은 수동 검토 범위를 기록한다.
   - 검증: 수용 기준 충족 후에만 이 참조 의존 인시던트를 닫는다. 다른 품질 이슈는 별도로 유지한다.

## 9. 최종 수용 기준

- 커밋되는 문서의 특정 로컬 아티팩트 링크가 제거됐다.
- 역사적 관찰은 최소 정보로 자체 설명되고 원본의 영구 보존을 전제하지 않는다.
- 필수 회귀·검증은 커밋된 자료만으로 수행되며 로컬 결과를 추정하지 않는다.
- 집계 관찰을 재현 가능하거나 독립 검증된 데이터로 과장하지 않는다.
- 개인 정보·전체 생성 결과를 커밋하거나 외부로 옮기지 않는다.
- 일반 경로 계약과 실행 중인 run의 진행·복구 참조는 계속 사용할 수 있다.
- 로컬 아티팩트가 없는 작업 사본에서도 문서와 필수 검증이 성립한다.

| 기준선 채택 ADR | 버전 채택 결정은 유지, 로컬 성공은 당시의 관찰로 구분 | 특정 원본 실행에 대한 접근 요구 없음 |

검사기의 수동 검토 후보 10개는 위 버전 정책·가상 예제·도입 당시 기록·문제 설명으로
분류해 유지했다. 후보 수는 이후 문서 변경에 따라 달라질 수 있으며 자동 승인 목록이 아니다.

### 추가·연결한 자료

- [문서 참조 검사기](../../scripts/check-document-artifacts.ts): 추적·신규 Markdown을
  조사하고 실제 로컬 아티팩트 링크를 오류로 반환한다. 코드 블록 안의 형식 예제는 제외한다.
  의미상 비교 의존을 완전히 판정하는 Markdown 파서나 의미 분석기는 아니다.
- `bun run check:docs`: 문서 검사. `bun run check:docs --review`로 수동 검토 후보를 출력한다.
- `bun run test`: 전체 테스트 뒤 문서 검사도 실행한다. `just test`도 같은 경로를 사용한다.
- [합성 평가 자료](../../scripts/fixtures/README.md): 방어적 의미·직역 문제의 수동 비교 자료와
  기존 구조 검증 테스트를 연결한다. 의미 판정이나 실제 생성 품질이 해결됐다고 주장하지 않는다.
- 프로젝트 지침 및 생성 스킬에 로컬 아티팩트와 영구 문서의 경계를 추가했다.

### 검증 기록

- 일반 작업 트리와 아티팩트 없는 임시 사본에서 각각 `bun run test` 통과:
  19개 파일, 149개 테스트, 문서 참조 오류 0개.
- 소스 사본은 Git의 추적·신규 파일 목록에서 만들었다. `artifacts/`와 `docs/legacy/`는
  복사하거나 읽지 않았고, 의존성만 기존 설치 디렉터리로 별도 연결했다.
- 임시 사본을 새 Git 작업 트리로 초기화해 검사기가 로컬 원본의 존재에 의존하지 않는지 확인했다.
- 저장소 Markdown 링크의 누락 후보 0개, 변경 파일의 `git diff --check` 통과.
- 생성 스킬 두 개의 `quick_validate.py` 통과.

로컬 원본은 삭제·이동·수정하지 않았고 `.gitignore`와 활성 series도 변경하지 않았다.
컨텍스트 인계와 해석 품질의 미해결 incident는 이번 참조 정비의 완료와 별개로 유지한다.
