# Tauri 출생 프로필·명식 톱니바퀴 UI 명세

> 상태: 확정
> 작성일: 2026-09-24
> 범위: Tauri 애플리케이션의 출생 프로필 입력, 명식 계산 상태, 톱니바퀴 연출 및 생성 세션

## 1. 목적

사용자가 생년월일, 출생 시간, 출생 도시, 성별을 입력하면 사주팔자·자미두수·네이탈
차트를 계산하고, 세 결과와 통합 Seed가 준비된 경우에만 개인화 게임 생성으로 진행할 수
있게 한다.

입력과 명식 계산은 Tauri 앱 안에서 수행한다. 최종 사용자는 별도의 브라우저나 localhost
페이지를 사용하지 않는다. 개발 단계의 로컬 개발 서버 사용은 구현 편의를 위한 예외이며,
배포 실행 경로는 Tauri로 통합한다.

## 2. 설계 원칙

- 점술 결과는 미래 예측이 아닌 게임 생성을 위한 창작 Seed다.
- 세 차트가 모두 성공해야 생성 세션을 시작한다.
- 톱니바퀴는 계산 상태의 장식적 피드백이며 회전 각도에 점술적 의미를 부여하지 않는다.
- 입력값 변경은 기존 완성 게임을 수정하지 않고 새 생성 세션을 만든다.
- 생성 중간 산출물과 최종 산출물을 구분한다.
- 작업이 중단되면 자동으로 재실행하지 않고 사용자의 명시적 재개를 요구한다.

## 3. 애플리케이션 경계

```text
Tauri App
├── Profile UI
├── Chart Summary UI
├── Gear Animation UI
├── Generation Session UI
├── Rust Job Manager
├── Chart Calculation Adapter
└── Agent Adapter Registry
    ├── Claude Adapter
    └── Codex Adapter
```

Tauri는 입력 화면, 계산 상태, 작업 큐, 로컬 저장소, 티저·베타·완성 게임 목록을 통합한다.
생성된 2D 게임 자체는 별도 런타임으로 실행하며, 현재 게임 런타임 결정에 따라 LÖVE2D를
우선 사용한다.

## 4. 입력 프로필

### 4.1 필드

| 그룹 | 필드 | 필수 | 입력 방식 |
| --- | --- | --- | --- |
| 날짜 | 연·월·일 | 예 | 키보드 상하, 마우스 입력 |
| 시간 | 시·분 | 예 | 키보드 상하, 마우스 입력 |
| 도시 | 도시 검색·선택 | 예 | 문자 입력, 드롭다운 선택 |
| 성별 | 남성·여성 | 예 | 키보드 상하, 드롭다운 선택 |

출생 시간 미상 모드는 제공하지 않는다. 모든 입력이 유효하게 확정되어야 진행할 수 있다.

### 4.2 도시 입력

- 도시명은 로컬 도시 데이터셋을 검색한다.
- 키보드 문자 입력으로 검색어를 입력할 수 있다.
- 검색 결과는 도시·행정구역·국가를 함께 표시한다.
- 사용자는 드롭다운 후보 중 하나를 선택해야 한다.
- 자유 문자열만 입력한 상태는 유효한 도시로 인정하지 않는다.
- 선택 시 `cityId`, 표시 이름, 국가 코드, 위도, 경도, IANA 타임존을 확정한다.
- 기본 동작은 외부 지오코딩 API를 호출하지 않는다.

### 4.3 성별

성별 필드는 `남성`과 `여성`을 제공한다. 이 값은 현재 계산 엔진이 요구하는 입력으로
사용한다. UI 문구와 계산 엔진 내부 기준의 의미가 달라질 경우 별도 변환 계층을 둔다.

## 5. 키보드 및 마우스 조작

### 5.1 대상 이동

좌우 방향키는 다음 네 입력 그룹 사이를 이동한다.

```text
날짜 ↔ 시간 ↔ 도시 ↔ 성별
```

현재 선택 그룹은 시각적으로 강조한다. 첫 그룹에서 왼쪽, 마지막 그룹에서 오른쪽으로
이동하는 경계 동작은 순환하지 않고 해당 위치에 머문다.

### 5.2 값 변경

상하 방향키는 현재 선택 그룹의 값을 변경한다.

- 날짜: 달력상 유효한 연·월·일 조합을 유지한다.
- 시간: 유효한 시·분 범위에서 변경한다.
- 도시: 검색 결과 후보를 순환하거나 검색어를 수정한다.
- 성별: `남성`과 `여성` 후보를 순환한다.

날짜에서 존재하지 않는 조합을 만들지 않는다. 예를 들어 월 변경으로 2월 31일이
생기지 않도록 달력 규칙을 적용하고, 변경 후 유효성 검사를 다시 수행한다.

마우스는 일반 입력 컨트롤과 도시 드롭다운을 제공한다. 키보드와 마우스는 같은 상태
변경 경로를 사용해야 하며, 한쪽 입력만 별도의 계산 규칙을 갖지 않는다.

## 6. 계산 흐름

입력값이 변경되면 마지막 변경 후 250ms가 지나고 계산을 시작한다.

```text
입력 변경
    ↓
250ms debounce
    ↓
입력 유효성 검사
    ↓
사주팔자 계산 ───────┐
자미두수 계산 ────────┼─ 세 결과 검증
네이탈 차트 계산 ────┘
    ↓
통합 Seed 생성
    ↓
진행 버튼 활성화
```

한 차트의 계산이 실패하면 해당 차트만 재시도한다. 세 차트 중 하나라도 실패했거나
통합 Seed가 생성되지 않았다면 다음 단계로 진행할 수 없다.

UI는 입력 화면 오른쪽에 각 차트의 대표 요약과 계산 상태를 표시한다. 제출 이후에는
세 차트의 상세 결과를 결과 화면에서 표시한다.

## 7. 톱니바퀴 연출

### 7.1 구성

배경에 네 개의 톱니바퀴를 배치한다.

1. 사주 톱니바퀴
2. 자미두수 톱니바퀴
3. 네이탈 차트 톱니바퀴
4. 통합 Seed 톱니바퀴

세 차트 톱니바퀴는 각 계산 성공 시 한 번 회전한다. 세 결과가 통합되어 Seed가
생성되면 통합 Seed 톱니바퀴가 한 번 회전한다.

### 7.2 표현 규칙

- 입력값이 변경되었다는 이유만으로 성공 회전을 재생하지 않는다.
- 계산 시작, 계산 중, 성공, 실패 상태를 UI 텍스트와 상태 표시로 함께 전달한다.
- 회전 각도, 방향, 속도는 명식의 실제 값을 인코딩하지 않는다.
- 같은 계산 성공 이벤트는 중복 회전하지 않는다.
- 이전 계산 결과가 폐기된 뒤 새 계산이 성공한 경우에는 새 성공 이벤트로 한 번 회전한다.
- 사용자가 처음 생성 화면을 보는 동안 톱니바퀴 연출을 사용한다.
- 톱니바퀴 화면은 설정 또는 새 프로필 생성으로 다시 진입할 수 있지만, 기존 게임을
  수정하지 않고 별도 생성 세션을 만든다.
- Q9 결정에 따라 모션 감소 설정과 관계없이 회전한다. 회전이 어려운 사용자를 위해
  계산 상태 텍스트와 성공 아이콘을 함께 제공한다.

### 7.3 이벤트 예시

```text
chart-saju-ready
chart-ziwei-ready
chart-natal-ready
seed-ready
```

각 이벤트는 `sessionId`, 계산 버전, 상태, 결과 참조를 포함한다. 큰 차트 결과 전체를
이벤트 payload에 넣지 않고 저장소의 결과 참조를 전달한다.

## 8. 진행 가능 조건

다음 조건을 모두 만족해야 `게임 생성 시작` 버튼을 활성화한다.

- 생년월일이 유효하다.
- 출생 시간이 유효하다.
- 도시 후보가 확정되어 있다.
- 성별이 선택되어 있다.
- 사주팔자 대표 요약과 상세 계산이 성공했다.
- 자미두수 대표 요약과 상세 계산이 성공했다.
- 네이탈 차트 대표 요약과 상세 계산이 성공했다.
- 통합 Seed가 생성되었다.
- 현재 세션이 취소·중단·실패 상태가 아니다.

조건을 만족하지 못하면 버튼은 비활성화하고, 누락 또는 실패한 조건을 필드와 차트
상태에 표시한다.

## 10. Tauri 작업 큐와 AI 에이전트

Claude, Codex 등 로컬에서 사용자가 인증한 AI 에이전트는 에이전트별 어댑터를 통해
공통 작업 큐에 연결한다.

```text
Generation Queue
├── Agent Adapter: Claude
├── Agent Adapter: Codex
└── Future Agent Adapters
```

Tauri는 인증정보를 직접 수집하지 않는다. 각 에이전트의 기존 로컬 로그인·설정 상태를
사용하고, 작업 실행 결과와 상태만 수집한다.

작업 시작 시 세션 ID와 작업 ID를 생성하고, stdout/stderr 또는 어댑터가 제공하는 진행
상태를 로컬 작업 로그에 저장한다. 출생정보 원문은 로그에 기록하지 않는다.

## 11. 취소·뒤로가기·프로세스 종료

취소 또는 뒤로가기는 현재 생성 세션에만 적용한다.

1. 실행 중인 에이전트에 취소 신호를 보낸다.
2. 일정한 유예 시간 동안 정상 종료를 기다린다.
3. 종료되지 않은 프로세스와 하위 프로세스를 강제 종료한다.
4. 현재 세션의 중간 파일, 임시 티저, 작업 로그를 삭제한다.
5. 세션을 `cancelled` 상태로 저장한다.
6. 이전에 완성된 게임과 최종 티저는 유지한다.

Tauri 창을 닫을 때도 같은 취소 흐름을 적용한다. 앱을 다시 열었을 때 중단된 작업은
자동으로 재개하지 않고 `중단됨` 상태와 `재개` 버튼을 표시한다. 사용자가 재개를
선택하면 저장된 체크포인트에서 재개할 수 있는지 확인한 뒤 작업을 다시 큐에 넣는다.

## 12. 저장 및 보존

로컬 앱은 원문 입력, 계산 결과, 생성 산출물을 저장하고 재실행 시 복원한다.

- 현재 프로필과 차트 결과는 앱 전용 로컬 저장소에 보존한다.
- 생성 세션마다 별도의 `sessionId`를 사용한다.
- 기존에 완성된 게임은 읽기 전용 결과로 유지한다.
- 새 프로필은 기존 게임을 덮어쓰지 않는다.
- 생성 중간 파일과 로그는 30일 후 자동 삭제한다.
- 최종 게임과 최종 티저는 자동 삭제 대상이 아니다.
- 명시적인 전체 데이터 삭제 기능을 제공한다.

저장소 구현은 후속 기술 결정에서 정한다. 저장된 출생정보와 계산 결과에는 접근 권한을
최소화하고, 애플리케이션 로그나 원격 분석으로 전송하지 않는다.

## 13. 화면 상태

```text
ProfileDraft
    ↓ 입력 완료
CalculatingCharts
    ├── RetryableChartError → ChartRetry
    └── AllChartsReady → SeedReady
                              ↓
                         ReadyToStart
                              ↓
                         GenerationQueued
                              ↓
                         GenerationRunning
                    ┌─────────┴─────────┐
                Completed            CancelRequested
                                         ↓
                                     Cancelled
```

입력 화면에서는 차트 요약과 톱니바퀴 상태를 보여준다. `ReadyToStart`가 되면 생성 시작
버튼을 활성화한다. 생성 화면에서는 티저·오픈 베타·완성 게임의 상태가 업데이트될 때
앱 재시작 없이 해당 버튼을 활성화한다.

## 14. 완료 조건

- 최종 사용자는 Tauri 창에서만 입력 UI에 접근할 수 있다.
- 생년월일·시간·도시·성별이 모두 입력되지 않으면 진행할 수 없다.
- 출생 시간 미상은 제출할 수 없다.
- 도시를 문자로 검색하고 후보를 드롭다운으로 확정할 수 있다.
- 좌우 방향키로 날짜·시간·도시·성별 그룹을 이동할 수 있다.
- 상하 방향키로 현재 그룹의 값을 변경할 수 있다.
- 입력 변경 후 250ms debounce 뒤 세 차트 계산이 시작된다.
- 세 차트가 모두 성공하고 통합 Seed가 생성되어야 생성 버튼이 활성화된다.
- 차트별 성공 시 해당 톱니바퀴가 한 번 회전한다.
- 통합 Seed 생성 성공 시 통합 Seed 톱니바퀴가 한 번 회전한다.
- 계산 결과에 점술적 의미를 부여하지 않고 상태 피드백으로만 회전한다.
- 차트 하나가 실패하면 해당 차트만 재시도할 수 있다.
- 취소 시 현재 세션의 프로세스와 중간 산출물이 제거된다.
- 이전에 완성된 게임은 취소나 새 프로필 입력으로 삭제되지 않는다.
- 앱 재실행 시 저장된 프로필·결과·세션 상태를 복원한다.
- 중단된 작업은 자동 실행되지 않고 사용자의 재개 동작을 기다린다.
- 생성 완료 시 앱을 재시작하지 않고 티저·오픈 베타·게임 버튼이 활성화된다.
