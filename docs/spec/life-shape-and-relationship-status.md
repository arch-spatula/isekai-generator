# 일생의 모양과 관계 상태를 서사보다 먼저 정하기

> 상태: 제안 — 구현 전
> 작성일: 2026-11-21
> 해결 대상: [일생 해석의 관계 인물 '있음' 수렴 이슈](../incidents/2026-11-21-life-relationship-presence-convergence.md)
> 관련: [일생 서사용 2차 해석](life-narrative-interpretation.md), [세 체계 일생 통합](life-integration.md)

## 1. 문제와 목표

일생 해석은 명식과 관계없이 같은 뼈대로 수렴한다. 강한 짝, 아이나 제자, 스승이 늘 실제 인물로 나오고, 노년에
남긴 것을 물려주며 끝난다. 일생의 모양과 관계 구성이라는 큰 축을 서사를 쓰는 에이전트가 그때그때 정하고 있고,
그 결정이 모델에 익숙한 모양으로 돌아가기 때문이다.

이 두 축을 서사보다 먼저 정한다.

- **일생의 모양**: 생애 단계마다 운이 순풍인지 역풍인지를 1차 판단과 大運에서 스크립트로 계산한다.
- **관계 상태**: 짝·자식·제자가 있는지를 체계마다 1차 판단에서 근거와 함께 판정한다.

일생 해석과 통합은 이 값을 따르고 살만 붙인다.

성공 조건:

- 서로 다른 합성 명식을 넣으면 생애 단계별 운 기조의 순서가 서로 다르게 계산된다.
- 관계 상태가 `없음`인 인물은 일생 해석과 통합 문서의 생애 연표 `인연`에 나오지 않는다.
- 세 체계의 관계 상태가 갈리면 통합 문서는 정해진 규칙으로 본선을 고르고, 나머지 체계는 갈림길에 남긴다.
- 자녀와 제자는 서로 다른 인물 칸이다.

## 2. 범위

포함: 사주 판단 파생 사실, 세 체계의 1차 판단 문서와 검증기, 세 체계 일생 해석 형식과 검증기, 재료표 스크립트,
통합 검증기, 관련 스킬 지침, 합성 fixture.

제외:

- 고신·과숙·화개, 孤辰·寡宿 같은 고독 지표를 사실 층에 추가하는 일. 현재 육친·공망·궁별 보조성·하우스별
  룰러만으로 판정 근거는 충분하다. 사실 층의 비대칭 보강은 후속 범위다(7절).
- 부모·형제·벗·스승·경쟁자의 상태 판정. 첫 구현은 인연 수렴이 확인된 짝·자식·제자만 다룬다.
- GDD 단계와 [고정 제작 조건 조립](deterministic-design-document-assembly.md). 범위가 겹치지 않는다.
- 기존 로컬 산출물의 이동·수정·재생성.

## 3. 결정

| 항목 | 결정 |
| --- | --- |
| 운 기조 | 사주 大運마다 천간·지지 역할(용신·희신·기신·해당 없음)로 `순풍 · 역풍 · 혼조 · 평이` 중 하나를 스크립트가 정한다 |
| 곡선 유형 | 유형 목록을 두지 않는다. 단계별 기조의 순서 자체가 일생의 모양이다 |
| 관계 상태 값 | `있음 · 약함 · 없음` 세 가지. `약함`은 늦음·짧음·떨어져 삶·갈등이 큰 관계를 모두 포함하고 구체 모습은 서사가 정한다 |
| 관계 판정 위치 | 세 체계의 1차 판단 문서에 `짝 · 자식 · 제자` 세 섹션을 더한다 |
| 인물 칸 | `자녀·제자`를 `자녀`와 `제자`로 나눈다. 인물 사전은 8칸이 된다 |
| 통합 본선 | 세 체계 상태의 중앙값(`있음 > 약함 > 없음` 순서). 다른 값을 낸 체계는 갈림길에 남긴다 |

관계 상태를 세 값으로 줄인 이유: 통합 본선을 중앙값으로 정하려면 순서가 있어야 한다. `떨어져 삶`처럼 순서가 없는
값은 `약함`의 한 모습으로 서사가 쓴다.

판정을 1차 판단에 둔 이유: 1차 판단은 서사 전에 합의하는 기초 판단이고, 이미 `결론 · 근거 · 대안 · 뒤집힘` 형식과
검증기가 있다. 서사를 쓰는 단계가 관계를 함께 정하면 서사에 편한 쪽(있음)으로 기운다. 별도 문서를 두는 안은 8절에 남긴다.

## 4. 운 기조

### 4.1 大運별 기조

`saju-derived-facts.md`의 `大運별 용신·희신·기신` 각 줄에 기조를 붙인다.

| 천간·지지 역할 | 기조 |
| --- | --- |
| 둘 다 용신·희신 | 순풍 |
| 둘 다 기신 | 역풍 |
| 하나는 용신·희신, 하나는 기신 | 혼조 |
| 하나는 용신·희신, 하나는 해당 없음 | 순풍 |
| 하나는 기신, 하나는 해당 없음 | 역풍 |
| 둘 다 해당 없음 | 평이 |

가상 예제:

```text
大運별 용신·희신·기신 (…):
  1運 甲寅 5–14 (유년·소년): 甲 木 용신 · 寅 木 용신 · 순풍
  2運 乙卯 15–24 (소년·청년): 乙 木 용신 · 卯 木 용신 · 순풍
  3運 丙辰 25–34 (청년): 丙 火 해당 없음 · 辰 土 기신 · 역풍
```

### 4.2 생애 단계별 운 기조

같은 파일에 새 항목 `생애 단계별 운 기조`를 둔다. 단계마다 겹치는 大運의 기조를 나이 구간과 함께 순서대로 나열한다.
한 단계에 大運이 여럿 걸리면 하나로 합치지 않는다.

```text
생애 단계별 운 기조 (단계 나이 구간 안에서 겹치는 大運의 기조, 첫 大運 이전 제외):
  유년 0–12: 순풍 5–12
  소년 13–19: 순풍 13–14 → 순풍 15–19
  청년 20–34: 순풍 20–24 → 역풍 25–34
```

- 단계 경계는 `scripts/life-stages.ts`를 쓴다. 나이는 기존과 같은 출생 연도 차다.
- 첫 大運 이전 구간은 기존 판단 파생 사실과 같이 대상에서 뺀다. 유년이 모두 첫 大運 이전이면 `유년 0–12: 해당 大運 없음`으로 쓴다.
- 자미두수 大限은 강점·과제 궁이 걸린 구간만 지금처럼 파생 사실로 둔다. 운 기조는 사주 하나로 계산한다.

### 4.3 일생 해석과 통합이 따르는 규칙

- 사주·자미두수 일생 해석의 생애 연표 `근거`는 그 단계의 운 기조를 `[derived:생애 단계별 운 기조]`로 인용한다.
  자미두수는 사주 파생 사실을 읽지 않으므로 이 규칙은 사주에만 적용한다.
- 역풍뿐인 단계에 순탄한 결말을 쓰지 않는다. 노년이 역풍이나 혼조로 끝나면 회복이나 계승으로 닫지 않아도 된다.
- 이 의미 준수는 검증기로 판정하지 않는다. 인용의 존재만 검사한다.

## 5. 관계 상태

### 5.1 1차 판단 섹션

세 체계의 1차 판단 문서 끝에 `## 짝`, `## 자식`, `## 제자`를 이 순서로 더한다. 형식은 기존 섹션과 같다.

```markdown
## 짝
결론: <있음 | 약함 | 없음>
근거: <인용 1개 이상>
대안: <결론과 다른 허용값> — <설명, 인용 1개 이상>
뒤집힘: <무엇이 달라지면 결론이 대안으로 바뀌는지>
```

체계별 판정 신호(스킬 지침에 둔다. 신호의 가중은 에이전트가 판단하고 근거로 밝힌다):

| 관계 | 사주 | 자미두수 | 네이탈 |
| --- | --- | --- | --- |
| 짝 | `육친`의 배우자 별 유무, 배우자 자리 日支의 십신과 沖·刑, 해당 별 자리의 공망 | 夫妻궁 주성 유무(空宮), 煞星 수, 生年四化 | 7H 커스프·룰러 위치·품위, 7H 안 행성 |
| 자식 | `육친`의 자녀 별 유무, 그 자리의 공망·沖 | 子女궁 주성 유무, 煞星 수, 生年四化 | 5H 커스프·룰러 위치·품위, 5H 안 행성 |
| 제자 | 식상(전하고 가르치는 기운)의 유무와 상태 | 子女궁과 交友궁 | 9H·5H의 룰러와 행성 |

- 사실은 기존 사실·차트 파일에 있는 것만 인용한다. 새 사실을 만들지 않는다.
- `없음`은 여러 신호가 함께 부재를 가리킬 때 쓴다. 신호 하나만 있으면 `약함`이 기본이다. 전통 해석의 단정적인
  '무자'·'고독' 판정을 그대로 옮기지 않는다.
- 제자는 전통 체계에 직접 대응하는 별이 없다. 위 신호는 이 명세가 정한 기본값이고 학파 기준이 아니다(8절).

### 5.2 일생 해석

- 인물 사전은 `부모 · 형제·또래 · 연인·배우자 · 자녀 · 제자 · 벗·동료 · 스승·후원자 · 경쟁자·적대자` 8칸이다.
- `연인·배우자`, `자녀`, `제자` 항목에 `상태` 필드를 더하고, 값은 같은 체계 1차 판단의 `짝`, `자식`, `제자` 결론과 같아야 한다.
- 상태가 `없음`이면 항목은 쓰되 대체 인물을 만들지 않는다. `성향`·`주인공과의 관계`·`관계의 변화`에는 그 부재가 삶에
  무엇을 남기는지 쓴다.
- 상태가 `없음`인 인물은 생애 연표 `인연`에 쓰지 않는다.

### 5.3 재료표와 통합

- `assemble-life-material.ts`는 세 인물 칸마다 세 체계 상태와 중앙값을 재료표에 쓴다.

```text
### 자녀
상태 [saju]: 없음
상태 [ziwei]: 있음
상태 [natal]: 약함
상태 본선: 약함
```

- 통합 문서의 해당 인물 항목 `상태`는 `상태 본선`과 같아야 한다.
- 본선과 다른 상태를 낸 체계가 있으면, 그 체계의 같은 인물 항목을 `다른 길`에서 인용하는 갈림길이 하나 이상 있어야 한다.
- `없음` 인물에 대한 `인연` 규칙은 통합 문서에도 적용한다.

## 6. 형식 변경과 기존 지침 정리

| 대상 | 변경 |
| --- | --- |
| 생애 연표 `시련`·`얻는 것`·`잃는 것` | 값으로 `없음`을 허용한다. 모든 단계에 손실과 수확을 만들어 넣지 않게 한다 |
| 네 일생 스킬의 예시 문구 | "집을 떠남, 스승을 만남, 첫 상실, 동료와의 결별, 책임을 떠안음" 같은 사건 목록 예시를 빼고, 단어 변환 예시(현대 제도 명사 → 보편 명사)만 남긴다 |
| 일생 스킬의 부재 지시 | "부재를 서사 정보로 다룬다"를 "관계 상태를 따르고, `없음`이면 대체 인물을 만들지 않는다"로 바꾼다 |
| 통합 스킬의 "겹치는 재료가 기둥" | 관계 상태와 운 기조를 뒤집지 않는 범위로 한정한다 |

기존 폴더 호환: 새 섹션이 없는 1차 판단, `생애 단계별 운 기조`가 없는 파생 사실, `자녀·제자` 칸을 쓴 일생 해석은 새 검증기를
통과하지 못한다. 스킬은 무엇이 오래되었는지 알리고 멈춘다. 옛 형식을 자동으로 고치거나 재해석하지 않는다.

## 7. 후속 범위

- 고독 지표(고신·과숙·화개, 孤辰·寡宿)를 사실 층에 추가. orrery에 없어 직접 계산해야 한다. 인연이 많아지는 쪽 지표
  (도화살·홍염살)만 있는 비대칭을 맞춘다.
- 부모·형제 등 나머지 인물의 상태 판정.
- 자미두수 大限 전체의 기조 계산.

## 8. 열린 질문

구현 전에 정한다. 괄호 안이 이 초안의 기본값이다.

1. 관계 판정 위치: 1차 판단에 섹션 추가(기본값) / 체계별 별도 `relations` 문서. 별도 문서는 기존 판단 검증기를 바꾸지
   않지만 체계마다 생성 호출이 하나씩 늘어난다.
2. 제자 판정 신호: 5.1 표(기본값) / 제자는 체계 판정 없이 재능 섹션에서 전수가 나올 때만 등장.
3. 관계 상태 값: `있음 · 약함 · 없음`(기본값) / 순서 없는 값을 더하고 통합 본선은 다수결.
4. 해당 없음 오행의 처리: 4.1 표처럼 중립(기본값) / 조후 판단을 반영해 가중.

## 9. 구현 순서와 검증

1. **운 기조 계산**
   - `derive-judgment-facts.ts`의 사주 경로에 大運별 기조와 `생애 단계별 운 기조`를 더한다.
   - 검증: 합성 차트·판단 fixture로 4.1 표의 여섯 경우와 단계 경계, 첫 大運 이전 제외를 확인한다. 기대값은 표에서 직접
     쓰고 구현 출력에서 복사하지 않는다.
   - 검증: 서로 다른 합성 출생 입력 여러 개에서 단계별 기조 순서가 모두 같지 않음을 확인한다. 이것은 계산이 명식에 반응한다는
     확인이고 서사 다양성의 증거가 아니다.
2. **1차 판단 섹션**
   - 세 판단 검증기에 `짝 · 자식 · 제자` 섹션과 허용값을 더하고 세 판단 스킬 지침을 갱신한다.
   - 검증: 허용값 밖의 결론, 대안이 결론과 같은 값, 섹션 누락·순서 오류를 거부한다.
3. **일생 해석 형식**
   - 인물 8칸, `상태` 필드, 상태 일치, `없음` 인물의 `인연` 금지, `시련`·`얻는 것`·`잃는 것`의 `없음` 허용,
     사주의 운 기조 인용을 검증기와 세 스킬에 반영한다.
   - 검증: 상태 불일치, `없음` 인물을 `인연`에 쓴 문서, 옛 `자녀·제자` 칸 문서를 각각 의도한 진단으로 거부한다.
     `없음` 상태로 짧게 쓴 정상 항목은 통과한다.
4. **재료표와 통합**
   - 재료표에 상태와 중앙값을, 통합 검증기에 본선 일치와 갈림길 인용 규칙을 더한다.
   - 검증: 세 상태가 모두 같은 경우·둘이 같은 경우·모두 다른 경우의 중앙값, 갈림길 누락 거부, `없음` 본선 인물의 `인연` 거부.
5. **실제 생성 관찰(선택)**
   - 필수 검증이 아니다. 같은 명식과 다른 명식으로 생성해 관계 구성과 결말이 명식에 따라 갈리는지 로컬에서 관찰한다.
     결과는 로컬 run에 두고 이 문서의 완료 조건으로 삼지 않는다.

모든 필수 검증은 커밋된 합성 fixture로 하고 모델 호출을 넣지 않는다. [테스트 작성 가이드](test-writing-guide.md)를 따른다.

```sh
bun run test
bun run check:docs
git diff --check
```

구조 검사 통과는 형식과 값의 일치만 확인한다. 서사가 운 기조와 관계 상태를 의미상 따르는지는 검증기로 판정하지 않는다.
