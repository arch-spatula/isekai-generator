# 사주 1차 판단 문서와 검증기

> 상태: 설계 중 — 구현 전
> 작성일: 2026-11-19

## 1. 목표

사주 전문 해석 에이전트가 상세 해석을 쓰기 전에 모두 따라야 하는 기초 판단을 한 문서로 고정한다.
대상은 일간 강약, 격국, 조후, 용신, 희신, 기신이다. 판단은 에이전트가 하고, 문서의 구조와 근거 추적은
결정론적 검증기가 확인한다.

- 입력: 같은 차트 디렉터리의 `saju-chart.md`, `saju-facts.md`만 읽는다. 자미두수·네이탈 파일은 읽지 않는다.
- 출력: 같은 디렉터리의 `saju-judgment.md`. 이미 있으면 덮어쓰지 않는다.
- 용신 판단 기준의 우선순위(억부·조후 등)는 이 문서에서 정하지 않는다. 판단마다 사용한 기준을 기록하게 해서
  나중에 우선순위를 정해도 형식이 바뀌지 않게 한다.

## 2. 문서 형식 (결정)

고정 제목과 `키: 값` 줄로 된 Markdown을 쓴다. 해석 에이전트와 사람이 그대로 읽을 수 있고 검증기가 엄격하게
파싱할 수 있기 때문이다. JSON 블록은 쓰지 않는다.

가상 예제:

```markdown
# 四柱 1차 판단

원국: 己亥 丙寅 癸未 乙亥

## 일간 강약
결론: 신약
근거: [facts:득령] [facts:득세 근거] [facts:통근] [chart:八字關係]
대안: 중화 — [facts:득지] [chart:八字關係] …
뒤집힘: 寅亥合을 化로 보면 인성이 늘어 중화

## 격국
…

## 용신
결론: 木
기준: 억부
근거: …
대안: …
뒤집힘: …
```

- 섹션은 일간 강약, 격국, 조후, 용신, 희신, 기신의 6개이고 이 순서를 따른다.
- `원국` 줄은 `saju-chart.md`의 시·일·월·년 간지와 같아야 한다.
- `기준`은 용신 섹션에만 있고 억부·조후·통관·병약·전왕 중 하나다.
- 근거 인용: `[facts:<항목 이름>]`은 `saju-facts.md` 항목, `[chart:<이름>]`은 `saju-chart.md`의 절 제목이나 위치(`月支` 등)다.
- 모든 섹션에 `대안`과 `뒤집힘`을 항상 쓴다. `대안`은 `<결론과 다른 허용값> — <설명>` 형태이고 설명에 근거 인용이
  1개 이상 있어야 한다. `뒤집힘`은 어떤 사실이나 해석이 달라지면 결론이 대안으로 바뀌는지 적는다.
- 자기 보고 확신도 필드는 두지 않는다 (§5).

| 섹션 | 결론 허용값 |
| --- | --- |
| 일간 강약 | 신강 · 신약 · 중화 |
| 격국 | 자유 텍스트 (§4.1) |
| 조후 | 한습 · 난조 · 불필요 |
| 용신 · 희신 · 기신 | 木 · 火 · 土 · 金 · 水 |

## 3. 검증기 범위

`scripts/check-saju-judgment.ts <차트 디렉터리>`가 위반을 한 줄씩 출력하고 위반이 있으면 exit 1로 끝난다.

| 검사 | 막는 실수 |
| --- | --- |
| 6개 섹션이 순서대로 있고 섹션마다 필수 필드가 한 번씩 있다 | 판단 누락, 형식 이탈 |
| 결론과 `기준`이 허용값이다 | "木 또는 火" 같은 얼버무림 |
| `원국`이 `saju-chart.md`와 일치한다 | 다른 디렉터리·다른 명식 참조 |
| 근거가 1개 이상이고 인용한 항목이 실제 파일에 있다 | 꾸며낸 근거 |
| `대안` 값이 허용값이면서 결론과 다르고, 대안 설명의 인용도 실제 항목이다 | 반대 검토 생략, 대안 근거 날조 |
| `뒤집힘`이 비어 있지 않다 | 결론 조건을 따지지 않은 단정 |
| 용신·희신·기신이 서로 다르다 | 자기모순 |

판단 내용의 옳고 그름과 글 길이는 검사하지 않는다. 테스트는 커밋된 합성 fixture 디렉터리와 그 변형으로 한다.

## 4. 보류한 결정과 재검토 조건

아래 항목은 지금은 느슨하게 두고, 운영에서 관찰한 결과로 엄격하게 바꿀지 정한다. 판단 기준은
최종 GDD 품질, 그리고 생성 중 불필요한 재시도·토큰 낭비다. 재검토할 때는 관찰한 사례를 개인정보를 뺀
최소 형태로 이 절에 남긴다.

### 4.1 격국 결론: 자유 텍스트

검증기는 격국 결론이 비어 있지 않은지만 본다. 정해진 격 이름 목록을 강제하지 않는다.

엄격하게 바꿀 신호:

- 같은 구조를 다른 이름(예: 월겁격·양인격·건록격 혼용)으로 적어 후속 해석 문서끼리 어긋난다.
- 격국 이름이 모호해 상세 해석 단계에서 다시 판단하거나 통합 단계에서 충돌을 고치느라 재시도가 생긴다.

자유롭게 유지할 신호:

- 목록을 강제했을 때 목록 밖 격(특수격·외격)을 억지로 끼워 맞추거나 이름 불일치로 검증 실패·재시도가 반복된다.

### 4.2 희신·기신과 용신의 관계: 검증기에서 강제하지 않음

"희신은 용신을 생하고 기신은 용신을 극한다" 같은 관계 규칙은 학파마다 달라 검증기가 강제하지 않는다.
서로 다르기만 하면 통과한다.

엄격하게 또는 결정론적으로 바꿀 신호:

- 희신·기신 판단이 실행마다 흔들려 후속 해석의 길흉 방향이 서로 모순된다.
- 관계가 맞지 않는 조합 때문에 상세 해석·통합 단계에서 재시도가 생긴다.

이런 신호가 확인되면 관계 규칙을 검증기 검사로 넣거나, 용신에서 희신·기신을 규칙으로 계산하는 스크립트로 바꾼다.

## 5. 확신도 대신 대안 근거 (결정)

에이전트가 스스로 적는 확신도 라벨은 쓰는 데 비용이 없어 책임 회피용 "낮음" 남발을 검증기로 막을 수 없다.
그래서 라벨을 두지 않고, 모든 판단에 대안과 대안 근거, 뒤집힐 조건을 쓰게 한다. 판단의 애매함은 라벨이 아니라
결론 근거와 대안 근거의 균형으로 드러나고, 후속 해석 에이전트는 양쪽 근거를 직접 비교한다.
