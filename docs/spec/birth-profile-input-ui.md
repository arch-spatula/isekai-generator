# 출생 프로필 입력 UI 명세

> 상태: 초안
> 작성일: 2026-09-23
> 범위: 로컬 웹 UI에서 게임 생성용 출생 정보를 입력하고 확인하는 단계

## 1. 목적

사용자가 생년월일, 태어난 시간, 태어난 도시를 로컬 웹 화면에 입력할 수 있게 한다.
확정된 입력은 이후 사주팔자, 자미두수, 네이탈 차트 계산과 게임 시드 생성 단계에
전달한다.

초기 버전은 공개 웹 서비스가 아니라 사용자의 컴퓨터에서 실행하는 로컬 애플리케이션이다.
프로그램을 실행한 뒤 브라우저에서 `http://localhost:<port>`에 접속해 입력한다.

## 2. 참고 자료

- [혼천의 라이브 UI](https://sky.told.me/): 출생 정보 입력 흐름, 시간 미상 처리,
  모바일 대응 및 세 가지 점술 결과를 한 화면에서 다루는 방식을 참고한다.
- [rath/orrery](https://github.com/rath/orrery): 브라우저에서 백엔드 없이 사주팔자,
  자미두수, 네이탈 차트를 계산하는 구조와 출생 입력 모델, 도시 검색 방식을 참고한다.

Orrery의 문서에서 확인되는 관련 기능은 다음과 같다.

- 출생 연·월·일·시·분 입력
- 출생 시간 미상 모드. 단, 이 프로젝트에서는 지원하지 않는다.
- 출생지의 위도, 경도 및 IANA 타임존 사용
- 한국 및 세계 주요 도시 검색과 한글 초성 검색
- 모바일 반응형 UI
- 사주팔자, 자미두수, 네이탈 차트의 클라이언트 측 계산

Orrery는 AGPL-3.0 라이선스다. 이 문서는 아이디어와 사용자 경험을 참고한다는 기록이며,
소스 코드나 `@orrery/core` 패키지를 사용하기로 결정한 것은 아니다. 코드 또는 패키지의
직접 사용 여부와 이 프로젝트의 라이선스 영향은 별도 ADR과 법률 검토를 거쳐 결정한다.

## 3. 범위

### 포함

- localhost에서 접근할 수 있는 출생 프로필 입력 화면
- 생년월일 입력
- 필수 출생 시간 입력
- 출생 도시 검색과 선택
- 계산에 필요한 타임존, 위도, 경도의 자동 확정
- 입력 검증, 최종 확인 및 다음 단계로 전달
- 출생 정보의 로컬 처리 원칙 안내

### 제외

- 사주팔자, 자미두수, 네이탈 차트 계산 로직 자체
- 게임 시드 변환 규칙
- 계정, 로그인, 클라우드 동기화
- 원격 서버로의 출생 정보 전송
- 게임 생성 진행 화면과 티저 화면

## 4. 사용자 흐름

1. 사용자가 로컬 프로그램을 실행한다.
2. 프로그램이 loopback 주소에 웹 서버를 열고 접속 URL을 안내한다.
3. 사용자가 브라우저에서 출생 프로필 입력 화면을 연다.
4. 생년월일과 출생 시간을 입력한다.
5. 출생 도시를 검색하고 후보 중 정확한 도시를 선택한다.
6. 화면에서 날짜, 시간, 도시 및 타임존을 검토한다.
7. 사용자가 `이 정보로 시작`을 누른다.
8. 유효한 정규화 입력이 다음 계산 또는 게임 생성 준비 단계로 전달된다.

## 5. 화면 구성

```text
┌─────────────────────────────────────────────┐
│ 당신만의 이세계 생성을 시작합니다          │
│ 입력 정보는 이 컴퓨터에서 처리됩니다.       │
├─────────────────────────────────────────────┤
│ 생년월일                                    │
│ [연도] [월] [일]                            │
│                                             │
│ 태어난 시간                                 │
│ [시] [분]                                   │
│                                             │
│ 태어난 도시                                 │
│ [도시 이름 검색________________________]    │
│ ┌ 검색 결과: 도시 · 지역 · 국가 ─────────┐ │
│ └─────────────────────────────────────────┘ │
│ 선택: 서울, 대한민국                        │
│ 시간대: Asia/Seoul                          │
│                                             │
│ [입력 내용 확인]                            │
└─────────────────────────────────────────────┘
```

첫 화면에는 점술 결과나 게임 설정을 함께 표시하지 않는다. 사용자가 민감한 출생 정보를
정확히 입력하고 검토하는 한 가지 작업에 집중하게 한다.

## 6. 입력 필드

| 필드 | 필수 | UI | 규칙 |
| --- | --- | --- | --- |
| 생년월일 | 예 | 날짜 입력 또는 연·월·일 선택 | 실제 달력에 존재하며 미래가 아닌 날짜 |
| 출생 시간 | 예 | 시·분 입력 | 필수, 24시간 형식 |
| 출생 도시 | 예 | 검색형 콤보박스 | 자유 문자열 제출이 아니라 검색 결과 중 하나를 선택 |
| 국가/행정구역 | 자동 | 도시 후보의 보조 텍스트 | 동명 도시 구분에 사용 |
| 타임존 | 자동 | 읽기 전용 | 선택한 도시의 IANA 타임존 ID |
| 위도/경도 | 자동 | 기본 화면에서는 숨김 | 네이탈 차트 계산용 좌표 |
| 성별/계산 기준 | 추후 결정 | 아직 표시하지 않음 | 자미두수 등 계산 엔진 요구사항을 검토한 뒤 별도 결정 |

성별은 Orrery의 일부 계산 API 입력에 포함되지만, 사용자가 반드시 제공해야 하는지와
어떤 표현을 사용할지는 아직 제품 결정이 아니다. 계산상 필요한 개념과 사용자의 성별
정체성을 혼동하지 않도록 별도 ADR 또는 도메인 명세에서 다룬다.

## 7. 도시 검색

- 두 글자 이상 입력하면 검색 후보를 표시한다. 한국어 초성 검색은 선택 기능으로 둔다.
- 각 후보는 `도시 · 행정구역 · 국가` 순으로 표시해 동명 도시를 구분한다.
- 도시를 선택하면 내부적으로 `cityId`, 표시 이름, 국가 코드, 위도, 경도, IANA 타임존을
  함께 확정한다.
- 브라우저나 운영체제의 현재 위치를 출생 도시로 자동 간주하지 않는다.
- 원하는 도시가 없으면 초기 버전에서는 가장 가까운 지원 도시를 고르게 안내한다.
  좌표 직접 입력은 고급 기능으로 남기며 MVP 범위에서는 제외한다.
- 도시 데이터가 로컬 번들에 포함된 경우 검색 과정에서 외부 지오코딩 API를 호출하지 않는다.

## 8. 시간 처리

- 화면에는 출생지의 현지 시각을 입력한다.
- 저장 및 계산 단계에서는 선택한 도시의 IANA 타임존을 함께 전달한다.
- UTC 오프셋을 사용자가 직접 입력하게 하지 않는다.
- 일광절약시간 등 역사적 오프셋은 날짜, 현지 시각, IANA 타임존의 조합으로 계산한다.
- 출생 시간 미상 모드는 지원하지 않으며 임의의 기본 시간도 대입하지 않는다.
- 사용자가 정확한 시간을 모르면 입력을 완료할 수 없다고 안내한다.

## 9. 정규화 데이터 계약

UI가 다음 단계에 전달하는 값의 개념적 형식은 아래와 같다. 이는 저장 형식이나 공개 API를
확정하는 명세가 아니라 UI와 계산 단계 사이의 최소 계약이다.

```json
{
  "birthDate": "1993-03-12",
  "birthTime": "09:45",
  "birthPlace": {
    "cityId": "kr-seoul",
    "displayName": "서울, 대한민국",
    "countryCode": "KR",
    "latitude": 37.5665,
    "longitude": 126.978,
    "timezone": "Asia/Seoul"
  }
}
```

`birthTime`은 항상 `HH:mm` 형식의 유효한 값이어야 하며 `null`을 허용하지 않는다.

## 10. 검증과 오류 표시

- 오류는 제출 후 한꺼번에 보여주지 않고 해당 필드에서 이탈하거나 제출할 때 인라인으로
  표시한다.
- 오류 문구는 원인과 해결 방법을 함께 설명한다.
- 첫 오류 필드로 포커스를 이동하고, 색상 외에도 텍스트와 아이콘으로 상태를 표시한다.
- 검색어만 입력하고 도시 후보를 선택하지 않았다면 유효한 출생 도시로 인정하지 않는다.
- 제출 버튼을 연속해서 눌러도 다음 단계가 중복 실행되지 않아야 한다.

예시 오류:

- `존재하지 않는 날짜입니다.`
- `태어난 시간을 입력해 주세요.`
- `검색 결과에서 태어난 도시를 선택해 주세요.`

## 11. 개인정보와 로컬 실행

- 개발 서버는 기본적으로 `127.0.0.1` 또는 동등한 loopback 인터페이스에만 바인딩한다.
- 명시적인 사용자 설정 없이는 LAN의 다른 기기에서 접근할 수 없어야 한다.
- 입력 페이지와 도시 검색은 기본적으로 인터넷 연결 없이 동작해야 한다.
- 이 단계에서는 출생 정보를 원격 분석, 로그, 오류 추적 서비스로 보내지 않는다.
- 로그에는 생년월일, 출생 시간, 도시, 좌표를 원문으로 기록하지 않는다.
- 새로고침 또는 재실행 시 값을 보존할지는 별도 개인정보·저장 정책에서 결정한다.
- 화면에 `입력 정보는 이 컴퓨터에서 처리되며 자동으로 외부에 전송되지 않습니다`라는
  안내를 표시한다.

향후 원격 AI API에 파생 데이터 또는 출생 정보를 전달하게 된다면, 전송 직전에 범위와
목적을 별도로 고지하고 명시적인 동의를 받아야 한다. localhost에서 UI를 제공한다는 사실만으로
모든 처리가 로컬이라는 의미는 아니므로 실제 데이터 경로와 안내 문구가 일치해야 한다.

## 12. 접근성 및 반응형 요구사항

- 모든 입력에는 화면에 보이는 레이블을 제공한다.
- 키보드만으로 날짜, 시간, 도시 후보 선택과 제출이 가능해야 한다.
- 도시 검색 결과에는 적절한 콤보박스 상태와 선택 상태를 보조 기술에 전달한다.
- 오류와 개인정보 안내는 스크린 리더가 인식할 수 있어야 한다.
- 최소 모바일 화면 폭에서도 가로 스크롤 없이 입력할 수 있어야 한다.
- 날짜 형식은 화면 언어에 맞게 표시하되 내부 값은 `YYYY-MM-DD`로 정규화한다.

## 13. 완료 조건

- 사용자는 localhost 화면에서 유효한 생년월일, 출생 시간, 출생 도시를 입력할 수 있다.
- 출생 시간이 비어 있으면 제출할 수 없다.
- 동명 도시를 국가 및 행정구역 정보로 구분할 수 있다.
- 선택된 도시에서 위도, 경도, IANA 타임존이 함께 결정된다.
- 잘못된 날짜, 불완전한 시간, 선택되지 않은 도시는 다음 단계로 전달되지 않는다.
- 유효한 입력은 정규화 데이터 계약을 만족해 다음 단계로 한 번만 전달된다.
- 기본 설정에서 UI와 도시 검색은 외부 네트워크 없이 작동한다.
- 서버는 기본 설정에서 loopback 인터페이스 외부에 노출되지 않는다.
- 출생 정보가 애플리케이션 로그나 원격 서비스로 전송되지 않는다.

## 14. 미결정 사항

- 양력만 받을지, 음력 입력과 윤달 선택도 첫 버전에 포함할지
- 계산에 필요한 성별 또는 음양 순행 기준을 어떤 용어와 UI로 받을지
- Orrery 코드를 직접 사용할지, 계산 엔진을 별도로 구현할지
- 도시 데이터셋의 출처, 라이선스, 갱신 방식
- 고급 사용자를 위한 좌표 및 타임존 직접 수정 기능을 제공할지
- 입력값을 다음 실행까지 로컬에 보존할지
- localhost 서버의 기본 포트와 포트 충돌 시 선택 규칙
