# 테스트 작성 가이드

## 목적과 적용 범위

일반 개발과 스킬·생성 결과 검증기의 테스트에 공통으로 적용한다. 이 가이드는 다중
에이전트 실행을 요구하지 않는다. 사용자가 요구한 동작과 실제 계약을 검증하며, 테스트를
쉽게 작성하기 위해 별도의 제품 정책이나 품질 기준을 만들지 않는다.

## 요구사항을 직접 검증하기

각 주요 테스트의 입력·기대 결과·거부 이유를 요구사항으로 설명할 수 있어야 한다.
기대값을 구현의 출력이나 상수에서 그대로 복사하지 않는다. 구현과 테스트가 같은 잘못된
가정을 공유해도 통과하는지 확인한다.

의미의 충실도·구체성·깊이·재미를 글자 수, 문장 수, 특정 단어의 출현 같은 간접지표로
판정하지 않는다. 길면 충실하고 짧으면 부실하다고 가정하지 않는다. 예를 들어 강점과
취약점의 구분을 요구한다면 각 내용의 존재를 검사할 수 있지만, 최소 글자 수만으로
양면성이 잘 설명됐다고 판정할 수는 없다. 내용의 타당성은 별도 의미 검토로 다룬다.

빈 값, 없는 근거 ID, 잘못된 참조, 누락된 필수 항목처럼 직접 확인할 수 있는 계약 위반은
자동 검사한다. 자동 검사가 확인한 구조와 별도 검토가 확인한 의미를 결과 보고에서 구분한다.

## 길이 검사가 적절한 경우

길이 자체가 검증할 계약이거나 실제 제약과 직접 연결될 때는 사용할 수 있다.
사용 여부는 아래와 같이 판단한다.

| 검증 대상 | 길이 검사 사용 | 이유 |
| --- | --- | --- |
| 프로토콜의 고정 바이트 길이 | 적절 | 길이 자체가 데이터 형식의 일부다. |
| 저장소 필드·외부 API의 최대 크기 | 적절 | 초과 시 저장·전송이 불가능하다는 직접 제약이 있다. |
| 사용자가 요청한 제목 글자 수·출력 분량 | 적절 | 명시된 분량 계약을 확인한다. 의미 품질까지 증명하지는 않는다. |
| 필수 텍스트의 빈 값·공백만 있는 값 | 적절 | 내용의 존재 여부를 확인한다. |
| 해석의 깊이·설득력·구체성 | 부적절 | 길이가 의미 품질을 보장하지 않는다. |
| 같은 뜻의 짧은 표현을 부실하다고 거부 | 부적절 | 정상적인 간결한 설명을 불필요하게 탈락시킨다. |

길이 조건을 사용할 때는 요구사항이나 실제 제약의 근거, 최소·최대 경계, 측정 단위를
설명한다. 바이트·문자·사용자가 보는 글자 수는 다를 수 있으므로 계약에 맞게 측정한다.
단순히 기존 코드나 문서에 숫자가 있다는 이유만으로 그 기준의 적절성이 증명되지는 않는다.
기존 기준이 정상 입력을 거부하면 해당 요구사항과 기준을 함께 재검토한다.

## 반례와 실패 원인 확인

- 정상 사례와 함께 짧지만 완결된 표현 등 거부하면 안 되는 사례를 확인한다.
- 긴 반복문이나 무관한 내용으로 길이만 채워도 통과하는지 확인한다. 통과한다면 이를
  의미 품질을 검증하는 테스트라고 설명하지 않는다.
- 길이 계약이 있는 경우 경계 바로 아래·경계값·바로 위를 검사하고, 필요한 경우
  한글·이모지·공백 등 측정 단위가 달라지는 입력도 확인한다.
- 버그 회귀는 변경 전 실패·변경 후 통과를 확인한다. 관련 없는 오류로도 통과하는
  테스트가 되지 않도록 가능한 경우 진단 코드·대상 필드·위치를 확인한다.
- 필수 필드 누락과 짧은 정상 내용을 서로 다른 사례로 다룬다.

아래는 실제 개인 자료와 관계없는 합성 예시다.

| 입력 | 검토할 사항 |
| --- | --- |
| `강점: 약속을 지킴 / 취약점: 도움 요청이 늦음` | 짧다는 이유만으로 거부하지 않는다. 해석의 근거·조건은 별도로 검토한다. |
| `강점: / 취약점: 도움 요청이 늦음` | 필수 강점 내용이 비었으므로 거부한다. |
| 무의미한 글자를 길게 반복한 강점·취약점 | 길이 통과를 의미 품질의 증거로 삼지 않는다. |

## 테스트 이름과 검증 한계

테스트 이름은 실제 assertion이 확인하는 동작을 설명한다. 최소 길이만 검사하면서
“얕은 해석을 거부한다”거나 “충분히 깊은 설명을 보장한다”고 이름 붙이지 않는다.
분량 계약 검사라면 “요청한 최소 분량 미달을 거부한다”처럼 측정 대상을 밝힌다.

새 테스트와 수정한 테스트는 필요한 범위에서 실행한다. 구조 검사의 통과를 의미 품질의
보장으로 보고하거나 검증을 위해 실제 모델 생성 전체를 관성적으로 실행하지 않는다.
회귀 자료는 커밋된 합성 입력을 사용하며 [로컬 아티팩트와 영구 문서의 경계](local-artifact-document-boundary.md)를 따른다.
