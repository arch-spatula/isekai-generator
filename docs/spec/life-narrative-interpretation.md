# 일생 서사용 2차 해석

> 상태: 구현 — 사주·자미두수 사실 층·검증기 설정·`saju-life`·`ziwei-life` 스킬, 네이탈 검증기 설정과 `natal-life` 스킬
> 작성일: 2026-11-19

## 1. 목표

사람마다 이세계에서 한 번의 일생을 살아 보는 게임을 만들기 위해, 체계별 1차 판단 위에 일생 서사의 재료를
담는 2차 해석을 둔다. 기존 해석은 "어떤 사람인가"를 영역별로 정리했지만 생애 단계별 전환점, 가족과 인연의
인물상, 재능이 꽃피는 시기, 상처와 회복을 담지 않았다. 2차는 시간 축을 뼈대로 쓴다.

- 체계마다 하나씩 쓰고, 세 체계의 통합과 GDD 템플릿 변경은 이후 단계에서 다룬다.
- 입력: 같은 차트 디렉터리의 해당 체계 차트·사실 파일과 1차 판단 문서.

## 2. 결정

| 항목 | 결정 |
| --- | --- |
| 생애 단계 | 유년 0–12 · 소년 13–19 · 청년 20–34 · 장년 35–54 · 노년 55– 의 5단계 고정. 세 체계가 같은 칸을 쓴다 |
| 나이 기준 | 출생 연도 차(사주 大運 표시 나이와 같음). 자미두수 大限 세는나이는 1을 빼 대조한다 |
| 다루는 범위 | 노년을 끊지 않고 계산된 운의 끝까지 다룬다 |
| 네이탈 | 시기 계산(트랜짓·프로그레션)이 없으므로 인물 사전과 재능만 맡고 생애 연표는 쓰지 않는다 |
| 언어 | 보편적 생애 사건 언어로 쓴다. 현대 제도 명사(회사·대학·회계·계약·심사 등)와 게임 용어(무기·스킬·던전 등)는 쓰지 않는다 |
| 판단 파생 사실 | 1차 판단을 입력으로 받아 결정론적으로 계산되는 사실(大運별 용신·기신 오행 포함, 강점·과제 궁이 걸린 大限 등)은 스크립트가 만든다 |

언어 규칙은 현실 해석의 표면 명사가 게임 절차로 직역되는 문제를 줄이려는 것이다. 의미 준수는 검증기로 완전히
판정할 수 없어 운영 관찰로 확인한다.

## 3. 문서 형식

체계마다 같은 차트 디렉터리에 `saju-life.md`, `ziwei-life.md`, `natal-life.md`를 쓴다. 이미 있으면 덮어쓰지 않는다.
구조는 `## 섹션 > ### 항목 > 키: 값 필드`의 3단계이고, 항목 안에는 필드 줄만 쓴다.

가상 예제(사주):

```markdown
# 四柱 일생 해석

원국: 己亥 丙寅 癸未 乙亥

## 생애 연표
### 유년
운: 대운 이전 0–0, 1運 甲申 1–10, 2運 乙酉 11–20
주제: …
전환점: …
인연: 부모, 형제·또래
시련: …
얻는 것: …
잃는 것: …
성격 변화: …
근거: [derived:大運별 용신·희신·기신] [facts:육친] [judgment:용신]

## 인물 사전
### 부모
성향: …
주인공과의 관계: …
관계의 변화: 유년에는 … 청년에 …
근거: [facts:육친] …

## 재능과 생업
### 주 재능
…

## 상처와 회복
…
```

| 체계 | 제목 | 신원 줄 |
| --- | --- | --- |
| 사주 | `# 四柱 일생 해석` | `원국:` — 1차 판단과 같은 규칙 |
| 자미두수 | `# 紫微斗數 일생 해석` | `명반:` — 1차 판단과 같은 규칙 |
| 네이탈 | `# Natal 일생 해석` | `차트:` — 1차 판단과 같은 규칙 |

### 섹션과 항목

| 섹션 | 항목 | 필드 |
| --- | --- | --- |
| 배경 | 뿌리 · 자란 집 · 떠남의 조건, 이 순서로 모두 | `모습`, `준 것`, `막은 것`, `근거` |
| 생애 연표 (사주·자미두수만) | 유년 · 소년 · 청년 · 장년 · 노년, 이 순서로 모두 | `운`, `주제`, `전환점`, `인연`, `시련`, `얻는 것`, `잃는 것`, `성격 변화`, `근거` |
| 인물 사전 | 부모 · 형제·또래 · 연인·배우자 · 자녀 · 제자 · 벗·동료 · 스승·후원자 · 경쟁자·적대자, 이 순서로 모두 | `성향`, `주인공과의 관계`, `관계의 변화`, `함께 한 일`, `곁에 있던 시기`, `영향`, `근거`. 연인·배우자·자녀·제자는 `상태`도 쓴다([관계 상태와 무게](life-shape-and-relationship-status.md) 5.2·5.4) |
| 재능과 생업 | 주 재능 · 보조 재능 (필수), 그 뒤 추가 재능 항목 자유, `생업: <이름>` 항목 하나 이상 | 재능: `내용`, `다루는 것`, `꽃피는 시기`, `막히는 조건`, `근거` · 생업: `내용`, `시기`, `쓰인 재능`, `근거` |
| 상처와 회복 | 반복되는 실패 · 상실 · 회복, 이 순서로 모두 | `내용`, `발현 조건`, `근거` |

### 배경

배경은 주인공이 자란 환경이다(#97, [ADR](../ADR/2026-11-24-chart-background-interpretation.md)). 사람의 성정이 아니라 조건을 쓴다.
집안이 무엇으로 살림을 일으켰는지, 공동체에서 어떤 자리에 있었는지, 가족과 공동체가 무엇을 주고 무엇을 막았는지, 무엇이 집을 떠나게 하는지다.
[인물과 환경 해석 구분 ADR](../ADR/2026-11-10-person-environment-world-story.md)의 환경 해석을 차트 해석 층에서 맡는 자리다. 이전에는 배경 절이 없어
배경이 부모(사람의 성정)와 유년(본인의 성정)에 흩어졌고, 본인의 자리에서 읽은 성향이 유년 환경의 사건으로 쓰였다.

| 체계 | 뿌리 | 자란 집 | 떠남의 조건 | 배경의 근거로 쓰지 않는 본인 자리 |
| --- | --- | --- | --- | --- |
| 사주 | 年柱 (윗대·가문·출신 공동체) | 月柱 (부모 세대의 집과 성장 환경) | 年柱·月柱의 관계(`八字關係`), 유년·소년에 걸친 大運 | 日干·日柱, 일간 강약 |
| 자미두수 | 父母, 福德 | 田宅, 父母 | 遷移 | 命宮과 명궁 삼방사정, 명궁 역량, 격국 |
| 네이탈 | 4H(IC) | 4H, 10H(MC) | 9H, 3H, 4H 룰러의 위치 | ASC, 차트 룰러, 차트 룰러 상태 |

- 장소의 종류·이름·산업은 정하지 않는다. 그것은 정체성 단계가 이 배경에서 정한다. 기호의 뜻을 장소 명사로 직역하지 않는다.
- 신호 하나로 지원이 없었다고 쓰지 않는다. 결핍·단절은 인물 사전의 부재 규칙과 같다.
- 생애 연표의 유년·소년에 집과 공동체가 나오면 배경과 같은 환경으로 쓴다.
- 환경 해석은 창작의 재료이며 실제 출생 가정의 사실로 단정하지 않는다(인물과 환경 해석 구분 ADR 결정 4).

재능의 `다루는 것`은 그 재능이 다루는 대상·매체다(#70). 직업 이름은 쓰지 않지만 다루는 대상은 지우지 않는다. 태도(꾸준함·고집)와
삶의 조건("정해진 틀이 없음")은 재능이 아니다. 차트에서 재능의 영역은 사주 십신·오행, 자미두수 별, 네이탈 행성·사인에서 읽고, 柱의 자리·궁·하우스는
그 재능이 쓰이는 무대로 읽는다. 이전에는 직무 명사 금지("대장장이" 대신 "손으로 형태를 만들고 고치는 일에 오래 몰입한다")가 다루는 대상까지
흐려, 게임 단계가 태도 동사("꾸준히 쌓아")를 메커니즘으로 삼았다.

생업은 재능이 실제로 어떤 일이 되어 살림을 꾸렸는지다(#85, [ADR](../ADR/2026-11-24-isekai-identity-design.md) 1번). 직업 이름은 생업 항목에만 쓰고,
이세계에서도 성립하는 일의 이름으로 쓴다. 금지하는 것은 이세계에 없는 현대 제도나 기술에 기대는 이름이다. 시기마다 일이 바뀌면 여럿 쓴다.
`시기`는 사주·자미두수에서 생애 단계 이름을 포함하고, 네이탈은 조건으로 쓴다. `쓰인 재능`은 같은 섹션의 재능 항목 이름이다.
생업은 게임의 직업 클래스가 아니다. 생업을 전투 능력으로 직역하는 것은 게임 단계에서 막는다(번역 브리프의 능력 출처는 재능 항목만 된다).

- `운`은 사실 파일의 `생애 단계별 大運`(사주) 또는 `생애 단계별 大限`(자미두수)에서 해당 단계 줄의 콜론 뒤 내용과
  같아야 한다. 에이전트가 나이를 세다 틀리는 일을 막는다.
- `인연`은 인물 사전 항목 이름을 쉼표로 나열한다.
- 사주·자미두수의 `관계의 변화`와 `꽃피는 시기`는 생애 단계 이름을 하나 이상 포함한다. 네이탈은 생애 연표가
  없으므로 단계 대신 조건으로 쓴다.
- 차트에서 해당 육친·궁·하우스가 비어 있어도 인물 사전 항목은 쓴다. 부재도 서사 정보다.

### 인용

| 표기 | 대상 |
| --- | --- |
| `[facts:<항목>]` | 해당 체계 사실 파일의 항목 이름 |
| `[chart:<이름>]` | 1차 판단과 같은 절 제목·위치. 자미두수는 `流年`·`流月`만 금지하고 `大限`은 쓸 수 있다 |
| `[judgment:<섹션>]` | 해당 체계 1차 판단 문서의 섹션 이름 |
| `[derived:<항목>]` | 해당 체계 판단 파생 사실 파일의 항목 이름 (사주·자미두수) |

## 4. 사실 층

| 사실 | 파일 | 정의 |
| --- | --- | --- |
| `생애 단계별 大運` | `saju-facts.md` | 단계 나이 구간과 겹치는 大運. 첫 大運 전은 `대운 이전` |
| `육친` | `saju-facts.md` | 어머니 正印, 아버지 偏財, 형제 比肩·劫財, 배우자 남 正財 / 여 正官, 자녀 남 正官·偏官 / 여 食神·傷官. 천간과 지지 정기 십신 기준, 배우자 자리는 日支 |
| `생애 단계별 大限` | `ziwei-facts.md` | 세는나이 − 1로 대조해 겹치는 大限. 첫 大限 전은 `大限 이전` |
| `하우스별 룰러와 행성` | `natal-facts.md` | 12하우스의 커스프 사인, 전통 룰러와 그 위치, 하우스 안 10행성 |

육친은 학파 차이가 작은 기본 대응만 두고(偏印·偏官 등 세부 역할은 넣지 않는다), 하우스 룰러는 품위와 같은
전통 지배성만 쓴다. 생애 단계 정의는 `scripts/life-stages.ts`에 있다.

### 판단 파생 사실

1차 판단이 정해진 뒤 `bun scripts/derive-judgment-facts.ts <saju|ziwei> <차트 디렉터리>`가 만든다. 판단 문서가
해당 검증기를 통과하지 않으면 멈추고, 결과 파일이 이미 있으면 쓰지 않는다.

| 파일 | 내용 |
| --- | --- |
| `saju-derived-facts.md` | 大運마다 천간·지지 자체 오행이 1차 판단의 용신·희신·기신 중 무엇인지(해당 없음 포함)와 겹치는 생애 단계 |
| `ziwei-derived-facts.md` | 1차 판단의 강점 궁·과제 궁이 걸린 大限과 겹치는 생애 단계 |

네이탈은 1차 판단에서 파생되는 시기 사실이 없어 만들지 않는다. 첫 大運 이전(月柱 구간)은 대상에서 뺀다.

## 5. 검증기

`bun scripts/check-life-document.ts <saju|ziwei|natal> <차트 디렉터리>`. 위반을 한 줄씩 출력하고 위반이 있으면 exit 1이다.
1차 판단 검증기를 바꾸지 않도록, 인용 해석·항목 이름 추출 같은 공통 부분만 함께 쓰는 별도 파서를 둔다.

| 검사 | 막는 실수 |
| --- | --- |
| 제목·신원 줄, 섹션 순서, 필수 항목과 순서, 항목마다 필드가 한 번씩 있고 비어 있지 않음 | 누락, 형식 이탈 |
| `운`이 사실 파일의 대응 줄과 같고, 사실 파일에 그 단계 줄이 있음 | 나이 계산 실수, 생애 단계 사실이 없는 오래된 폴더 |
| `인연`의 이름이 인물 사전에 있음 | 등장인물 불일치 |
| 배경 항목의 `근거`에 위 표의 자리가 하나 이상 있고, 배경 절이 본인 자리를 인용하지 않음 | 배경 누락, 본인 성향을 환경으로 씀 |
| 사주·자미두수의 `관계의 변화`·`꽃피는 시기`·생업 `시기`에 생애 단계 이름이 있음 | 시간 축 없는 서술 |
| 생업 항목이 하나 이상 있고, `쓰인 재능`이 같은 섹션의 재능 항목이며, 생업 이름에 현대 제도·기술의 말이 없음 | 생업 누락, 이세계에 없는 일 |
| 1차 판단 섹션을 모두 한 번 이상 인용, 사주·자미두수는 판단 파생 사실도 인용 | 1차 판단 무시 |
| 모든 인용이 실재하고 금지 절이 아님 | 꾸며낸 근거, 조회 연도 의존 |

내용의 질, 1차 판단과의 의미상 모순, 글 길이는 검사하지 않는다. 테스트는 커밋된 합성 fixture(`scripts/fixtures/saju-life/`,
`scripts/fixtures/ziwei-life/`, `scripts/fixtures/natal-life/`)와 그 변형으로 한다(`bun test scripts/check-life-document.test.ts`).

## 6. 작성 스킬과 실행 흐름

체계마다 `saju-life`, `ziwei-life`, `natal-life` 스킬을 둔다. 각 스킬은 해당 체계의 차트·사실·1차 판단·판단 파생
사실만 읽는다.

```text
chart-report → <체계>-judgment → derive-judgment-facts <체계> (사주·자미두수) → <체계>-life
```

스킬은 앞 단계 산출물이 없으면 무엇이 없는지 알리고 멈추며, 앞 단계를 대신 실행하지 않는다. 1차 판단의 결론을
뒤집지 않고, 1차의 `대안`은 서사의 갈림길로 쓸 수 있다.

## 7. 보류한 결정과 재검토 조건

### 7.1 현대 제도 명사·게임 용어: 스킬 지침에만 둠

단어 목록 검사는 "계약"처럼 일반적인 말에서 오탐이 나고 의미를 단어로 판정하게 되므로 검증기에 넣지 않는다.
예외로 생업 항목의 이름(문장이 아닌 일의 이름 한 줄)만 좁은 목록(`MODERN_LIVELIHOOD_WORDS`, `scripts/life-document.ts`)으로 검사한다(#85).

검증기에 넣을지 다시 볼 신호:

- 생성된 일생 해석에 현대 제도 명사나 게임 용어가 반복해서 나타난다.
- GDD 단계에서 그런 표현이 주인공 직업·능력·세계 법칙으로 직역된다.

재검토할 때는 관찰한 사례를 개인정보를 뺀 최소 형태로 이 절에 남긴다.
