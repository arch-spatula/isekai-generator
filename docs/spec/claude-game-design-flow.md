## 1. 목표

`life.md`에서 GDD까지의 게임 단계를 Claude 스킬로 만든다. 이전 Codex 흐름의 두 실패를 구조로 막는다.

- **기호 직역:** 게임 단계는 차트 기호를 보지 않고, 산출물에 차트 명칭이 나오면 거부한다.
- **배경 부재:** 번역 브리프가 출신지·성장 환경·가족 구조·떠남의 계기를 해석하고, 세계와 GDD는 그 배경에서 출발한다.

성공 조건:

- 서로 다른 `life.md`에서 출신지·세계의 성격·동료 구성이 서로 다르게 나온다.
- 게임 단계 산출물 어디에도 차트 명칭이 없다(결정적 검사).
- 세계·지역·세력의 요소는 모두 `life.md` 항목이나 번역 브리프를 인용하거나 `창작:`으로 구분된다.
- 필수 검증은 합성 fixture로 하며 모델을 호출하지 않는다.

## 3. 입력 격리

| 단계 | 읽을 수 있는 것 | 읽을 수 없는 것 |
| --- | --- | --- |
| translation brief | `life.md` | 차트·사실·1차 판단·파생 사실·체계별 일생 해석·재료표 |
| combat·world selection | 번역 브리프, 앞 단계 브리프, 자기 시도 폴더의 지문 스냅샷 | 위 목록과 `life.md` 원문(브리프가 인용한 항목만 쓴다) |
| gdd | 번역 브리프, 전투·세계 브리프 | 위와 같음 |

- 전투·세계·GDD가 `life.md` 원문을 직접 읽지 않게 하는 이유는 번역 규칙을 브리프 한곳에 모으기 위해서다([게임 번역 명세](life-to-game-translation.md) 6절).
- 입력 조회 명령(`artifact-input.ts`)은 단계표의 입력만 돌려준다.

## 4. 공통 규칙

### 4.1 기호 명칭 금지

게임 단계 산출물(번역 브리프, 전투·세계 브리프, GDD)에 차트 명칭이 나오면 거부한다. 명칭 목록은 계산기 상수에서 만든다:
자미두수 주성·보조성·사화·12궁 이름, 사주 천간·지지·십신·신살 이름, 네이탈 행성·사인 이름. 일반어와 겹치는 짧은 말(예: 한 글자 천간)은 단독 한자로 쓰일 때만
잡는 등 오탐을 줄이는 규칙을 구현에서 정하고 테스트로 고정한다.

### 4.2 출처와 창작의 구분

세계·지역·세력·인물 설정의 요소마다 출처를 인용한다. 번역 브리프는 `[life:<항목>]`, 그 뒤 단계는 `[brief:<항목>]`(번역 브리프)과 `[combat:…]`·`[world:…]`(앞
단계 브리프)를 쓴다. 근거가 없는 설정은 `창작:`으로 시작해 구분한다. 창작 자체를 금지하지는 않는다.

### 4.3 장르 성격

[ADR](../ADR/2026-11-23-claude-gdd-flow.md) 5번을 따른다. 픽셀 그래픽, 빠른 실시간 액션, 로그라이트(런 반복, 런 중 보상 선택, 런 밖 성장)를 유지하고,
칸 배치 인벤토리·인접 칸 시너지·장비 슬롯 연결·슬롯 퍼즐은 쓰지 않는다. 화면 시점·해상도·아트 규격은 고정하지 않는다. 검증기는 제외 메커니즘의 용어가
시스템 설명에 쓰였는지 확인하되, 의미 판단은 의미 검토로 한다.

### 4.4 반복 모티프 경계

서로 다른 명식에서 같은 모티프가 반복되는 것은 모델 종류가 아니라 은유의 효율 때문에 생긴다. 붙들기·연결·거리 조절·이동을 한 번에 설명하는 사슬,
고립·연결·이동·거점을 한 번에 설명하는 바다와 군도, 순환을 설명하는 원처럼 적은 말로 많은 기능을 설명하는 이미지가 반복해서 선택된다
([전투 원형 수렴](../incidents/2026-11-03-combat-archetype-convergence.md), [해양 세계관 수렴](../incidents/2026-11-04-maritime-world-setting-convergence.md)).
기존 지문 비교는 구조 축만 보므로 모티프가 같은 결과를 막지 못한다.

- 전투·세계 브리프에 `핵심 모티프:` 필드를 두고, 주무기·주요 이미지·세계의 지배적 이미지를 2~3개의 명사로 선언한다.
- 시도 폴더를 만들 때 지문 스냅샷과 함께 같은 series 다른 run들의 핵심 모티프를 스냅샷한다. 검증기는 선언한 모티프가 스냅샷의 모티프와 같으면
  거부한다. 표기 차이(예: 사슬검·사슬날)를 묶는 정규화 규칙은 구현에서 정하고 테스트로 고정한다.
- 한 run 안에서 하나의 모티프가 전투·세계·성장·서사를 모두 독점하지 않게 한다(기존 단일 은유 독점 방지 원칙). 이것은 의미 검토로 본다.
- 모티프 자체를 금지하지 않는다. 브리프의 재능·배경에서 그 모티프가 필요한 이유를 인용할 수 있고 다른 run과 겹치지 않으면 쓸 수 있다.

### 4.5 지침의 단어가 결과에 새지 않게 하기

스킬 지침·템플릿·필드 이름·예시에 구체적인 사물 이미지(사슬, 닻, 항로, 불씨, 원 등)를 쓰지 않는다. 지침의 단어는 그대로 결과물의 모티프로 새어 나온다.
예를 들어 전투 브리프의 일반 동사 `anchor`·`route`가 GDD에서 닻·항로·군도로 번졌다([해양 세계관 수렴](../incidents/2026-11-04-maritime-world-setting-convergence.md)).
필드 이름은 기능을 나타내는 추상어로 쓰고(예: `경로`, `근거`), 예시는 합성 사례를 여러 갈래로 두거나 결과물에 쓰일 수 없는 형식으로 쓴다.

## 5. 단계별 계약

### 5.1 번역 브리프

[게임 번역 명세](life-to-game-translation.md) 3~5절을 따른다. 주인공 능력(재능 재료), 동료(스크립트가 계산한 후보에서만), 배경 네 항목(해석 경로),
동기와 퀘스트, 옮기지 않은 인물을 쓴다.

### 5.2 전투 선택

- 브리프의 `주인공 능력` 재료(재능 항목) 안에서 서로 다른 전투 방식 후보 네 개를 만들고 비교해 하나를 고른다. 후보마다 출처 재능을 인용한다.
- 동료가 있으면 동료와 함께 하는 기술은 브리프의 `함께 하는 일`에서만 만든다.
- 다른 run과의 중복은 기존 전투 지문 비교(시도 폴더 스냅샷, `artifact-fingerprints.ts`)로 막는다. 지문 축과 challenger 규칙은 유지한다.

### 5.3 세계 선택

- 브리프의 `배경`에서 출발한다. 출신지와 성장 환경을 첫 지역으로 두고, 생애 단계(장)마다 그 시기의 사건에서 지역의 성격을 만든다.
- 세력·공동체는 자체 목적과 제약을 가진다. 주인공의 `반복되는 실패`·`축`은 세계의 성격이 아니라 그 세계와 부딪치는 서사 갈등으로 쓴다.
- 서로 다른 세계 후보 네 개를 비교하고, 기존 세계 지문 비교로 다른 run과 겹치지 않게 한다.

### 5.4 GDD

기존 11절 구성을 이어받되 다음을 바꾼 새 템플릿을 쓴다(구현 때 `docs/prompts/`에 작성).

1. 게임 개요 2. 플레이어 경험과 핵심 재미 3. **주인공의 배경(출신지·성장·가족·떠남)** 4. 주인공과 주요 인물(동료와 퀘스트 인물) 5. 세계와 주요 지역(장 구성)
6. 전투 시스템 7. 능력의 기원과 성장(런 밖 성장 포함) 8. 탐험과 런 진행 9. 서사와 인물 관계의 변화(갈림길) 10. 대표 플레이 시나리오 11. 개인화 설계 근거

- 근거는 `[brief:…]`·`[combat:…]`·`[world:…]`로 인용한다. 통합 해석 ID와 공통 화면 계약 블록은 쓰지 않는다.
- 동료가 없으면 혼자 모험하는 구조로 쓴다.

## 6. 검증

| 검사 | 대상 |
| --- | --- |
| 차트 명칭 금지 | 브리프·전투·세계·GDD |
| 필수 절과 순서, 필드 형식 | 각 산출물 |
| 인용 대상 실재(`[life:]`·`[brief:]`·`[combat:]`·`[world:]`) | 각 산출물 |
| 배경 네 항목과 세 단계 해석 경로 | 번역 브리프 |
| 동료 후보 일치·동행 장 범위 | 번역 브리프 |
| 후보 네 개, 출처 재능 인용, 지문 스냅샷 비교 | 전투·세계 브리프 |
| 제외 메커니즘 용어 | 전투 브리프·GDD |
| 핵심 모티프가 다른 run의 모티프 스냅샷과 겹치지 않음 | 전투·세계 브리프 |

합성 fixture로 정상 사례와 거부 사례를 둔다. 거부 사례에는 **기호 직역**(예: 출신지를 재물의 별에서 장부 도시로 만든 설정), 근거 없는 배경, 후보가 아닌
동료, 제외 메커니즘, **다른 run과 같은 핵심 모티프**를 넣는다. 이전 [직역 평가 사례](../../scripts/fixtures/gdd-translation-cases.json)에 기호 직역과 배경 부재 사례를 더한다. 의미 품질(배경이
설득력 있는가, 세계가 주인공과 구별되는 논리를 가지는가)은 의미 검토 체크리스트로 본다.

## 7. 구현 순서

1. **단계표 교체:** 이 흐름의 단계로 바꾸고 일생 해석 단계의 폴더 배치를 `interpretation/`으로 옮긴다. 기존 Codex 단계 정의는 GDD 입력에서 뺀다.
2. **번역 브리프:** 동료 후보 계산 스크립트, 차트 명칭 목록과 검사, 브리프 검증기, `translate-life` 스킬.
3. **전투·세계 선택:** 브리프 기반 후보 비교로 스킬과 검증기를 새로 쓰고, 지문 비교는 기존 명령을 쓴다. 핵심 모티프 스냅샷과 반복 검사를 더한다.
4. **GDD:** 새 템플릿, 검증기, `write-gdd` 스킬.
5. **실제 생성 관찰(선택):** 서로 다른 명식 2~3개로 끝까지 생성해 배경·세계·동료가 명식에 따라 갈리고 기호 직역이 없는지 본다.
6. **정리:** 쓰는 곳이 없어진 Codex 생성 스킬과 검증기를 제거한다.

## 8. 열린 질문

1. **기호 명칭의 오탐 처리:** 한 글자 천간·지지처럼 일반 한자와 겹치는 명칭을 어디까지 잡을지 구현 때 사례로 정한다.
2. **GDD 분량과 형식:** light·deep 모드의 차이를 이 흐름에서 유지할지.
3. **모티프 정규화:** 같은 모티프의 표기 차이를 어떻게 묶을지(어근 비교, 동의어 표 등)와, 최근 몇 run까지 비교할지.
