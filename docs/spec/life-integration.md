# 세 체계 일생 통합

> 상태: 구현 — 재료표 스크립트, 검증기, `life-integration` 스킬
> 작성일: 2026-11-20

## 1. 목표

[일생 서사용 2차 해석](life-narrative-interpretation.md)이 체계마다 쓴 `saju-life.md`, `ziwei-life.md`,
`natal-life.md`를 한 사람의 일생 하나로 합쳐 `life.md`를 쓴다. 이후 GDD 단계는 이 문서 하나를 일생 서사의 입력으로 쓴다.

- 통합은 새로 해석하지 않는다. 차트·사실 파일·1차 판단을 다시 읽지 않고, 세 일생 해석에 있는 재료를 고르고
  맞추고 잇기만 한다. 근거 추적 경로가 한 단계로 유지되고 토큰 비용이 줄어든다.
- 언어 규칙은 2차 해석과 같다. 보편적 생애 사건 언어로 쓰고 현대 제도 명사와 게임 용어는 쓰지 않는다.
- 문장(인용 밖)에는 차트 명칭과 판단·운세·차트 해설 용어를 쓰지 않는다. 생애 연표는 운의 국면이 아니라 사건으로 쓴다(#66). 검증기가 차트 명칭 목록(`scripts/chart-names.ts`)과 해석 용어 목록(`INTERPRETATION_TERMS`, 일상어와 겹치는 말은 제외)으로 거부한다. 게임적 번역
  (예: 제자를 동료 모험가로 옮기기)은 GDD 단계에서 다룬다.

## 2. 결정

| 항목 | 결정 |
| --- | --- |
| 입력 | 세 체계의 일생 해석 문서만. 1차 판단과 차트는 통합 단계의 입력이 아니다 |
| 재료표 | 스크립트가 세 문서를 항목 이름 기준으로 나란히 모은 `life-material.md`를 만들고, 스킬은 이 파일만 읽는다 |
| 충돌 처리 | 합칠 수 있으면 합친다. 양립할 수 없을 때만 하나를 본선으로 쓰고 나머지를 `갈림길` 섹션에 조건과 함께 남긴다 |
| 네이탈 배치 | 생애 연표에 네이탈 인용을 허용하되 강제하지 않는다. 네이탈 조건이 사주·자미두수 단계의 사건과 맞물릴 때만 그 단계에 얹는다 |
| 체계 누락 방지 | 같은 이름의 원본 항목(배경·단계·인물)을 문서 어딘가에서 모두 인용해야 한다. 위치는 묶지 않는다 |

충돌을 본선과 갈림길로 나누는 것은 1차 판단의 `대안`과 같은 방식이다. 갈림길은 이후 게임에서 서사 분기의
재료로 쓸 수 있다.

## 3. 실행 흐름

```text
saju-life · ziwei-life · natal-life → assemble-life-material → life-integration → check-life-integration
```

- `bun scripts/assemble-life-material.ts <차트 디렉터리>`는 세 일생 해석이 모두 있고 각각
  `check-life-document.ts`를 통과할 때만 `life-material.md`를 쓴다. 하나라도 없거나 실패하면 무엇이 문제인지 알리고
  멈춘다. 결과 파일이 이미 있으면 쓰지 않는다.
- `life-integration` 스킬은 `life-material.md`가 없으면 만드는 방법을 알리고 멈추며, 대신 실행하지 않는다.
- `bun scripts/check-life-integration.ts <차트 디렉터리>`가 `life.md`를 검사한다.

## 4. 재료표 `life-material.md`

세 문서의 같은 이름 항목을 한곳에 모은다. 해석이 아니라 계산만으로 만드는 표다. 원본의 `근거` 필드는 다른 파일을
가리키는 인용이라 옮기지 않고, 나머지 필드는 값을 그대로 옮긴다.

- 배경: 항목마다 필드별로 `saju`·`ziwei`·`natal` 줄을 둔다.
- 생애 연표: 단계마다 필드별로 `saju`·`ziwei` 줄을 둔다.
- 인물 사전: 인물마다 필드별로 `saju`·`ziwei`·`natal` 줄을 둔다.
- 재능과 생업, 상처와 회복: 체계별로 항목 이름과 필드를 그대로 나열한다(재능은 체계마다 추가 항목 이름이 다르다).

가상 예제:

```text
일생 통합 재료 (세 체계 일생 해석을 항목 이름으로 모은 것 · 해석 아님)
─────
## 생애 연표
### 청년
운 [saju]: 2運 辛巳 18–27, 3運 壬午 28–37
운 [ziwei]: 福德 丁亥 22–31歲, 田宅 戊子 32–41歲
주제 [saju]: …
주제 [ziwei]: …
…
## 인물 사전
### 스승·후원자
성향 [saju]: …
성향 [ziwei]: …
성향 [natal]: …
…
## 재능과 생업
### natal 주 재능
내용: …
다루는 것: …
꽃피는 시기: …
```

원본 문서 안에서 항목 이름은 섹션을 넘어 겹치지 않아야 한다. 필수 항목 이름은 서로 다르므로, 추가 재능 이름이
다른 항목 이름과 같을 때만 스크립트가 멈추고 알린다.

테스트는 세 일생 해석 fixture를 입력으로 한다(`bun test scripts/assemble-life-material.test.ts`). 재료표는 이름 기준
병합이라 fixture가 서로 다른 합성 출생 입력이어도 된다.

## 5. 통합 문서 `life.md`

구조는 `## 섹션 > ### 항목 > 키: 값 필드`의 3단계이고 항목 안에는 필드 줄만 쓴다. 첫 줄은 `# 일생 통합 해석`이고
신원 줄은 두지 않는다.

| 섹션 | 항목 | 필드 |
| --- | --- | --- |
| 일생의 축 | 축 | `내용`, `근거` |
| 배경 | 뿌리 · 자란 집 · 떠남의 조건, 이 순서로 모두 | `모습`, `준 것`, `막은 것`, `근거` |
| 생애 연표 | 유년 · 소년 · 청년 · 장년 · 노년, 이 순서로 모두 | `주제`, `전환점`, `인연`, `시련`, `얻는 것`, `잃는 것`, `성격 변화`, `근거` |
| 인물 사전 | 부모 · 형제·또래 · 연인·배우자 · 자녀 · 제자 · 벗·동료 · 스승·후원자 · 경쟁자·적대자, 이 순서로 모두 | `성향`, `주인공과의 관계`, `관계의 변화`, `함께 한 일`, `곁에 있던 시기`, `영향`, `근거`. 연인·배우자·자녀·제자는 `상태`도 쓴다([관계 상태와 무게](life-shape-and-relationship-status.md) 5.2·5.4) |
| 재능과 생업 | 주 재능 · 보조 재능 (필수), 그 뒤 추가 재능 항목 자유, `생업: <이름>` 항목 하나 이상 | 재능: `내용`, `다루는 것`, `꽃피는 시기`, `막히는 조건`, `근거` · 생업: `내용`, `시기`, `쓰인 재능`, `근거` |
| 상처와 회복 | 반복되는 실패 · 상실 · 회복, 이 순서로 모두 | `내용`, `발현 조건`, `근거` |
| 갈림길 | 에이전트가 정한 이름, 0개 이상 | `본선`, `다른 길`, `갈리는 조건` |

재능은 같은 영역을 다루는 것끼리만 한 항목으로 합치고, 다루는 것이 다르면 항목을 나눈다(#82). 서로 무관한 영역을 한 재능에 이어 붙이면 게임 단계가
그 재능을 조각내 조각마다 후보를 하나씩 만든다. 한 체계가 쓴 성격 구조나 삶의 조건은 재능 문장으로 옮기지 않는다(#70).

생업은 세 체계의 생업 항목을 합쳐 시기 순으로 쓴다(#85). 같은 일끼리 합치고 서로 다른 일은 나누며, 네이탈의 조건은 맞물리는 생애 단계로 옮긴다.
`쓰인 재능`은 이 문서의 재능 항목 이름이고, `근거`는 원본의 생업 항목을 인용한다. 형식과 이름 규칙은 [일생 해석](life-narrative-interpretation.md) 3절을 따른다.

- `일생의 축`은 일생을 관통하는 한 문장이다.
- `배경`은 세 체계의 배경을 한 집안의 모습으로 합친다(#97). 사람의 성정이 아니라 조건이며, 부모의 성정은 인물 사전, 주인공의 성향은 축과 성격 변화에 쓴다.
- 생애 연표에 `운` 필드는 두지 않는다. 운은 원본 문서와 재료표에 있다.
- `인연`은 인물 사전 항목 이름을 쉼표로 나열한다.
- `관계의 변화`와 `꽃피는 시기`는 생애 단계 이름을 하나 이상 포함한다. 네이탈의 조건은 통합하면서 단계에 놓는다.
- `갈림길`의 `본선`은 문서에 채택한 서사, `다른 길`은 채택하지 않은 서사, `갈리는 조건`은 어떤 선택·사건에서
  갈리는지다. 충돌이 없으면 섹션 제목만 둔다.

### 인용

| 표기 | 대상 |
| --- | --- |
| `[saju:<항목>]` | `saju-life.md`의 `###` 항목 이름 |
| `[ziwei:<항목>]` | `ziwei-life.md`의 `###` 항목 이름 |
| `[natal:<항목>]` | `natal-life.md`의 `###` 항목 이름 |

`근거` 필드와 갈림길의 `본선`·`다른 길`에 쓴다. 사실 파일·차트·1차 판단은 직접 인용하지 않는다.

## 6. 통합 판단 지침

스킬이 따르는 의미 규칙이다. 검증기로 판정할 수 없어 운영 관찰로 확인한다.

- 세 체계가 함께 말하는 재료는 서사의 기둥으로, 한 체계만 말하는 재료는 그 단계·인물의 색깔로 쓴다.
- 서로 다른 재료라도 한 사람의 일생에서 함께 성립하면 합친다(예: 한 체계의 "바른말"과 다른 체계의 "부수고 다시
  세움"을 같은 사건의 두 면으로 쓴다). 함께 성립할 수 없을 때만 갈림길로 보낸다.
- 네이탈 조건은 사주·자미두수 단계의 사건과 실제로 맞물릴 때만 그 단계에 얹는다(예: 네이탈 "많은 사람 앞에서
  책임을 맡았을 때"와 자미두수 장년의 "공동체의 일을 맡음"). 맞는 단계가 없으면 인물·재능·상처에만 쓴다.
- 원본에 없는 사건이나 인물을 만들지 않는다. 잇는 데 필요한 연결 문장만 더한다.

## 7. 검증기

`bun scripts/check-life-integration.ts <차트 디렉터리>`. 위반을 한 줄씩 출력하고 위반이 있으면 exit 1이다. 일생 해석
검증기의 구조 파서(`scripts/life-document.ts`)를 함께 쓴다.

| 검사 | 막는 실수 |
| --- | --- |
| 제목, 섹션 순서, 필수 항목과 순서, 항목마다 필드가 한 번씩 있고 비어 있지 않음 | 누락, 형식 이탈 |
| `인연`의 이름이 인물 사전에 있음 | 등장인물 불일치 |
| `관계의 변화`·`꽃피는 시기`·생업 `시기`에 생애 단계 이름이 있음 | 시간 축 없는 서술 |
| 생업 항목이 하나 이상 있고, `쓰인 재능`이 같은 섹션의 재능 항목이며, 생업 이름에 현대 제도·기술의 말이 없음 | 생업 누락, 이세계에 없는 일 |
| 모든 인용이 원본 문서에 실재하는 항목 | 꾸며낸 근거 |
| 배경 항목마다 세 체계의 같은 항목, 생애 단계마다 `[saju:<단계>]`·`[ziwei:<단계>]`, 인물마다 세 체계의 같은 인물이 문서 어딘가에서 인용됨 | 한 체계가 조용히 빠짐 |
| 재능과 생업, 상처와 회복 섹션이 각각 세 체계를 한 번 이상 인용 | 한 체계의 재능·상처가 통째로 빠짐 |
| 갈림길 항목의 `본선`·`다른 길`에 인용이 있고, `다른 길`에 `본선`이 인용하지 않은 체계가 하나 이상 있음 | 근거 없는 갈림길, 같은 체계 안의 말 바꾸기 |

내용의 질, 합침과 갈림길 판단의 타당성, 네이탈 배치가 맞는지는 검사하지 않는다. 같은 이름 인용은 위치를 묶지 않으므로
충돌하는 재료는 갈림길에서 인용해도 된다. 테스트는 세 일생 해석 fixture를 재료로 손으로 쓴 합성 통합 문서
(`scripts/fixtures/life-integration/life.md`)와 그 변형으로 한다(`bun test scripts/check-life-integration.test.ts`).

## 8. 보류한 결정과 재검토 조건

### 8.1 갈림길 최소 개수를 강제하지 않음

최소 개수를 두면 충돌이 없는 명식에서 억지 갈림길이 생긴다. 1차 판단에서 확신도 표시를 빼고 `대안`을 둔 것과
같은 이유다. 다시 볼 신호:

- 재료표에 분명히 양립하지 않는 재료가 있는데 생성된 통합 문서의 갈림길이 반복해서 비어 있다.

### 8.2 네이탈 배치를 검증하지 않음

조건과 단계가 맞는지는 의미 판단이다. 다시 볼 신호:

- 네이탈 재료가 맞지 않는 단계에 반복해서 얹힌다.
- 네이탈 재료가 연표에서 늘 빠져 GDD 단계에서 시기를 다시 정하게 된다.

재검토할 때는 관찰한 사례를 개인정보를 뺀 최소 형태로 이 절에 남긴다.
