# Edit defensive phrases

Review exactly one assigned system and scope. Preserve interpretation, stable item IDs, evidence, headings, resolution and order. Make only local replacements linked to a diagnostic or explicit semantic secondary target. Review every automatic diagnostic and additional semantic target; unresolved and missing preservation confirmation cannot pass. Specialist false-positive decisions cannot pass. For integration, a false-positive decision with a contextual reason preserves the exact diagnosed source location; review every diagnostic explicitly. Do not expand scope yourself. For integration use only source, the three accepted specialist documents, supplied guidelines, diagnostics, mode and scope; do not read raw birth data or chart text. Preserve I-NN IDs, order, domains, relationships, all S/Z/N references and unique insights; add no interpretation or game design. Use `allowedTargets` from the input command for both edits and secondary review decisions: actual I-NN IDs or tool-generated region IDs, never arbitrary titles. A preservation-only decision requires no fake edit. Preserve calculation premises, real data limitations and conditional manifestations. Do not replace forbidden words with synonyms.

## File invocation contract

The caller supplies repository root, version directory, attempt path and mode. Read your input only with:

`bun <root>/scripts/artifact-input.ts <version-dir> <attempt>`

Use only the returned documents. Do not read other artifact directories, other attempt folders, conversation history, another system, or prior runs. Evidence, previous candidates with diagnostics, edit sources with diagnostics and allowed targets, and registry snapshots come from this command; never create an intermediate JSON file. The status and attempt tools assign attempt numbers and scopes. Return the structured edit proposal to the orchestrator. Do not write candidate Markdown: the tool assembles it. The orchestrator pipes the proposal to `artifact-edit.ts`; do not publish final paths or create another attempt. Return a concise status without reproducing content. A semantic conflict blocks completion even when structural validation passes.

Return the submission as JSON to the parent orchestrator, which pipes it directly to `bun <root>/scripts/artifact-edit.ts <version-dir> <attempt>` stdin, with `{sourceSha256,edits,review,reviewMarkdown}`. `sourceSha256` is `source.sha256` from the input command. The review contains system, attempt, scope, primary decisions with diagnosticIndex/status/reason/editIds, secondary decisions with id/target/status/reason/editIds, preservationConfirmed, unresolved, and nextScopeReason for unresolved targets. Every edit has id,target,original,replacement and diagnosticCode or reviewTargetId. `reviewMarkdown` is a nonempty semantic report. Do not write an edits file. The tool assembles and validates candidate Markdown, writes `candidate.md` and `result.md` in the attempt folder, and preserves the source on editing-contract errors. The proposal itself is not stored; for integration `result.md` records each diagnostic decision and preservation reason. Retries receive the previous edit candidate as source plus its result. For integration, format errors consume the three-call budget at the same scope; only unresolved semantic preservation expands sentence to item to system (related document regions, never a whole-document rewrite).
