# 한국 연예인 출생정보 후보

`korean-celebrity-births.json`은 사용자가 제공한 표와 출생 입력 코드블록을
함께 정리한 자료다. 여기서 임상은 프로젝트의 사례 수집 명칭이며 의학적 임상 자료를 뜻하지 않는다.
외부 출처 확인이나 차트 계산은 아직 수행하지 않았다.

## 자료 구성

- 후보 19명: 표의 생년월일·생시·도시·등급·출처 설명과 코드블록의 성별·원문 입력을 보존했다.
- 제외 6명: 황현진?, 윤보라, 최수영, 김태리, 임윤아, 박신혜. 생시를 임의로 채우지 않았다.
- 원표의 중복 번호 13 대신 고유 `id`를 사용한다. 배열은 후보와 제외 항목을 각각 원표 순서로 둔다.
- 모든 출처와 등급은 사용자 제공 주장이다. 검증된 사실이나 계산 정확도 보증으로 해석하지 않는다.

## 필드

| 필드 | 의미 |
| --- | --- |
| `schema_version` | 파일 구조 버전. 현재 1 |
| `id`, `name`, `alias`, `field` | 내부 식별자, 제공된 이름, 별칭, 분야 |
| `status` | `candidate` 또는 `excluded`. 후보도 검증 완료를 의미하지 않음 |
| `birth_date` | 제공된 날짜를 `YYYY-MM-DD`로 정규화. 달력 종류는 원자료에 명시되지 않음 |
| `birth_time` | 제공된 시각을 24시간제 `HH:mm`로 정규화. UTC 변환 없음 |
| `birth_time_precision` | `as_reported`: 제공된 분 단위 표기, `approximate`: 잠정·추정 시각, `unknown`: 시각 없음 |
| `birth_city` | 제공된 도시 이름. 좌표·시간대·역사적 서머타임은 아직 부여하지 않음 |
| `sex` | 코드블록의 남성은 `male`, 여성은 `female`. 제공되지 않은 값은 `null` |
| `reported_reliability` | 사용자 표의 A/B/C. 독자적 재평가나 등급 정의 추가 없음 |
| `reported_source`, `source_note` | 사용자 표의 출처명과 비고. `Astrid` 등 표기도 그대로 유지 |
| `source_url` | 실제 원문 링크. 제공되지 않아 현재 모두 `null` |
| `verification_status` | 현재 모두 `unverified` |
| `raw_birth_input` | 사용자 코드블록 한 줄 원문. 코드블록이 없는 제외 후보는 `null` |
| `notes` | 정규화 중 확인한 불확실성 |

누락된 스칼라 값은 `null`, 별도 메모가 없으면 `notes: []`로 저장한다.

## 표와 코드블록 대조

코드블록 19개의 날짜·시각·도시는 표와 일치한다. 성별은 코드블록에서 가져왔다.
명시적인 임시 값 표시는 없으나 다음 항목은 활용 시 확인이 필요하다.

- 심재윤(Jake): 표와 코드블록의 `22:00경`을 `22:00`으로 저장하되 `approximate`로 표시했다.
  비고에는 밤 10시 이후이며 정확한 분은 불명이라고 되어 있다. `22:00`을 확정 시각으로 사용하지 않는다.
- 김희철: `18:00` 표기와 함께 원 비고의 “6pm일 것”을 보존하고 `approximate`로 표시했다.
- 선미: 시각이 출생차트 역산에 기반한다는 설명을 보존했다. `as_reported`는 직접 증언을 뜻하지 않는다.
- 윤영재(Youngjae): 이름과 별칭의 동일 인물 여부가 확인되지 않았으므로 임의 교정하지 않았다.
- 황현진?: 물음표를 포함한 원래 이름을 유지했다.

## 활용

JSON을 읽고 `records`에서 `status === "candidate"`인 항목을 선택하면 된다.
그중 `birth_time_precision === "as_reported"`이면 제공된 시각을 그대로 사용하는 사례,
`approximate`이면 잠정 시각을 사용한 탐색 사례로 구분할 수 있다.
A 등급도 출처 검증을 대신하지 않는다. 현재 자료는 검증 전 탐색 입력으로 활용한다.

차트 입력으로 변환할 때는 달력 종류, 도시 좌표, 시간대와 해당 날짜의 서머타임 처리,
이름·출처를 확인해야 한다. 잠정 시각을 사용한 결과에는 그 조건을 함께 기록한다.
현재 단계에서는 계산 도구의 입력 형식 변환이나 실행 기능을 추가하지 않았다.

검증은 JSON 파싱, 고유 식별자, 후보 19명·제외 6명, 날짜·시각 형식,
후보 원문 입력과 정규화 값의 일치 여부를 확인한다. 문서는 `bun run check:docs`로 검사한다.
